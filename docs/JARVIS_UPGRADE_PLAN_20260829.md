# 자비스 고도화 계획 (2026-08-29)

> [8/29 점검서](JARVIS_DASHBOARD_REVIEW_20260829.md)를 다시 읽고, **오픈클로 에이전트로 학교 업무를 한다**는
> 실제 사용 방식을 반영해 다시 세운 계획이다. 점검서는 "웹앱" 관점이라 화면 개편에 무게가 실려 있었는데,

## 0. 한 줄 요약

자비스는 웹앱이 아니라 **오픈클로 에이전트의 관제탑**이다.
그래서 화면을 예쁘게 고치는 것보다, **에이전트가 쓴 것과 화면이 서로 다른 말을 하는 곳을 먼저 막는 것**이 1순위다.

## 3. 고도화 방향 3가지

**① 원본은 마크다운 하나로 못박는다**
화면에서 지운 건 파일에서도 지워지든지, 아니면 화면에서 아예 못 지우게 한다. 지금처럼 "화면에서는 지워졌는데
파일에는 남아 있는" 중간 상태를 없앤다.

**② 자비스를 에이전트 관제탑으로 만든다**
첫 화면이 누적 건수가 아니라 **오늘 에이전트가 만든/고친 것, 동기화 성공·실패, 내가 확인해야 할 것**을 보여준다.
혼자 쓰는 앱에서 가장 값진 정보는 "내가 모르는 사이에 무슨 일이 있었나"다.

**③ 말로 넣고, 눈으로 확인하고, 손으로 고친다**
입력은 텔레그램(에이전트)이 맡는다. 화면은 입력 폼을 늘리는 대신 **확인·정정 동선**을 좋게 한다.
자비스 안에 채팅 UI를 만들지 않는다 — 텔레그램이 이미 그 역할이다.

```bash
# sudo가 필요해 이 세션에서 실행하지 못한 부분 — 한 번에 붙여넣으면 된다
sudo cp /etc/caddy/Caddyfile /etc/caddy/Caddyfile.bak-$(date +%Y%m%d-%H%M%S) \
  && sudo sed -i '' 's|reverse_proxy 127.0.0.1:3003|reverse_proxy 127.0.0.1:3004|' /etc/caddy/Caddyfile \
  && sudo /opt/homebrew/bin/caddy validate --config /etc/caddy/Caddyfile \
  && sudo /opt/homebrew/bin/caddy reload --config /etc/caddy/Caddyfile \
  && launchctl bootout gui/501/com.jarvis.frontend \
  && mv ~/Library/LaunchAgents/com.jarvis.frontend.plist ~/Library/LaunchAgents/com.jarvis.frontend.plist.disabled \
  && curl -s -o /dev/null -w "3003(죽어야 정상): %{http_code}\n" http://127.0.0.1:3003/
```

#### 조치 1 — 안 쓰는 도구 끄기 (가장 큼, 5분)

`tools.profile`을 바꾸는 대신 **`tools.deny`로 안 쓰는 것만 빼는 게 안전하다**(deny가 이긴다).
`~/.openclaw/openclaw.json`에 다음을 더한다.

```json5
{
  tools: {
    profile: "full",
    deny: ["cron", "browser", "image_generate", "video_generate",
           "music_generate", "canvas", "tts", "skill_workshop",
           "nodes", "node_inference"]
  }
}
```

- 줄어드는 양: 약 **33KB / 78KB (42%)**, 세션당 대략 8~9천 토큰
- 한 달 483세션 기준 대략 **400만 토큰**
- 스킬을 새로 만들 땐 `skill_workshop`을 잠깐 빼면 된다. 되돌리기는 그 줄을 지우면 끝이다.
- 주의: 정기 알림을 쓰기 시작하면 `cron`을 deny에서 빼야 한다.

#### 조치 2 — 찾기를 "파일 뒤지기"에서 "한 번 물어보기"로 (반나절)

지금 "이번 주 안 끝난 업무 뭐 있지?"에 답하려면 `Task_Management/` 161개 파일(평균 4KB)을 훑어야 한다.
같은 답이 DB에는 한 줄 질의면 나온다.

```bash
# jarvis-lookup 스킬이 쓸 형태 — 파일 161개 대신 결과 몇 줄만 읽는다
docker exec agit-db psql -U postgres -d postgres -tAc \
  "select date, status, content from app.tasks
    where status <> '완료' order by date limit 20;"
```

- 업무·일정·학급기록·프로젝트 조회를 이 방식으로 바꾸면 조회 한 번에 **수십 KB → 1~2KB**
- 쓰기는 지금처럼 마크다운 원본으로 한다. **읽기만** DB로 돌린다

`AGENTS.md` 레드라인에 한 줄 더한다.

```
- `Vault/` 파일은 통째로 읽지 않는다. 필요한 줄만 grep 하고, 내용은 화면에 옮기지 않는다.
```

민감 자료 보호와 토큰 절약이 같은 방향이다.

#### 조치 4 — 저장 스킬 9개를 3개로 (J4와 같은 작업)

스킬 설명은 매 세션 실리고, 어느 스킬을 쓸지 고르느라 본문을 두세 개 열어 보기도 한다

고르는 과정 자체가 없어진다.

#### 조치 5 — 하트비트 정리 (10분)

하트비트도 세션이라 78KB 헤더를 그대로 문다. 하루 2~4회면 한 달에 60~120세션이다.

- 야간(23~08시)엔 아예 돌지 않게 한다
- 확인할 게 없으면 `HEARTBEAT_OK` 한 마디로 즉시 끝낸다 (이미 `token-saver.md`에 있는 규칙 — 지켜지는지 확인)
- 조치 1을 하면 하트비트 한 번당 비용도 같이 42% 준다

#### 효과 요약 (2026-08-29 실측)

세션 헤더를 도구별로 세어 본 결과다.

| | 지금 | 조치 1 적용 후 |
|---|---|---|
| 기본 지침 | 19.4KB | 19.4KB (그대로) |
| 도구 정의 | 56.8KB (29개) | **24.0KB (20개)** |
| **요청 1건당 헤더** | **76.2KB** | **43.4KB** |
| 토큰 환산(3.5~4.0바이트/토큰) | 19,500~22,300 | 11,100~12,700 |

**요청 1건마다 8,400~9,600 토큰이 준다. 비율로는 입력의 43%.**

한 달 총량은 요청 수에 달렸다. 2026년 8월 기록은 세션 483회·턴 514회·도구 결과 되먹임 1,540회로,
모델 요청이 대략 2,000건이었다.

| 계산 방식 | 월 절감 |
|---|---|
| 확실한 몫 — 세션 첫 요청 483건만 세어도 | **약 400만~460만 토큰** |
| 캐시가 전혀 안 걸린다고 보면(요청 2,000건) | 약 1,700만~1,900만 토큰 |

실제값은 이 사이다. 도구 정의는 프롬프트 앞머리에 고정으로 붙는 부분이라 캐시가 잘 듣는 자리인데,
**세션의 98%가 한 턴짜리**여서 캐시가 살아 있는 동안 재사용될 기회가 적다. 그래서 아래쪽 값(400만 이상)은
캐시가 잘 들어도 그대로 남는 몫이다.

체감으로는, 세션 파일 중앙값이 110KB인데 그중 76KB가 헤더다. 조치 1만 해도 보통 세션 하나가
**110KB → 77KB, 약 30% 가벼워진다.**

#### 나머지 조치의 크기 (정직하게)

| 조치 | 실측 근거 | 크기 |
|---|---|---|
| 1. 안 쓰는 도구 끄기 | 헤더 76.2→43.4KB | **가장 큼** |
| 2. 조회를 DB로 | 8월 `exec_command` 1,464회. 업무 조회 한 번이 파일 161개(평균 4KB) 대상 | 중간 — 조회가 잦을수록 커진다 |
| 3. Vault 통째 읽기 금지 | 39파일 8.4MB, 평균 227KB | 평소 0, 사고 나면 1회에 6만 토큰 — 보험 |
| 4. 스킬 9개 → 3개 | 스킬 본문 합계 42KB, 고를 때 2~3개 열람 | 작음 — 다만 형식 일관성이 본래 목적 |
| 5. 하트비트 정리 | 8월 `heartbeat_respond` **64회**뿐 | 생각보다 작다 |

처음에 하트비트를 하루 2~4회로 보고 크게 잡았으나, 실제 8월 기록은 64회였다. **조치 1이 사실상 전부이고
나머지는 덤이다.**

### J7 — 기록 창고에서 산출물 공장으로 (활용도 확장)

> 2026-08-29 사용자 방향 설정: 오픈클로로 **업무 자체를 줄이는** 쪽으로 쓴다.
> 일정표를 남에게 공유하고, 내가 만든 양식에 자료를 부어 결과물을 만들고, 사진으로 자료를 정리하고,
> 그 결과를 표로 묶어 공유까지 한 번에 한다.

#### 지금 구조로는 왜 안 되나

자비스는 지금 **기록 창고**다. 넣고, 보고, 찾는다. 원하시는 것은 **산출물 공장**이다.

```
지금:  말·파일 → 마크다운 → DB → 화면에서 본다                        (끝)
원하는 것: 말·사진 → 정리 → 양식에 붓기 → 산출물 → 남에게 공유       (한 줄로)
```

없는 조각이 넷이다.

| 없는 것 | 지금 상태 |
|---|---|
| **양식** | 기록 종류가 코드에 박혀 있다(tasks·memos·journals…). 내가 양식을 만들 자리가 없다 |
| **산출물** | 만들어진 문서(주간 안내문, 일정표)를 담을 표가 없다 |
| **공유** | 모든 화면이 로그인 필수다. 밖에 보여줄 길이 아예 없다 |
| **이미지 입력** | 첨부는 되지만 "사진 → 표"로 바꾸는 자리가 없다 |

#### 이미 있어서 다시 만들 필요 없는 것

- **샘링크에 공유 인프라가 통째로 있다** — `samlink.short_links`, `short_link_visits`,
  `short_link_daily_stats`, `short_link_notifications`, `short_link_rate_limits`.
  같은 `agit-db` 안이라 **단축링크·조회수·속도제한을 새로 만들 필요가 없다.**
- 오픈클로는 이미 이미지를 읽는다 (`school-calendar-sync` 스킬이 일정표 사진을 다루고,
  `clawpdf-text-extract` 스킬도 있다).
- 첨부 업로드·PIN 잠금·마크다운 원본 규칙은 그대로 재사용한다.

#### 새로 넣을 개념은 셋뿐

```
app.templates          내가 만든 양식 (마크다운 + 자리표시자)
app.documents          양식 + 자료 → 만들어진 산출물 (원본 참조·만든 시각 보관)
app.document_shares    산출물 하나에 대한 공개 토큰 · 만료일 · 조회수
```

화면에는 **공개 라우트 하나**만 는다: `/s/<토큰>`. 로그인 없이 **그 산출물 하나만** 보여준다.

#### 단계

**J7-a 산출물과 공유의 뼈대 (2~3일, 먼저)**
- `app.documents`·`app.document_shares` 추가, `/s/<토큰>` 읽기 전용 공개 라우트
- 관리 화면: 지금 열려 있는 공유 목록, 만료일, 즉시 해지
- 샘링크 단축링크로 짧은 주소 발급 (`short_links` 재사용)
- **먼저 하는 이유**: 양식·이미지·표는 전부 "만들어서 → 공유한다"로 끝난다. 출구를 먼저 뚫는다

**J7-b 양식 (2일)**
- `Templates/` 폴더 + `app.templates`. 양식도 마크다운 원본 규칙을 그대로 따른다
- 자리표시자: `{{학급}}`, `{{기간}}`, `{{표:이번주일정}}`
- 화면에서 양식 목록·미리보기, 오픈클로에서 `jarvis-render 양식이름 기간` 한 마디로 산출물 생성

**J7-c 표로 정리 (1~2일)**
- 일정·업무를 기간·조건으로 뽑아 표 산출물로 만드는 질의 몇 개를 고정
- 예: "9월 학사일정표", "이번 주 제출 업무", "학급별 상담 횟수"
- J6 조치 2(DB 조회)와 같은 길을 쓴다 — 파일 161개를 훑지 않는다

**J7-d 사진으로 자료 넣기 (1~2일)**
- 사진을 보내면 오픈클로가 표로 정리해 **초안 산출물**을 만든다
- 사람이 화면에서 확인·수정한 뒤에만 확정 — AI가 만든 것을 바로 확정하지 않는다
- 확정하면 그때 마크다운 원본에 반영된다

#### 안전 규칙 (교사 업무라 이게 제일 중요하다)

- 공유는 **산출물 단위로만** 한다. 원본 기록이나 목록은 어떤 경우에도 공개되지 않는다
- 공유 링크는 **기본 30일 만료**, 언제든 즉시 해지
- **학급기록·보안저장소에서 나온 자료가 섞인 산출물은 공유를 막는다** (기본 차단, 예외 없음)
- 공개 페이지는 `noindex`, 토큰은 추측 불가 길이
- 공유를 만들 때 **무엇이 공개되는지 미리보기를 반드시 거친다**
- 학생 이름이 들어간 산출물은 공유 직전 한 번 더 확인시킨다

#### 이 순서인 이유

출구(J7-a)를 먼저 뚫으면, 그다음부터는 **양식 하나 추가 = 새 업무 하나 자동화**가 된다.
양식을 먼저 만들면 만들어 놓고 쓸 데가 없다.

#### cron 을 껐는데 정기 작업이 되나

된다. **`cron` 도구를 끈 것은 "대화 중에 에이전트가 일정을 잡는 것"만 막은 것이고,
등록된 정기 작업 자체는 그대로 돈다.** 명령줄로 등록하면 된다.

```bash
openclaw cron add --name "주간 업무 확인" --schedule "0 16 * * 5" --session main \
  --prompt "이번 주 업무를 app.tasks 에서 읽어 채팅 표로만 보여 줘. DB에 쓰거나 공유 자료·링크를 만들지 마."
```

대화 중에 *"매주 금요일에 이거 해줘"* 라고 말로 시키고 싶으면 그때 `tools.deny` 에서 `cron` 을
빼면 된다. 요청당 약 3,700 토큰이 늘어난다. **먼저 CLI 로 두세 개 걸어 보고, 자주 바꾸게 되면

## 5. 하지 말 것

- 멀티유저·권한 시스템 (혼자 쓴다)
- Realtime·실시간 협업·분산 캐시 (자료가 몇백 건이다)
- 마크다운 원본을 버리고 DB만 쓰기 (에이전트가 다루기 가장 쉬운 형태가 마크다운이다)
- 자비스 안에 채팅 UI 만들기 (텔레그램이 이미 있다)
- 프레임워크 이관·전면 재작성

## 6. 실행 순서 한눈에

| 단계 | 무엇 | 왜 지금 | 크기 | 선행 |
|---|---|---|---|---|
| **J1** | 어긋남 막기 | 자료가 실제로 사라지거나 되살아난다 | 반나절 | 없음 |
| **J2** | 안전망 | 이후 변경을 반복해도 안전하게 | 하루 | J1 |
| **J3** | 관제탑 홈 | 체감이 가장 큰 개편 | 2~3일 | J2 |
| **J4** | 에이전트 스킬 정리 | 입력 품질이 일정해진다 | 반나절 | J3(활동 기록 표) |
| **J5** | 부하·유지보수 | 급하지 않지만 오래 간다 | 반나절 | J3 |
| **J6** | 오픈클로 토큰 아끼기 | 조치 1·3·5는 30분에 42% 절감 | 30분 + 하루 | 없음(1·3·5는 지금 가능) |
| **J7** | 산출물·양식·공유 | 여기서부터 실제 업무가 줄어든다 | 1~2주 | J7-a 먼저 |
| **J8** | 오픈클로 미사용 기능 활용 | 이미 있는 것부터 쓴다 | 설정~반나절 | 없음 |

J1·J2는 이어서 하는 게 좋고, J3부터는 한 번에 하나씩 배포·확인하면 된다.

## 7. 1차 완료 기준 (J1~J3 끝났을 때)

- 외부·로컬 어느 경로에서도 같은 Docker 빌드만 응답한다.
- 화면에서 지운 기록이 동기화 뒤 되살아나지 않고, 웹에서 올린 첨부가 동기화 뒤에도 남는다.
- 자비스 코드와 비밀 없는 운영 스크립트를 private 원격에서 복구할 수 있고, 개인 자료는 Git 대상이 아니다.
- 로그인 없이 어떤 서버 액션도 성공하지 않고, 잠금 쿠키를 임의로 만들어도 민감 자료가 열리지 않는다.
- 첫 화면에서 오늘 일정 · 미완료 업무 · 오래된 프로젝트 · 오늘 에이전트 활동을 스크롤 없이 확인한다.
- `lint` · 타입 검사 · 테스트 · 빌드가 질문 없이 한 번에 통과한다.
