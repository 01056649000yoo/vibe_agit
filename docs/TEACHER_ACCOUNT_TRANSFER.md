# 교사 계정 이관 (관리자 절차)

교육청이 구글 계정을 지워 **로그인할 수 없게 된 선생님**의 자료를 새 구글 계정으로 옮긴다. 관리자 화면 `👩‍🏫 선생님 → 계정 이관` 에서 한다.
서버 규칙은 `supabase/migrations/20261403_teacher_account_transfer.sql`, 시험은 `tests/sql/20261403_*.smoke.sql`.

## 하기 전에
1. **새 구글 계정으로 선생님이 한 번 로그인**한다(새 교사 계정이 만들어진다).
2. 새 계정이 **승인**되고 **교사 정보(이름·학교)를 입력**해 둬야 한다(관리자 `승인 대기` 에서 승인).
3. 새 계정에서 **이미 학급·과제를 만들었다면** 먼저 알려 달라고 한다 — 같은 자료가 겹치면 사전 점검이 충돌로 알려 준다.
4. 안전하게 하려면 실행 직전에 백업이 최근인지 본다(`백업 상태`).

## 순서
1. `① 옛 계정`·`② 새 계정` 을 이름이나 이메일로 찾아 고른다.
2. `③ 사전 점검` — **아무것도 바꾸지 않는다.** 어떤 자료가 몇 행 옮겨지는지, 충돌이 없는지 본다. 옛 계정이 승인 상태이거나 최근 30일 안에 로그인했으면 빨간 경고가 뜬다(옛·새 계정을 바꿔 골랐거나 다른 선생님을 고른 것은 아닌지 확인).
3. 충돌이 없으면 `④ 이관 실행` — 옛 계정의 **이메일을 그대로 입력**해야 단추가 열린다. 한 번에(전부 성공하거나 전부 취소) 처리된다.
4. 끝나면 새 계정으로 로그인해 학급·학생·과제가 보이는지 확인한다.

## 무엇이 옮겨지나
- **옮긴다(소유·접근을 정하는 열)**: 담당 학급(학생·학생 글·학급 자료는 학급에 묶여 그대로 따라온다), 과제, 학생 기록, 피드백 틀, 점수 지급, 교사 댓글·피드백, 독서록 한마디, 독서 마라톤, 연구소 방·질문·개요·프로필, 샘링크 단축 주소 접근. 새 계정의 개인 설정(자주 쓰는 태그·피드백 문구·기본 루브릭 등)이 비어 있으면 옛 계정 것을 이어받는다.
- **옛 계정에 둔다(이력·보안)**: 로그·이벤트 기록(누가 했는지 추적), 승인·확인자 표시, 구글 로그인 기록, 다했니 연동 키, 개인 API 키, 약관·개인정보 동의, 모두의 아지트 기록. **새 계정에서 다시 해야 하는 것**: 다했니 연동, 개인 API 키, 약관 동의, 연구소 AI 연결.
- **옮길 수 없는 것**: 삭제된 구글 계정의 드라이브에 있던 파일(구글 문서로 내보낸 것).
- 옛 계정은 **지우지 않고 승인을 취소**해 로그인을 막는다(되돌릴 수 있다). 이관 기록은 `이관 기록` 에 남는다.

## 새 표가 생겼을 때
교사 계정을 가리키는 열이 있는 새 표를 만들면 `teacher_transfer_targets_v1()` 에 `move`(옮긴다) 또는 `keep`(둔다) 한 줄을 더해야 한다.
빠뜨리면 `tests/sql/20261403_*` 스모크(= `npm run test:security`)가 실패한다.

## 같은 옛 계정은 한 번만
옛 계정마다 이관 기록이 한 줄이라 두 번 할 수 없다. 잘못 이관했다면 새 계정을 바꿔 다시 하는 대신 관리자(운영자)가 기록을 보고 되돌린다.
