# 우리반 아지트 — 보고서 사진을 전시·문집에 담기 (설계)

> 2026-10-20 선생님 결정으로 시작. 열린 일은 [OI-034](OPEN_ITEMS.md). 1단계(편지·사진 없는 보고서)는 `20261400`.
> 법률 자문이 아니라 일반 기준을 앱 구조에 맞춘 설계다. 학교 개인정보 보호책임자 확인을 거친다.

## 결정(선생님, 2026-10-20)

1. 보고서 사진에는 **개인을 알아볼 수 있는 정보가 없어야** 한다(얼굴·이름표·교복 글씨·이름이 적힌 물건·학교나 집을 알 수 있는 모습). 직접 찍은 사진만 쓴다.
2. 학생 쪽은 **올리기 전 약속 안내 + 확인 칸**(법적 동의가 아니다 — 만 14세 미만은 보호자 동의가 필요하다. 학교가 학기초에 받는 동의서가 기준이다).
3. 책·전시에 담을 때는 **선생님이 사진을 직접 보고 확인**해야 담긴다. 문제가 있으면 **사진만 빼고 글만** 담는다.
4. 일기·안건 의견 모으기는 제외. 독서록은 별도(OI-035).

## 지금 구조에서 알아낸 것

| 사실 | 영향 |
|---|---|
| 원본 사진은 비공개 저장소 `report-images`(경로 `글ID/폴더/파일.jpg|webp`, 파일당 256KB 이하·변 720px 이하, 올릴 때 다시 그려 저장해 촬영 위치 같은 숨은 정보가 남지 않음) | 책이 원본을 가리키면 학생이 사진을 바꾸거나 지울 때 책이 바뀐다 → **담는 순간 복사본을 고정**한다. |
| 원본 읽기 권한은 글쓴이·담임·관리자·**같은 반 학생(제출·학급 공개 글)** | 학급 안 읽기는 원본으로도 가능하지만 고정 복사본이 필요하다. 외부 공유 방문자는 원본을 못 읽는다. |
| 책 표지 그림(`class-agit-covers`)이 같은 문제를 이미 풀었다: 비공개 버킷, 서명 주소, 접근 판단 함수(`can_access_class_agit_cover_v1`), 청소 스크립트 | 사진도 **같은 패턴**(`class-agit-photos`)으로 간다. |
| 전시·책·외부 공유가 각자 스냅샷(`class_agit_items`·`class_agit_book_items`·`class_agit_external_items`, 공개판 `class_agit_published_items.blocks`)을 가지고, 저장·공개·읽기 함수 십여 곳이 **`blocks`(문자열 배열)만** 골라 옮긴다 | 새 필드(`media`)를 달면 그 함수들을 모두 고쳐야 한다 → **`blocks` 안에 사진 자리표 한 줄**(`\x1f` + `photo:` + 사진ID)을 끼운다(2026-10-20 설계 변경). 고정·철회·동의 규칙이 사진에도 저절로 적용된다. 학생 글 속 `\x1f` 는 정본이 먼저 지워 자리표를 흉내 낼 수 없다. |
| 책 쪽 나누기는 화면에서 높이를 재며 글을 쪼갠다(`pagination.js`) | 사진 칸은 **쪼갤 수 없는 덩어리**로 다루고 사진이 불러진 뒤에 잰다. |

## 단계

### 2a. 학생이 올릴 때의 약속 (끝남, 코드만)
- `reportPhotoRules.js` 한 곳의 문구 4줄 + 체크 칸. 체크 전에는 사진 올리기·바꾸기 입력이 막힌다. 저장하지 않는다(DB 변경 없음).

### 2b. 서버: 사진 복사본과 선생님 확인 (끝남, 승인 뒤 적용 — `20261401`)
- 비공개 버킷 `class-agit-photos`(경로 `학급ID/사진ID.jpg|webp`, 256KB, **직접 쓰기·삭제 정책 없음**), 읽기 정책 `can_read_class_agit_photo_v1`: 담임·관리자, 그리고 **지금 볼 수 있는 전시·문집에 이 사진 자리표가 든** 같은 반 학생. 외부 공유 방문자(2d)와 이웃 반 문집은 아직.
- 표 `class_agit_item_photos`(RLS ON, 직접 권한 없음): 원본 경로·복사본 경로·크기·종류·상태(대기/복사됨/실패/제거)·확인한 선생님·시각·확인 문구 판.
- RPC: `confirm_class_agit_photo_use_v1`(담당 교사가 사진 1~3장을 보고 확인했다고 기록, 문구 판 1), `claim_class_agit_photo_copy_v1`(대기 중인 사진 목록), `finish_class_agit_photo_copy_v1`(서비스 전용), `class_agit_orphan_photo_paths_v1`(청소용, 서비스 전용).
- Edge 함수 `class-agit-photo-copy`: 요청에는 학급·사진 ID 만 받고 **경로는 DB 가 정한다**. `report-images` → `class-agit-photos` 복사. `check-operational-security.mjs` 에 등록(마이그레이션이 적용되면 배포 필수).
- 정본 `class_agit_source_data_v1` 은 4번째 인자(확인한 사진 지도)를 받는다. 칸마다 `[사진 자리표] → 글 문단` 순서로 blocks 를 만들고, 칸 제목은 뺀다. 사진 보고서도 이제 후보에 오른다(확인한 사진이 없으면 글만 담김). 칸에 실제로 있고 확인한 경로와 같은 사진만 쓰므로, 학생이 사진을 바꾸면 확인이 무효가 되고 원글 버전이 바뀐다.
- 스모크: 확인 전 글만 / 확인 후 복사 전 글만 / 복사 뒤 자리표 순서 / 다른 학급·서비스 전용 호출 거절 / 제어 문자 제거 / 사진 교체 시 확인 무효 / 전시·책 저장에 자리표 보존 / 비공개 상태에서 학생·다른 교사는 못 읽음.
- 청소 스크립트(고아 복사본 삭제)는 표지 청소(`class-agit-cover-sweep.mjs`)와 같은 방식으로 이어서.

### 2c. 화면 — 담기 전 확인과 읽기 (코드·시험 끝, 적용 대기 — `20261402`)
- **선생님 확인 화면**(`PhotoConfirmHost`): 글을 담는 모든 길(`classAgitApi.getSources`)이 확인하지 않은 사진이 든 보고서를 만나면 연다. 사진을 크게 보여 주고, 문구 체크(`TEACHER_PHOTO_CHECK_STATEMENT`) 뒤에 **담을 사진을 직접 골라야** 담긴다. 고르지 않은 사진은 빼고 글만, `사진 없이 글만 담기`·취소 가능. 확인 → 서버 기록 → Edge 복사 → 글을 다시 받아 사진이 든 모습으로 담는다. 일부 복사가 실패하면 몇 장만 담겼는지 알려 준다.
- **읽기**: 서버 `get_class_agit_photo_paths_v1`(20261402)이 읽기 권한(담임·관리자·지금 볼 수 있는 전시·책의 같은 반 학생)을 보고 복사본 경로를 알려 주면 서명 주소로 보인다. `WorkBlocks` 는 사진 찾는 방법을 주입받는다(공개 화면은 DB 를 가져오면 안 되는 구조 규칙) — 교사·학생 입구만 주입, 외부 공개 화면은 글만.
- **책자·미리보기 인쇄**: 사진을 데이터 주소로 인쇄 창에 넣고(`#anthology-photos`), 쪽 나누기는 사진을 **쪼갤 수 없는 덩어리**로 다루며 쪽 높이의 40% 안으로 줄인다. 사진이 풀린 뒤에 높이를 잰다(`settleAnthologyPhotos`).
- 구글 문서·엑셀 내보내기는 사진 자리표를 글로 쓰지 않는다(`textBlocks`) — 사진 넣기는 2d.

### 2d. 구글 문서 내보내기와 외부 공유
- 구글 문서: 사진을 해당 글 끝에 넣는 기존 방식(`googleDocImageExport`)을 책에도 연결.
- 외부 공유: 방문자는 로그인이 없으므로 공개 읽기 Edge 함수(`class-agit-public-read`)가 **짧게 유효한 서명 주소**를 발급한다. 이 단계는 외부 공개 정책과 함께 선생님이 시기를 정한다.

## 하지 않는 것
- 얼굴 자동 감지·자동 가리기(놓치는 경우가 있고 도구가 늘어난다). 선생님의 눈 확인이 기준이다.
- 사진 때문에 보호자 동의를 새로 받지는 않는다(학교 동의서 범위를 학교에서 확인).
- 독서록 표지 사진(외부 주소) — OI-035.

## 위험과 대응

| 위험 | 대응 |
|---|---|
| 선생님이 확인을 안 보고 누른다 | 사진을 크게 보여 준 뒤에만 체크 가능, 확인자·시각 기록, 철회 가능 |
| 복사본이 남아 공개 중단 뒤에도 읽힌다 | 읽기 접근을 책·전시 상태(철회·보관·공개 종료)에 묶고 청소 스크립트가 지운다 |
| 복사 중간 실패 | 사진마다 상태(대기·완료)를 두고 완료된 것만 `media` 에 싣는다. 실패하면 사진 없이 담기를 안내한다 |
| 큰 책(작품 100편·사진 300장) | 사진은 256KB 이하이고 복사는 서버에서 한 번에 여러 장씩. 화면은 지연 로딩 |

## 순서
2b(서버, 스모크) → 2c(담기 전 확인·읽기·책자) → 2d(구글 문서·외부 공유). 각 단계마다 `migrate:check`·스모크·아르곤 1회, DB 적용은 선생님 승인 뒤. 1단계(`20261400`)를 운영에 반영한 뒤 시작한다.
