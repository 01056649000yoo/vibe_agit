# 수호룡 퀴즈 아레나 — 아지트 병합 계획 (2026-10-22 시작)

> 상태: **관리자 시험 중**(`adminOnly`, 교사 `아지트 놀이터` 메뉴의 `수호룡의 인형뽑기` 바로 아래, **개발중** 표시).
> 게임 서버는 별도 저장소 `~/suhoryong-arena`(상태는 그쪽 `docs/STATUS.md`). 이 문서는 아지트 쪽 계획이다.

## 핵심 (선생님 정리, 2026-10-22)
1. 아지트 안에서 **교사가 가볍게 퀴즈 활동을 열고 학생이 참여**한다.
2. **기본 문제는 아지트에 이미 있는 어휘·맞춤법 자료**로 만든다(교사가 아무것도 입력하지 않아도 바로 쓴다).
3. 교사가 **직접 문제를 낼 수 있고, 낸 문제 세트는 공유**할 수 있다(학년·단원 정보로 찾아 불러다 쓴다).
4. 외부 접근은 막고 **관리자 계정에서만** 개발·시험한다. 공개는 선생님이 정한다.

## 구조
- 실시간 게임은 별도 서버(Docker `suhoryong-arena`, 소켓)가 돌린다. 아지트(Supabase+Edge)에는 상시 소켓 서버를 둘 수 없다.
- 아지트가 맡는 것: **로그인·메뉴·문제 세트 저장/공유·입장권 발급**. 게임 서버는 서명된 입장권만 확인한다(아지트 DB를 읽지 않음).
- 비상구: 게임 서버의 `/host` 관리자 암호 입구는 병합 뒤에도 남긴다(아지트가 멈췄을 때·외부에서 급할 때). 이 입구는 문제 세트 공유를 쓸 수 없다.

## 데이터·보안 원칙
- 문제 세트에는 학생 이름·학번·개인정보를 넣지 않는다. 기본 세트의 원본은 공개 정적 자료(`public/data/grade*_vocab.json`, `public/spelling/*`)뿐이다.
- 표는 RLS+직접 권한 닫기, 읽기·쓰기는 `SECURITY DEFINER` RPC 로만, anon 불가(SECURITY_HARNESS).
- 기본 세트 만들기는 **누를 때만** 정적 자료를 받고(`performance.load = on-open`, 홈 조회 0), 아지트 홈·학생 화면에는 아무 연결도 만들지 않는다.
- 기본 맞춤법 세트는 지금 **기본 사전+공통 카탈로그 JSON** 만 쓴다. 관리자 게시 공통 자료·학급 자료(DB)까지 쓰는 것은 4번 이후(Edge 에서 인형뽑기와 같은 방식으로).
