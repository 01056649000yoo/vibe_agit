> 바이브 코딩(AI 페어 프로그래밍)으로 구축된 **끄적끄적 아지트**의 전체 구조, 핵심 기술 스택, 코딩 방법론, 보안 체계를 비전공자나 교사도 한눈에 이해할 수 있도록 알기 쉽게 풀어서 설명한 **종합 기술 사전**입니다.

## 🗺️ 끄적끄적 아지트 시스템 전체 조감도 (System Architecture)

학생과 선생님이 스마트폰이나 태블릿, PC 브라우저에서 버튼을 눌렀을 때 데이터가 어떻게 흐르는지 보여주는 전체 지도입니다.

```
[학생 / 선생님 웹 브라우저 (Chrome, Whale, Safari)]
   │
   │ HTTPS 암호화 통신 (도메인: 끄적끄적아지트.site)
   ▼
[맥미니 호스트 (Mac mini M2 - 학교/교실 자율 운영 인프라)]
   │
   ├─► [Caddy 리버스 프록시 (포트 80/443)]
   │     • 자동 SSL/TLS 인증서 발급 및 무중단 갱신 (Let's Encrypt)
   │     • 장애 발생 시 자동 점검 화면(Outage Fallback) 안내
   │     │
   │     ├─► 프론트엔드 요청 (/): Docker `agit-app` (Node/Nginx 포트 8300)
   │     │     • React 19 + Vite 7 기반 Single Page Application (SPA)
   │     │     • 코어 셸 + 학급별 온오프 기능 모듈 (지연 로딩)
   │     │
   │     ├─► 백엔드 API 요청 (/rest/v1, /auth/v1): Docker `agit-kong` (포트 8100)
   │     │     • Supabase Kong API 게이트웨이 (JWT 토큰 검증 및 라우팅)
   │     │     │
   │     │     ├─► DB 엔진: Docker `agit-db` (PostgreSQL 17)
   │     │     │     - RLS (행 단위 보안 정책)로 다른 반/남의 글 침범 원천 차단
   │     │     │     - PL/pgSQL RPC 함수 (원자적 비즈니스 로직 및 포인트 처리)
   │     │     │     - 멀티 스키마 격리 (public, samlink, app, writing_helper)
   │     │     │
   │     │     └─► AI/함수 엔진: Docker `agit-functions` (Deno Runtime)
   │     │           - `vibe-ai`: 비동기 댓글 안전 검사 큐, 맞춤법 검사
   │     │           - 사전 로컬 비속어 필터링 후 필요시 OpenAI API 호출
   │     │
   │     └─► 연구소 연동 (/lab): Next.js 기반 연구소 앱과 통합 쿠키 SSO
   │
   ▼
[외부 서비스 연동]
   • Google Cloud OAuth (선생님 구글 원클릭 로그인)
   • OpenAI API (gpt-4o-mini: 초등학생 맞춤형 댓글 안전도 및 글쓰기 검사)
```

## 1. 인프라 & 서버 아키텍처 (Infrastructure & Hosting)

### 1.1 셀프 호스팅 (Self-Hosting)
* 📖 **전문용어 개념 해설**:
  * 아마존(AWS), 마이크로소프트(Azure), 구글(GCP) 같은 대형 클라우드 기업의 가상 컴퓨터를 매달 돈 내고 빌려 쓰는 대신, **자신이 소유한 물리적 하드웨어(서버 컴퓨터)**에 운영체제와 프로그램을 직접 설치하여 인터넷에 서비스를 제공하는 운영 방식입니다.
* 💡 **학교·일상 비유**:
  * 비싼 보증금과 월세를 내며 남의 건물 상가(클라우드)를 임대해 장사하는 대신, **내가 산 우리 집(맥미니 컴퓨터)**에 매장을 꾸며 독립적으로 운영하는 것과 같습니다.
* 🏗️ **내 앱(끄적끄적 아지트)에서의 실제 활용 & 작동 시나리오**:
  * **적용 위치**: 교실/연구실에 설치된 **Mac mini M2 (Apple Silicon, 저전력 고성능)**.
  * **작동 흐름**: 맥미니가 24시간 365일 켜져 있으며, 가정/학교 인터넷 회선에 연결되어 있습니다. 학생들이 집이나 교실에서 `끄적끄적아지트.site`로 접속하면 외부 통신사를 거쳐 이 맥미니로 직접 연결되어 웹 화면과 데이터를 전송합니다.
* 🎯 **왜 썼는가? (도입 효과 & 안 썼을 때 벌어질 끔찍한 일)**:
  * **도입 효과**: 매달 나가는 서버 비용(클라우드 DB 및 트래픽 요금 월 수십~수백만 원)이 **전기세 몇천 원 외에는 0원**이 됩니다. 또한 초등학생들의 일기나 글, 개인정보가 해외 상업용 클라우드에 저장되지 않고 선생님이 직접 통제하는 맥미니 물리 드라이브에 안전하게 보관됩니다.
  * **안 썼다면**: 트래픽이나 데이터베이스 용량이 조금만 늘어나도 매달 카드 결제 청구서가 눈덩이처럼 불어나 서비스를 유지하기 어려워졌을 것입니다.

### 1.2 도커 & 도커 컴포즈 (Docker & Docker Compose / 컨테이너 가상화)
* 📖 **전문용어 개념 해설**:
  * **도커(Docker)**는 프로그램 실행에 필요한 코드, 라이브러리, 환경설정을 하나의 독립된 가상 상자(컨테이너)로 묶어 어떤 컴퓨터에서든 똑같이 실행되게 해주는 기술입니다.
  * **도커 컴포즈(Docker Compose)**는 웹 서버, 데이터베이스, AI 엔진 등 여러 개의 도커 컨테이너를 설정 파일(`docker-compose.yml`) 하나로 한꺼번에 실행하고 관리하는 오케스트레이션 도구입니다.
* 💡 **학교·일상 비유**:
  * 이사 갈 때 짐을 낱개로 들고 가면 트럭마다 싣는 방법이 달라 엉망이 되지만, 모든 짐을 규격화된 **해상용 컨테이너 박스**에 딱 맞게 넣어두면 어떤 배나 화물 트럭에 실어도 내용물 그대로 똑같이 운반되는 원리입니다.
* 🏗️ **내 앱(끄적끄적 아지트)에서의 실제 활용 & 작동 시나리오**:
  * **적용 위치**: `~/agit-supabase/docker-compose.yml`, `docker-compose.pg17.yml`, `docker-compose.agit.yml`
  * **작동 흐름**: 아지트 시스템은 3개의 컴포즈 파일을 결합하여 실행됩니다. 프론트엔드(`agit-app`), 백엔드 게이트웨이(`agit-kong`), 데이터베이스(`agit-db`), AI 엣지 함수(`agit-functions`) 등 총 9개의 필수 서비스가 각자의 격리된 방에서 돌아가며 서로 내부 가상 네트워크(`agit-network`)를 통해 안전하게 통신합니다.
* 🎯 **왜 썼는가? (도입 효과 & 안 썼을 때 벌어질 끔찍한 일)**:
  * **도입 효과**: 맥미니 OS를 포맷하거나 다른 새 컴퓨터로 서버를 교체하더라도 `docker compose up -d` 명령어 딱 한 줄만 입력하면 1분 만에 동일한 운영 환경이 마법처럼 복구됩니다.
  * **안 썼다면**: Node 버전, PostgreSQL 버전, Deno 버전, C 라이브러리 충돌 때문에 "제 컴퓨터에선 되는데 서버 컴퓨터에선 에러가 나요!"라는 지옥 같은 환경 불일치 문제를 매일 겪었을 것입니다.

### 1.3 리버스 프록시 (Reverse Proxy) & Caddy
* 📖 **전문용어 개념 해설**:
  * **프록시(대리인)** 중에서도 **리버스 프록시**는 외부 인터넷 사용자와 내부 서버들 사이에 위치하여, 사용자의 요청을 가장 먼저 받아 알맞은 내부 서버 포트로 전달(토스)해 주고 그 결과를 다시 사용자에게 건네주는 관문 서버입니다.
* 💡 **학교·일상 비유**:
  * 학교 교문 입구의 **경비실(안내 데스크)**입니다. 학부모님이 학교에 방문했을 때 교실 번호를 몰라도 "3학년 2반 어디인가요?"라고 물어보면 경비실에서 정확한 교실로 안내해 주는 것과 같습니다. 외부 손님이 교무실이나 서버실로 무단 침입하는 것도 막아줍니다.
* 🏗️ **내 앱(끄적끄적 아지트)에서의 실제 활용 & 작동 시나리오**:
  * **적용 위치**: `/etc/caddy/Caddyfile`, [docs/OUTAGE_PLAN.md](file:///Users/seunghyeonmaegmini/vibe_agit/docs/OUTAGE_PLAN.md)
  * **작동 흐름**:
    1. 학생 브라우저가 `https://끄적끄적아지트.site`로 접속하면 맥미니의 80/443 포트를 지키고 있는 Caddy가 요청을 받습니다.
    2. 일반 웹 화면 요청(`/`)이면 웹 컨테이너(`127.0.0.1:8300`)로 넘깁니다.
    3. 데이터 조회나 로그인 요청(`/rest/v1`, `/auth/v1`)이면 Kong 게이트웨이(`127.0.0.1:8100`)로 넘깁니다.
    4. 연구소 메뉴 요청(`/lab`)이면 연구소 서비스로 자연스럽게 연결합니다.
* 🎯 **왜 썼는가? (도입 효과 & 안 썼을 때 벌어질 끔찍한 일)**:
  * **도입 효과**: Caddy는 Nginx나 Apache와 달리 HTTPS SSL 보안 인증서를 자동으로 발급받고 90일마다 알아서 갱신해 주므로 인증서 만료 사고가 영구히 없습니다.
  * **안 썼다면**: 학생들이 주소창 뒤에 포트 번호(`:8300`, `:8100`)를 일일이 붙여서 들어와야 했고, 내부 DB나 서버 포트가 외부에 그대로 노출되어 해킹 위협에 직면했을 것입니다.

### 1.4 API 게이트웨이 (API Gateway) & Kong
* 📖 **전문용어 개념 해설**:
  * 클라이언트(웹 브라우저)가 데이터베이스나 백엔드 기능에 접근하기 전에, 모든 API 요청을 단일 창구에서 모아 **인증(너 누구니?), 인가(권한 있니?), 트래픽 제어(너무 많이 호출하지 마)**를 수행하는 중앙 집중식 출입문입니다.
* 💡 **학교·일상 비유**:
  * 공항의 **출입국 심사대(보안 검색대)**입니다. 비행기(DB)를 타기 전 모든 승객이 신분증과 탑승권(JWT 토큰)을 검사받고 통과해야만 탑승할 수 있습니다.
* 🏗️ **내 앱(끄적끄적 아지트)에서의 실제 활용 & 작동 시나리오**:
  * **적용 위치**: Docker 컨테이너 `agit-kong` (내부 포트 8100)
  * **작동 흐름**: 브라우저의 Supabase 클라이언트 라이브러리가 글을 저장하거나 댓글을 불러올 때, 요청 헤더에 담긴 암호화된 토큰을 Kong이 검사합니다. 위조되지 않은 학생 토큰임이 확인되면 비로소 PostgreSQL 데이터베이스 엔진으로 요청을 안전하게 넘깁니다.
* 🎯 **왜 썼는가? (도입 효과 & 안 썼을 때 벌어질 끔찍한 일)**:
  * **도입 효과**: 데이터베이스 앞단에서 위조된 요청을 0.001초 만에 쳐내어 DB의 쓸데없는 연산 낭비를 막고 일관된 보안 검증을 보장합니다.

### 1.5 커넥션 풀링 (Connection Pooling) & Supavisor
* 📖 **전문용어 개념 해설**:
  * 데이터베이스에 쿼리를 날리려면 먼저 통신 연결(Connection)을 맺어야 하는데, 이 연결을 맺고 끊는 작업은 컴퓨터 메모리와 CPU를 매우 많이 소모합니다. 커넥션 풀링은 **미리 정해진 개수의 DB 연결 통로를 만들어 두고 손님들에게 빌려줬다가 회수하는 재사용 관리 기법**입니다.
* 💡 **학교·일상 비유**:
  * 시중 은행의 **창구 직원과 번호표 시스템**입니다. 손님 500명이 한꺼번에 몰려왔다고 해서 은행원 500명을 즉석에서 채용(DB 커넥션 생성)할 수 없으므로, 창구 직원 15명(커넥션 풀)이 번호표 순서대로 빠르고 정확하게 손님을 응대하고 바로 다음 손님을 받는 것과 같습니다.
* 🏗️ **내 앱(끄적끄적 아지트)에서의 실제 활용 & 작동 시나리오**:
  * **적용 위치**: Docker profile `pooler` (Supavisor 커넥션 풀러)
  * **작동 흐름**: 학교에서 30개 학급 1,000명의 학생이 1교시 시작(9시 정각)에 동시에 글쓰기를 열어도, 맥미니 DB에 1,000개의 물리 커넥션이 생기지 않고 Supavisor가 적정 커넥션(예: 30~50개)으로 묶어서 순차 배분합니다.
* 🎯 **왜 썼는가? (도입 효과 & 안 썼을 때 벌어질 끔찍한 일)**:
  * **도입 효과**: 학생 수백 명이 동시에 접속해도 맥미니 DB가 메모리 부족(OOM: Out Of Memory)으로 뻗어버리는 사태를 완벽히 막아줍니다.

### 1.6 장애 격리 및 시스템 점검 폴백 (Outage Fallback / Graceful Degradation)
* 📖 **전문용어 개념 해설**:
  * 메인 시스템이나 데이터베이스에 장애가 발생하거나 업데이트 점검 중일 때, 사이트가 '연결할 수 없음' 에러를 내며 하얗게 죽는 대신 **사용자에게 친절한 점검 화면을 보여주고 현재 상태를 안내하는 안전장치(Graceful Degradation: 우아한 성능 저하)**입니다.
* 💡 **학교·일상 비유**:
  * 학교 방송실 방송 장비가 고장 났을 때 아무 소리도 안 나서 전교생이 당황하게 두는 것이 아니라, 복도에 **"지금 방송 장비 점검 중입니다. 10분 뒤 정상 진행됩니다"라는 예쁜 알림 입간판**을 즉시 세워두는 것과 같습니다.
* 🏗️ **내 앱(끄적끄적 아지트)에서의 실제 활용 & 작동 시나리오**:
  * **적용 위치**: [docs/OUTAGE_PLAN.md](file:///Users/seunghyeonmaegmini/vibe_agit/docs/OUTAGE_PLAN.md), `/etc/caddy/Caddyfile`의 `handle_errors`
  * **작동 흐름**: 맥미니 재부팅이나 DB 마이그레이션 중 도커 컨테이너가 502/503 에러를 뿜으면, Caddy가 이를 가로채서 준비된 경량 정적 점검 HTML 페이지를 학생 브라우저에 0.01초 만에 띄워줍니다.
* 🎯 **왜 썼는가? (도입 효과)**:
  * 학생들이 "어? 사이트 해킹당했나 봐요!", "글 다 날아간 거 아니에요?" 하고 불안해하며 교사에게 문의하는 혼란을 원천 방지합니다.

## 2. 데이터베이스 & 백엔드 방법론 (Database & Backend)

### 2.1 관계형 데이터베이스 (RDBMS) & PostgreSQL 17
* 📖 **전문용어 개념 해설**:
  * 데이터를 행(Row)과 열(Column)로 이루어진 엑셀 표(Table) 형태로 저장하고, 표들 사이의 관계(예: 학생 표와 글 표의 연결)를 엄격한 규칙으로 엮어 데이터의 정확성과 무결성을 보장하는 데이터베이스 시스템입니다.
* 💡 **학교·일상 비유**:
  * 학교의 **공식 행정 전산 장부 시스템(나이스)**입니다. 학생 명부, 출석부, 성적표가 서로 주민번호나 학번으로 엄격히 연결되어 있어, 존재하지 않는 유령 학생이 글을 쓰거나 성적이 뒤바뀌는 일이 생기지 않습니다.
* 🏗️ **내 앱(끄적끄적 아지트)에서의 실제 활용 & 작동 시나리오**:
  * **적용 위치**: Docker 컨테이너 `agit-db` (최신 PostgreSQL 17 엔진)
  * **작동 흐름**: `students`(학생), `classes`(학급), `student_posts`(글), `post_comments`(댓글), `point_logs`(포인트 장부) 테이블이 외래키(Foreign Key)로 촘촘히 엮여 있습니다. 학생이 탈퇴하거나 학급이 삭제될 때의 참조 무결성을 DB 엔진이 스스로 감시합니다.
* 🎯 **왜 썼는가? (도입 효과)**:
  * PostgreSQL 17은 세계에서 가장 신뢰받는 오픈소스 DB로, 대규모 JSON 데이터 처리 속도가 비약적으로 향상되어 글과 댓글, AI 분석 결과를 단 1밀리초 만에 읽고 씁니다.

### 2.2 RLS (Row Level Security - 행 단위 보안 정책)
* 📖 **전문용어 개념 해설**:
  * 데이터베이스의 테이블 전체를 열람하거나 수정하는 권한을 주는 것이 아니라, **로그인한 사용자의 신원에 따라 테이블의 특정 행(Row)들만 보여주거나 숨기는 데이터베이스 엔진 차원의 보안 필터 규칙**입니다.
* 💡 **학교·일상 비유**:
  * 아파트 복도의 우편함(사물함)입니다. 방(테이블) 자체는 하나지만, **각자의 호수 열쇠로 열리는 자기 칸(행)의 우편물만 볼 수 있고 옆집 칸은 열리지도 보이지도 않는 것**과 같습니다.
* 🏗️ **내 앱(끄적끄적 아지트)에서의 실제 활용 & 작동 시나리오**:
  * **적용 위치**: 모든 DB 테이블 (`student_posts`, `post_comments`, `students` 등)
  * **작동 흐름**:
    ```sql
    -- 예: 3학년 2반 학생은 3학년 2반 글만 SELECT 할 수 있는 RLS 정책
    CREATE POLICY "내 학급 글만 읽기" ON public.student_posts
      FOR SELECT USING (
        class_id = (SELECT class_id FROM public.students WHERE auth_id = auth.uid())
      );
    ```
    학생이 브라우저에서 `SELECT * FROM student_posts;`를 호출해도, DB 엔진이 자동으로 WHERE 절을 가로채서 `WHERE class_id = '우리반ID'`를 강제로 붙여버립니다.
* 🎯 **왜 썼는가? (도입 효과 & 안 썼을 때 벌어질 끔찍한 일)**:
  * **도입 효과**: 프론트엔드 개발자가 실수로 필터링 코드를 빠뜨려도, 다른 학급의 비밀 일기나 글이 옆 반 학생 화면에 노출되는 사고가 100% 원천 차단됩니다.
  * **안 썼다면**: 똑똑한 학생이 브라우저 개발자 도구(F12) 콘솔에서 API를 직접 호출해 옆 반 친구들의 일기와 선생님 메모를 전부 털어보는 대형 개인정보 유출 사고가 터졌을 것입니다.

### 2.3 RPC (Remote Procedure Call - 원격 프로시저 호출 / 저장 프로시저)
* 📖 **전문용어 개념 해설**:
  * 클라이언트(웹 브라우저)가 DB의 테이블을 직접 조회하고 수정하는 수많은 SQL 문을 일일이 날리는 대신, **DB 서버 안에 미리 여러 동작을 하나로 묶어둔 함수(저장 프로시저: Stored Procedure)를 만들어두고 그 함수 이름만 콕 집어 호출하는 방식**입니다.
* 💡 **학교·일상 비유**:
  * 식당에서 손님이 주방에 들어가서 밥솥 열고 고기 굽고 설거지하는 게 아니라, 카운터에 **"돈가스 세트 하나 주세요!"(RPC 호출)**라고 주문서만 넣으면 주방장(DB)이 완벽히 조리해서 완제품 한 접시로 딱 내어주는 것과 같습니다.
* 🏗️ **내 앱(끄적끄적 아지트)에서의 실제 활용 & 작동 시나리오**:
  * **적용 위치**: `supabase/migrations/` 내 모든 `CREATE FUNCTION public.xxx_v1()`
  * **작동 흐름**:
    학생이 댓글을 작성할 때 브라우저는 DB 테이블을 건드리지 않고 아래 코드 딱 한 줄만 실행합니다.
    ```javascript
    const { data, error } = await supabase.rpc('create_my_post_comment_v1', {
      p_post_id: '글ID',
      p_content: '정말 멋진 글이야!'
    });
    ```
    DB 내부 함수가 0.001초 만에:
    1. 로그인한 학생이 해당 글을 볼 권한이 있는지 검사
    2. 글자수가 8자 이상 200자 이하인지 검증
    3. 댓글 테이블에 INSERT
    4. AI 안전 검사 대기열 큐에 등록
    5. 최종 결과를 깔끔한 JSON 하나로 묶어 응답
* 🎯 **왜 썼는가? (도입 효과 & 안 썼을 때 벌어질 끔찍한 일)**:
  * **도입 효과**: 브라우저와 서버 간 네트워크 통신이 5번에서 1번으로 줄어들어 속도가 극도로 빨라지고, 비즈니스 로직이 서버에 은닉되어 안전해집니다.
  * **안 썼다면**: 학생이 브라우저 코드를 조작해 글자 수 제한을 무시하고 10만 자짜리 도배 댓글을 달거나, 포인트를 999,999점으로 위조해 DB에 직접 꽂아 넣었을 것입니다.

### 2.4 SECURITY DEFINER vs SECURITY INVOKER (권한 상승과 격리)
* 📖 **전문용어 개념 해설**:
  * DB 함수를 실행할 때 적용되는 권한 모드입니다.
  * **SECURITY INVOKER**: 함수를 호출한 사람 본인의 권한으로 실행 (학생이 부르면 학생 권한으로 제한).
  * **SECURITY DEFINER**: 함수를 만든 사람(DB 관리자/슈퍼유저)의 전지전능한 권한으로 임시 승격되어 실행.
* 💡 **학교·일상 비유**:
  * **INVOKER**: 학생이 자기 학생증을 들고 도서관에 들어가는 것 (학생 열람실만 출입 가능).
  * **DEFINER**: 학생이 신청서를 내면, **사서 선생님(관리자)이 마스터키를 꺼내어** 일반 학생은 들어갈 수 없는 귀중본 서고(포인트 장부 테이블)에 들어가 안전하게 책을 꺼내다 건네주는 것과 같습니다.
* 🏗️ **내 앱(끄적끄적 아지트)에서의 실제 활용 & 작동 시나리오**:
  * **적용 위치**: 포인트 지급 RPC([src/modules/points/](file:///Users/seunghyeonmaegmini/vibe_agit/src/modules/points/)), 댓글 AI 승인 RPC.
  * **작동 흐름**: 학생은 보안상 `point_logs`(포인트 장부) 테이블에 직접 INSERT할 수 있는 RLS 권한이 없습니다. 하지만 학생이 미션을 완수하면 `SECURITY DEFINER`로 선언된 공용 함수가 실행되어, 관리자 권한으로 포인트 장부에 안전하게 100점을 적립해 줍니다.
* 🎯 **주의점 및 보안 불변식**:
  * SECURITY DEFINER 함수는 무소불위의 권한을 가지므로, 악의적인 해커가 가짜 함수를 끼워 넣지 못하도록 함수 선언부에 반드시 `SET search_path TO 'public'`을 박아두어야 합니다.

### 2.5 DB 트랜잭션 (BEGIN - COMMIT - ROLLBACK / ACID 원자성)
* 📖 **전문용어 개념 해설**:
  * 여러 개의 데이터베이스 변경 작업을 하나의 작업 묶음으로 취급하여, **"모두 성공하거나(COMMIT), 하나라도 실패하면 아무 일도 없었던 것처럼 전부 취소(ROLLBACK)하는"** 원자성(All or Nothing) 보장 기법입니다.
* 💡 **학교·일상 비유**:
  * **은행 계좌 이체**입니다. 내 통장에서 1만 원이 출금되는 것과 친구 통장에 1만 원이 입금되는 것은 반드시 둘 다 성공해야 합니다. 만약 내 돈은 빠져나갔는데 중간에 인터넷이 끊겨 친구에게 입금이 안 됐다면? 즉시 취소(ROLLBACK)되어 내 돈이 다시 통장으로 돌아와야 합니다.
* 🏗️ **내 앱(끄적끄적 아지트)에서의 실제 활용 & 작동 시나리오**:
  * **적용 위치**: 모든 마이그레이션 파일(`BEGIN; ... COMMIT;`), 글 제출 및 포인트 적립 함수.
  * **작동 흐름**: 학생이 글을 제출하고 50포인트를 받는 과정에서, 글은 저장되었는데 포인트 장부 기록 중 DB 에러가 발생하면 트랜잭션이 작동하여 저장되던 글도 취소시키고 에러를 반환합니다.
* 🎯 **왜 썼는가? (도입 효과)**:
  * "글은 등록되었는데 포인트는 안 들어왔어요", "포인트는 깎였는데 아이템은 안 생겼어요" 같은 데이터 불일치 및 꼬임 현상을 0%로 박멸합니다.

### 2.6 DB 마이그레이션 (Database Migration) & 롤백 스모크 테스트
* 📖 **전문용어 개념 해설**:
  * 데이터베이스의 테이블 구조나 함수 변경 내역을 버전별 SQL 스크립트 파일로 기록하여 추적·배포하는 기법입니다. **롤백 스모크 테스트**는 새 마이그레이션을 운영 DB에 적용하기 전에, 임시 가상 환경에서 적용 후 원상복구(ROLLBACK)가 완벽히 되는지 미리 불을 붙여 시험해보는 안전 검증입니다.
* 💡 **학교·일상 비유**:
  * 신축 건물의 엘리베이터를 개통하기 전, 승객을 태우지 않고 **비상 정지 버튼과 원위치 복귀 기능이 제대로 작동하는지 모래주머니를 싣고 사전 시뮬레이션**을 돌려보는 것과 같습니다.
* 🏗️ **내 앱(끄적끄적 아지트)에서의 실제 활용 & 작동 시나리오**:
  * **적용 위치**: `supabase/migrations/*.sql`, `tests/sql/*.smoke.sql`, `npm run migrate:check`
  * **작동 흐름**: 개발자가 새로운 기능(예: `20261351_comment_max_chars_200.sql`)을 만들면, 배포 전에 `npm run migrate:check`를 실행합니다. 실제 DB 복제본 위에서 트랜잭션을 열고 스모크 테스트를 돌린 뒤 100% 롤백되는지 자동으로 확인합니다.
* 🎯 **왜 썼는가? (도입 효과)**:
  * 배포 당일 실제 운영 DB에서 문법 에러나 권한 에러가 터져 교실 수업 도중 사이트가 멈추는 대형 참사를 사전에 방지합니다.

### 2.7 스키마 격리 (Schema Isolation / 멀티 테넌시)
* 📖 **전문용어 개념 해설**:
  * 하나의 PostgreSQL 데이터베이스 엔진 안에서 방(Schema)을 여러 개로 분리하여 서로 다른 서비스들이 테이블 이름 충돌 없이 독립적으로 공존할 수 있게 하는 기술입니다.
* 💡 **학교·일상 비유**:
  * 하나의 학교 건물 안에서 1층은 **초등 교실(`public`)**, 2층은 **교육연구소(`writing_helper`)**, 3층은 **교무 행정실(`samlink`)**, 4층은 **자비스 AI실(`app`)**로 층간 칸막이를 쳐서 서로의 짐이 섞이지 않게 하는 것입니다.
* 🏗️ **내 앱(끄적끄적 아지트)에서의 실제 활용 & 작동 시나리오**:
  * **적용 위치**: `public`(아지트 본체), `samlink`(샘링크 연동), `app`(자비스 앱), `writing_helper`(연구소 연동).

## 3. 프론트엔드 & 리액트 아키텍처 (Frontend & React Patterns)

### 3.1 SPA (Single Page Application) & React 19
* 📖 **전문용어 개념 해설**:
  * **SPA(단일 페이지 애플리케이션)**는 사용자가 링크를 누를 때마다 웹서버에서 HTML 페이지 전체를 새로 내려받아 깜빡거리며 새로고침하지 않고, 단 한 번 로드된 후 바뀐 데이터 부분만 자바스크립트로 부드럽게 갈아 끼우는 모던 웹 방식입니다.
  * **React 19**는 UI를 레고 블록(컴포넌트)처럼 조립하고 데이터(State)가 바뀔 때 화면을 가장 빠르고 부드럽게 갱신해 주는 프런트엔드 라이브러리입니다.
* 💡 **학교·일상 비유**:
  * 칠판 전체를 분필 지우개로 벅벅 지우고 새로 쓰는 게 아니라, **전자칠판에서 바뀐 글자 하나만 터치해서 0.01초 만에 싹 바꾸는 것**과 같습니다.
* 🏗️ **내 앱(끄적끄적 아지트)에서의 실제 활용 & 작동 시나리오**:
  * **적용 위치**: `src/App.jsx`, `src/components/`, `package.json`
  * **작동 흐름**: 학생이 홈에서 '글쓰기'로 가거나 '친구 아지트'로 탭을 바꿀 때 브라우저 새로고침(하얀 화면 깜빡임) 없이 앱처럼 즉시 전환됩니다.

### 3.2 빌드 도구 & 번들러 (Bundler / HMR) & Vite 7
* 📖 **전문용어 개념 해설**:
  * 수백 개의 자바스크립트, CSS, 이미지 파일들을 브라우저가 가장 빠르게 읽을 수 있는 최적의 작은 파일 묶음으로 압축·변환(번들링)해 주는 차세대 초고속 개발 도구입니다. **HMR(Hot Module Replacement)**을 통해 코드를 수정하자마자 브라우저 새로고침 없이 0.05초 만에 변경 내용이 화면에 반영됩니다.
* 💡 **학교·일상 비유**:
  * 복잡한 교재 원고 수백 장을 인쇄소에서 고속 윤전기로 순식간에 양면 제본하여 학생들이 읽기 편한 얇고 예쁜 한 권의 책으로 묶어주는 초고속 출판기계입니다.
* 🏗️ **내 앱(끄적끄적 아지트)에서의 실제 활용 & 작동 시나리오**:
  * **적용 위치**: `vite.config.js`, `package.json`의 `npm run dev`, `npm run build`
  * **작동 흐름**: 개발자가 글꼴 크기나 버튼 색상을 바꾸면 번개 같은 속도로 개발 화면에 즉시 적용되며, 배포 시에는 수십 메가바이트의 소스코드를 수백 킬로바이트로 최적화해 압축합니다.

### 3.3 코어 셸 (Core Shell) vs 플러그블 기능 모듈 (Pluggable Feature Modules)
* 📖 **전문용어 개념 해설**:
  * 시스템의 핵심 필수 영역(코어 셸)과 부가적인 선택 기능(기능 모듈)을 엄격히 분리하여, 부가 기능에 버그가 생기거나 기능을 꺼두어도 핵심 기능은 절대 멈추지 않도록 설계하는 아키텍처 패턴입니다.
* 💡 **학교·일상 비유**:
  * **스마트폰의 기본 전화/문자 기능(코어 셸)**과 **앱스토어에서 다운받은 게임 앱(기능 모듈)**의 관계입니다. 게임 앱이 에러로 튕기거나 지워져도, 엄마와의 긴급 전화 통화는 아무런 문제 없이 작동해야 합니다.
* 🏗️ **내 앱(끄적끄적 아지트)에서의 실제 활용 & 작동 시나리오**:
  * **적용 위치**:
    * **코어 셸**: 학생 로그인, 기본 글쓰기 파이프라인([StudentWriting.jsx](file:///Users/seunghyeonmaegmini/vibe_agit/src/components/student/StudentWriting.jsx)), 포인트 정산 엔진([src/modules/points/](file:///Users/seunghyeonmaegmini/vibe_agit/src/modules/points/))
    * **기능 모듈**: 드래곤 키우기, 어휘의 탑, 학급 문집 2.5D 전시관([src/modules/](file:///Users/seunghyeonmaegmini/vibe_agit/src/modules/))
  * **불변 판정 기준**: *"이 기능이 꺼졌을 때 초등 국어 글쓰기 수업이 중단되는가?"* → 중단되면 코어 셸, 정상 진행되면 기능 모듈!
* 🎯 **왜 썼는가? (도입 효과)**:
  * 선생님이 학급 관리자 화면에서 "우리 반은 오늘 게임 끕니다" 하고 드래곤이나 어휘의 탑을 OFF로 꺼도, 글쓰기 과제 제출과 피드백은 100% 정상 작동합니다.

### 3.4 선언적 모듈 레지스트리 (Declarative Module Registry & Manifest)
* 📖 **전문용어 개념 해설**:
  * 새로운 기능을 추가할 때 기존 메인 코드 곳곳을 뜯어고치지 않고, 그 기능의 이름, 아이콘, 진입점, 성능 특성을 적은 **명세서(Manifest)** 파일 하나만 만들어 등록소(Registry)에 꽂아 넣으면 시스템이 이를 알아서 인식하는 플러그인 등록 방식입니다.
* 💡 **학교·일상 비유**:
  * 멀티탭의 **플러그 앤 플레이(Plug & Play) 콘센트**입니다. 새 선풍기를 사 왔을 때 벽 내부 전선 공사를 다시 할 필요 없이 콘센트에 플러그만 꽂으면 전기가 통하는 것과 같습니다.
* 🏗️ **내 앱(끄적끄적 아지트)에서의 실제 활용 & 작동 시나리오**:
  * **적용 위치**: [src/modules/registry.js](file:///Users/seunghyeonmaegmini/vibe_agit/src/modules/registry.js), 각 모듈의 `manifest.js`
  * **작동 흐름**:
    ```javascript
    // src/modules/game/vocab-tower/manifest.js 예시
    export default {
      id: 'vocab-tower',
      name: '어휘의 탑',
      studentEntry: lazy(() => import('./StudentEntry.jsx')),
      teacherEntry: lazy(() => import('./TeacherEntry.jsx')),
      performance: { homeSummary: false, writesViaRpc: true, maxInitialList: 50 }
    };
    ```
* 🎯 **왜 썼는가? (도입 효과)**:
  * 메인 대시보드 코드를 한 줄도 수정하지 않고도 새로운 게임이나 도구를 완벽히 안전하게 붙였다 뗐다 할 수 있습니다.

### 3.5 상태 관리 (State Management) & Zustand
* 📖 **전문용어 개념 해설**:

### 3.6 관심사 분리 (Separation of Concerns) & 커스텀 훅 (Custom Hooks)
* 📖 **전문용어 개념 해설**:
  * 사용자에게 보여주는 UI 화면(버튼, 글자, 디자인)과 뒤에서 돌아가는 비즈니스 로직(데이터 조회, 유효성 검사, 네트워크 통신)을 하나의 파일에 마구 섞어 쓰지 않고 깔끔하게 분리하는 리액트 코딩 기법입니다.
* 💡 **학교·일상 비유**:
  * 자동차의 **운전석 대시보드**와 **엔진룸**의 분리입니다. 운전자는 운전대와 엑셀 페달(UI 컴포넌트)만 밟으면 되고, 복잡한 연료 분사와 모터 제어(데이터 로직)는 엔진룸 전용 장치(커스텀 훅)가 알아서 처리합니다.
* 🏗️ **내 앱(끄적끄적 아지트)에서의 실제 활용 & 작동 시나리오**:
  * **적용 위치**:
    * [src/hooks/usePostInteractions.js](file:///Users/seunghyeonmaegmini/vibe_agit/src/hooks/usePostInteractions.js): 댓글 쓰기, 글자수 체크, AI 검사 상태 추적 로직 전담.
    * `src/hooks/useStudentHome.js`: 학생 홈 화면 데이터 조회 및 에러 처리 전담.
* 🎯 **왜 썼는가? (도입 효과)**:
  * 화면 디자인을 완전히 뜯어고쳐도 데이터 통신 코드는 1줄도 건드릴 필요가 없어 버그 발생률이 80% 줄어듭니다.

### 3.7 코드 분할 (Code Splitting) & 지연 로딩 (Lazy Loading / Dynamic Import)
* 📖 **전문용어 개념 해설**:
  * 사용자가 처음 웹사이트에 접속할 때 사이트 전체의 모든 코드(수십 메가바이트)를 한꺼번에 다운로드하지 않고, **지금 당장 필요한 첫 화면 코드만 먼저 내려받은 뒤 다른 메뉴를 클릭할 때 비로소 그 화면 코드를 네트워크로 가져오는 최적화 기법**입니다.
* 💡 **학교·일상 비유**:
  * 뷔페 식당에서 100가지 음식을 처음부터 식탁에 다 쌓아두면 식탁이 무너지므로, **손님이 디저트 코너로 발걸음을 옮겼을 때 비로소 신선한 조각 케이크를 꺼내오는 것**과 같습니다.
* 🏗️ **내 앱(끄적끄적 아지트)에서의 실제 활용 & 작동 시나리오**:
  * **적용 위치**: `React.lazy()`, `import()`를 사용한 모든 하위 기능 모듈과 대형 모달창.
  * **작동 흐름**: 학생이 홈 화면에 접속할 때는 무거운 2.5D 문집 갤러리나 어휘의 탑 게임 코드가 로드되지 않습니다. 학생이 '어휘의 탑' 버튼을 터치하는 순간에만 해당 모듈이 0.1초 만에 비동기로 로드됩니다.
* 🎯 **왜 썼는가? (도입 효과)**:
  * 교실의 낡은 교육용 태블릿이나 느린 LTE 스마트폰에서도 초기 첫 화면 로딩이 1초 만에 번개처럼 뜹니다.

### 3.8 SSR (Server-Side Rendering) 연동 패키지 (`@supabase/ssr`)
* 📖 **전문용어 개념 해설**:
  * 브라우저뿐만 아니라 서버 환경(Node.js, Next.js 등)에서도 사용자의 로그인 인증 쿠키를 안전하고 일관되게 읽고 쓸 수 있도록 지원하는 Supabase 공식 최신 세션 연동 패키지입니다.
* 💡 **학교·일상 비유**:
  * 학생이 들고 다니는 종이 학생증(로컬스토리지) 대신, 학교 교문과 기숙사 입구 양쪽에 모두 비치된 **공식 통합 전자 출입증 리더기**입니다.
* 🏗️ **내 앱(끄적끄적 아지트)에서의 실제 활용 & 작동 시나리오**:
  * **적용 위치**: `package.json`, 연구소(`/lab`) Next.js 서버 및 통합 세션 핸들러.
  * **작동 흐름**: 아지트 본체에서 로그인한 교사의 세션 쿠키를 서버 사이드에서도 안전하게 복호화하여 교사 권한을 검증합니다.

* **`@supabase/supabase-js`**:
  * 📖 **해설**: 브라우저나 클라이언트 앱에서 Supabase 백엔드의 모든 기능(데이터베이스 쿼리, 보안 RPC 호출, JWT 인증 세션, 파일 저장소)을 단 몇 줄의 안전한 코드로 쉽게 다룰 수 있게 해주는 공식 자바스크립트 SDK 클라이언트 라이브러리입니다.
  * 🏗️ **활용**: `src/lib/supabaseClient.js`, 모든 데이터 조회 및 RPC 통신 전반.
* **`react-dom`**:
  * 📖 **해설**: 리액트 컴포넌트 트리(가상 DOM)를 실제 웹 브라우저 화면(실제 HTML DOM)에 마운트하고, 변경된 부분만 극도로 빠른 속도로 교체해 주는 리액트의 핵심 웹 렌더링 엔진입니다.
  * 🏗️ **활용**: `src/main.jsx`의 `createRoot` 및 전체 컴포넌트 렌더링.
* **`zustand`**:
  * 📖 **해설**: 번들 크기가 1KB 미만으로 극도로 가벼우면서도, 복잡한 보일러플레이트 코드 없이 직관적인 훅(Hook) 문법으로 전역 상태를 공유하게 해주는 모던 상태 관리 라이브러리입니다.

* **Framer Motion (`framer-motion`)**:
  * 📖 **해설**: 복잡한 CSS 키프레임 노가다 없이 선언적 코드 몇 줄로 자연스러운 물리 기반 스프링 애니메이션을 만들어주는 리액트 최고봉 모션 라이브러리.

## 4. 보안 & 인증 체계 (Security & Authorization)

### 4.1 JWT (JSON Web Token) 기반 무상태 인증 & `auth.uid()`
* 📖 **전문용어 개념 해설**:
  * 사용자의 로그인 정보를 서버 메모리(세션)에 일일이 기록해 두지 않고, 사용자의 신원 정보(ID, 역할, 유효기간)를 암호화된 전자 서명과 함께 문자열 토큰으로 만들어 클라이언트에게 쥐여주는 **무상태(Stateless) 인증 방식**입니다.
* 💡 **학교·일상 비유**:
  * 놀이공원의 **위조 불가능한 방수 자유이용권 팔찌**입니다. 놀이기구를 탈 때마다 사무실에 전화해서 "이 사람 입장권 산 거 맞아요?" 묻지 않고, 팔찌의 홀로그램 서명만 확인하고 즉시 태워주는 것과 같습니다.
* 🏗️ **내 앱(끄적끄적 아지트)에서의 실제 활용 & 작동 시나리오**:
  * **적용 위치**: 모든 API 호출 헤더(`Authorization: Bearer <JWT>`), DB 내부 `auth.uid()` 함수.
  * **작동 흐름**: 학생이 로그인하면 Supabase가 암호화된 JWT를 발급합니다. 브라우저가 글을 쓸 때 이 토큰을 함께 보내면, DB는 `auth.uid()`를 통해 토큰을 푼 뒤 "아, 이 요청은 진짜 3반 김철수가 보낸 게 맞구나" 하고 0.0001초 만에 확인합니다.
* 🎯 **왜 썼는가? (도입 효과)**:
  * 1,000명의 학생이 로그인해도 맥미니 서버 메모리에 세션 정보가 쌓이지 않아 서버가 지치지 않습니다.

### 4.2 SSO (Single Sign-On / 통합 로그인) & 최상위 도메인 쿠키 (Root Cookie)
* 📖 **전문용어 개념 해설**:
  * 여러 개의 서로 다른 독립된 웹 서비스(예: 아지트 본체와 아지트 연구소)를 이용할 때, 각 사이트마다 로그인할 필요 없이 **한 곳에서 한 번만 로그인하면 모든 서비스가 자동으로 로그인 상태를 공유하는 통합 인증 기술**입니다.
* 💡 **학교·일상 비유**:
  * 에버랜드 자유이용권 하나로 놀이공원(아지트)도 즐기고 워터파크(연구소)도 추가 검표 없이 자유롭게 드나드는 것과 같습니다.
* 🏗️ **내 앱(끄적끄적 아지트)에서의 실제 활용 & 작동 시나리오**:
  * **적용 위치**: `sb-agit-auth-token` 최상위 도메인 쿠키 (`Domain=.끄적끄적아지트.site; Path=/; SameSite=Lax`).
  * **작동 흐름**: 선생님이 `끄적끄적아지트.site`에서 구글 계정으로 로그인한 뒤 연구소 메뉴(`/lab`)를 클릭해 이동해도, 브라우저가 공용 쿠키를 자동으로 전달하므로 재로그인 창 없이 선생님의 학급 데이터가 그대로 이어집니다.

### 4.3 RBAC (Role-Based Access Control / 3단계 역할 기반 접근 제어)
* 📖 **전문용어 개념 해설**:
  * 사용자 개개인마다 일일이 권한을 설정하는 대신, 사용자가 속한 역할(Role)에 따라 시스템 접근 권한을 등급별로 부여하는 체계적인 권한 관리 방식입니다.
* 💡 **학교·일상 비유**:
  * 학교 열쇠 등급입니다. **학생 열쇠**(내 사물함만 열림) / **교사 열쇠**(우리 교실과 교무실 열림) / **행정실장 마스터키**(변전실, 서버실 등 전 구역 열림).
* 🏗️ **내 앱(끄적끄적 아지트)에서의 실제 활용 & 작동 시나리오**:
  * **적용 위치**: DB 함수 `public.auth_user_role()`, `classes` 및 `teachers` 테이블.
  * **3단계 역할**:
    1. **학생 (student)**: 자기 학급 글 열람, 내 글쓰기, 내 댓글 관리. 다른 학생의 글 수정/삭제는 절대 불가.
    2. **교사 (teacher)**: 자기 학급 학생 가입 승인, 글쓰기 과제 출제, 학급 글 검토 및 피드백, 학급 문집 출판.
    3. **관리자 (admin)**: 전체 시스템 모니터링, 어휘 사전 단어 승인, 신규 베타 기능 롤아웃 통제.

### 4.4 레이트 리밋 (Rate Limiting) & 일일 쿼터 (Daily Quota)
* 📖 **전문용어 개념 해설**:
  * 특정 사용자나 IP가 짧은 시간 동안 비정상적으로 많은 요청을 보내거나 하루 허용량을 초과하여 시스템 리소스를 독점하지 못하도록 요청 횟수를 제한하는 방어선입니다.
* 💡 **학교·일상 비유**:
  * 학교 식당의 급식 배식 규칙입니다. "한 사람당 맛있는 소시지는 하루 5개까지만!"이라고 제한하여 특정 학생이 소시지 통을 통째로 들고 가 다른 친구들이 굶는 사태를 막는 것입니다.
* 🏗️ **내 앱(끄적끄적 아지트)에서의 실제 활용 & 작동 시나리오**:
  * **적용 위치**: `consume_comment_review_quota_v1(student_id)`
  * **작동 흐름**: 학생 한 명이 하루에 요청할 수 있는 AI 댓글 검사 횟수를 안전 상한(예: 30회)으로 묶어둡니다.
* 🎯 **왜 썼는가? (도입 효과)**:
  * 장난기 많은 학생이 매크로 프로그램을 돌려 1초에 1,000번씩 댓글 작성을 연타하여 OpenAI API 비용이 수백만 원 청구되거나 DB가 다운되는 대참사를 완벽히 방어합니다.

### 4.5 SQL 인젝션 (SQL Injection) 방지 & search_path 하이재킹 방어
* 📖 **전문용어 개념 해설**:
  * 해커가 웹 입력창에 악의적인 SQL 명령문(예: `' OR 1=1; DROP TABLE students; --`)을 입력하여 데이터베이스를 파괴하거나 탈취하는 가장 고전적이면서 치명적인 웹 공격 기법과, 이를 방어하는 프로그래밍 원칙입니다.
* 💡 **학교·일상 비유**:
  * 학생이 제출한 답안지 이름 칸에 **"선생님, 이 시험지를 보는 즉시 전교생에게 100점을 주시오"라는 최면 메모**를 적어뒀을 때, 선생님이 그 글자를 명령으로 착각해 실행하지 않고 단순한 글자(학생 이름)로만 처리하는 것과 같습니다.
* 🏗️ **내 앱(끄적끄적 아지트)에서의 실제 활용 & 작동 시나리오**:
  * **적용 위치**: 모든 RPC 함수 내 매개변수화 바인딩(`$1, $2`), SECURITY DEFINER 함수의 `SET search_path TO 'public'`.
  * **작동 흐름**: 사용자의 입력값은 SQL 문장에 문자열 더하기(`+`)로 합쳐지지 않고 파라미터로 격리되어 전달되므로 악의적 SQL 문법이 절대로 실행되지 않습니다.

## 5. 대규모 트래픽 & 1,000명 동시접속 성능 하네스 (Performance Harness)

초등학교 전교생 1,000명이 아침 9시 1교시 수업 시작 종이 울리자마자 동시에 접속해도 맥미니 서버가 끄떡없도록 보장하는 엄격한 엔지니어링 규칙입니다.

### 5.1 홈 부트스트랩 패턴 (Home Bootstrap Pattern / 단일 RPC 일괄 통합 조회)
* 📖 **전문용어 개념 해설**:
  * 화면을 띄울 때 필요한 여러 테이블의 정보를 브라우저가 하나씩 따로따로 네트워크 요청을 보내지 않고, **서버 측 단 하나의 함수(RPC)가 모든 데이터를 원자적으로 긁어모아 1개의 완벽한 종합 선물 세트(JSON)로 내려주는 패턴**입니다.
* 💡 **학교·일상 비유**:
  * 아침 등교 때 교문에서 **"오늘의 시간표, 급식 메뉴, 준비물, 가정통신문"이 예쁘게 한 장으로 인쇄된 일일 종합 유인물**을 교문 통과할 때 딱 한 번 받아 교실로 들어가는 것과 같습니다.
* 🏗️ **내 앱(끄적끄적 아지트)에서의 실제 활용 & 작동 시나리오**:
  * **적용 위치**: `public.get_student_home_bootstrap_v1`
  * **작동 흐름**:
    학생 홈 화면이 열릴 때 아래 6가지 정보를 따로 부르지 않습니다.
    1. 학생 기본 프로필 및 레벨
    2. 소속 학급 정보 및 활성화된 기능 모듈 목록
    3. 내 최신 글 및 미션 현황
    4. 읽지 않은 새 알림 목록
    5. 현재 착용 중인 칭호 및 배지
    6. 학급 공지사항
    이 모든 것을 `get_student_home_bootstrap_v1` 함수 하나가 0.005초 만에 단 1번의 응답으로 끝냅니다.
* 🎯 **왜 썼는가? (도입 효과)**:
  * 1,000명이 동시 접속할 때 발생하는 네트워크 요청 수가 **6,000번에서 1,000번으로 83% 격감**하여 맥미니 CPU 사용률이 10% 미만으로 평온을 유지합니다.

### 5.2 N+1 쿼리 문제 해결 (N+1 Query Problem / Batch & Aggregate)
* 📖 **전문용어 개념 해설**:
  * 목록 데이터 N개를 가져온 뒤, 각 항목의 상세 정보나 하위 개수(예: 댓글 수, 좋아요 수)를 얻기 위해 **루프를 돌며 N번의 추가 쿼리를 날려 총 N+1번의 데이터베이스 조회가 발생하는 대표적인 성능 저하 버그**입니다.
* 💡 **학교·일상 비유**:
  * 배달 기사님이 피자 30판을 배달할 때, 피자 1판 싣고 배달 가고 다시 가게 와서 2번째 판 싣고 가기를 30번 반복(총 31번 왕복)하는 끔찍하게 비효율적인 방식과 같습니다. 큰 배달 가방에 30판을 한 번에 싣고 한 번만 다녀와야 합니다.
* 🏗️ **내 앱(끄적끄적 아지트)에서의 실제 활용 & 작동 시나리오**:
  * **적용 위치**: 게시글 목록 조회 쿼리, 학급 문집 작품 목록 조회.
  * **작동 흐름**: 글 20개를 가져올 때 각 글의 댓글 수를 20번 조회하지 않고, PostgreSQL의 `LEFT JOIN`과 `COUNT()` 집계 함수, 또는 CTE(Common Table Expression)를 사용하여 1번의 쿼리로 글과 댓글 수를 결합해 가져옵니다.

### 5.3 인메모리 캐시 (In-Memory Cache) & TTL (Time-To-Live)
* 📖 **전문용어 개념 해설**:
  * 매번 디스크의 데이터베이스를 두드려 읽어오는 대신, 한 번 조회한 결과를 컴퓨터의 초고속 RAM(메모리)에 임시로 저장해 두고 유효기간(TTL: Time-To-Live, 예: 3분) 동안은 메모리에서 빛의 속도로 즉시 꺼내주는 속도 최적화 기술입니다.
* 💡 **학교·일상 비유**:
  * 학생들이 자주 묻는 질문("선생님, 오늘 4교시 뭐예요?")의 답을 교탁 위 포스트잇에 적어두고, 10분 동안은 교무실 서류철을 다시 뒤적이지 않고 포스트잇만 보고 0.1초 만에 대답해 주는 것과 같습니다.
* 🏗️ **내 앱(끄적끄적 아지트)에서의 실제 활용 & 작동 시나리오**:
  * **적용 위치**: [src/lib/cache.js](file:///Users/seunghyeonmaegmini/vibe_agit/src/lib/cache.js) (`dataCache`, `classKey`)
  * **작동 흐름**: 자주 바뀌지 않는 학급 공지사항, 학급 온오프 설정은 `dataCache`에 캐싱되어 1,000명의 학생이 새로고침을 눌러도 DB를 단 한 번도 두드리지 않고 메모리에서 0밀리초 만에 응답합니다.

### 5.4 상시 웹소켓 차단 & 지연 분산 폴링 (Polling with Random Jitter)
* 📖 **전문용어 개념 해설**:
  * 모든 학생 기기와 서버 사이에 실시간 파이프(웹소켓)를 24시간 내내 꽂아두면 서버 리소스가 고갈되므로, **주기적인 가벼운 HTTP 요청(폴링)을 사용하되 요청 시간에 무작위 지연(Jitter, 예: 60초 ± 15초)을 섞어 트래픽이 한순간에 겹치지 않게 분산시키는 기술**입니다.
* 💡 **학교·일상 비유**:
  * 전교생 1,000명이 교무실 선생님과 통화하기 위해 수화기를 계속 든 채 대기(웹소켓 상시 연결)하면 교환기가 터지므로, 필요할 때만 1분~2분 간격으로 각자 다른 초에 전화를 걸어 용건만 묻고 끊는 방식입니다.
* 🏗️ **내 앱(끄적끄적 아지트)에서의 실제 활용 & 작동 시나리오**:
  * **적용 위치**: [PERFORMANCE_HARNESS.md](file:///Users/seunghyeonmaegmini/vibe_agit/PERFORMANCE_HARNESS.md), [usePostInteractions.js](file:///Users/seunghyeonmaegmini/vibe_agit/src/hooks/usePostInteractions.js)

## 6. AI 파이프라인 & 비용 최적화 (AI Engine & Cost Optimization)

### 6.1 엣지 함수 (Edge Functions / Deno Serverless Runtime)
* 📖 **전문용어 개념 해설**:
  * 무거운 상시 웹서버를 하나 더 띄우지 않고, 특정 이벤트(AI 검사 요청 등)가 발생했을 때만 순식간에 깨어나 코드를 실행하고 사라지는 초경량 서버리스 자바스크립트/타입스크립트 실행 환경(Deno 기반)입니다.
* 💡 **학교·일상 비유**:
  * 교문 옆에 있는 **AI 전문 상담 부스**입니다. 평소에는 불을 끄고 대기하다가 학생이 검사 신청서를 쏙 넣으면 불이 켜지면서 3초 만에 검사를 마치고 다시 대기 모드로 돌아가는 고효율 부스입니다.
* 🏗️ **내 앱(끄적끄적 아지트)에서의 실제 활용 & 작동 시나리오**:
  * **적용 위치**: `supabase/functions/vibe-ai/index.ts`
  * **작동 흐름**: 브라우저는 비싼 OpenAI API 키를 절대로 알 수 없습니다. 브라우저는 오직 Deno 엣지 함수(`vibe-ai`)만 호출하며, 엣지 함수 내부 환경변수에서 API 키를 꺼내 안전하게 AI를 다룹니다.

### 6.2 비동기 작업 대기열 (Task Queue) & 임대 토큰 (Lease Token / 비관적 락)
* 📖 **전문용어 개념 해설**:
  * 수많은 사용자가 동시에 AI 검사를 요청했을 때 서버가 감당하지 못해 뻗지 않도록, 작업들을 대기열(Queue)에 줄 세워두고 일꾼(워커)이 순서대로 하나씩 집어가 처리하되, 작업 중복을 막기 위해 **임대 토큰(Lease Token)**과 잠금(Lock)을 부여하는 분산 처리 기법입니다.
* 💡 **학교·일상 비유**:
  * 놀이공원의 **탑승 번호표와 모래시계**입니다. 손님이 몰려도 줄을 세운 뒤 1명씩 들여보내며, 들어간 손님에게 "너는 20초 동안 이 기구를 탈 권리가 있다(임대 토큰)"고 부여하여 다른 손님과 부딪히지 않게 하는 것입니다.
* 🏗️ **내 앱(끄적끄적 아지트)에서의 실제 활용 & 작동 시나리오**:
  * **적용 위치**: `post_comments.ai_review_token`, `ai_review_lease_until`, PostgreSQL의 `FOR UPDATE SKIP LOCKED`.
  * **작동 흐름**: 학생이 댓글을 달면 댓글은 `pending` 상태로 큐에 들어갑니다. AI 워커가 댓글을 가져갈 때 20초 유효기간의 임대 토큰을 발급받아 잠급니다. 20초 안에 성공하면 `approved`로 바뀌고, 만약 AI 서버 장애로 멈추면 20초 뒤 락이 풀려 다른 워커가 안전하게 재시도합니다.
* 🎯 **왜 썼는가? (도입 효과)**:
  * 동일한 댓글 하나를 두고 AI 호출이 2번 이상 중복 발생해 돈이 낭비되거나 무한 대기에 빠지는 현상을 완전히 방지합니다.

### 6.3 룰 기반 사전 필터링 (Rule-based Pre-filtering / 비용 0원 방어선)
* 📖 **전문용어 개념 해설**:
  * 모든 텍스트를 무조건 비싼 유료 AI(OpenAI)로 보내 검사하지 않고, 명백한 욕설, 비하어, 초성 욕설은 **서버 내부의 정규표현식 금칙어 규칙(Rule)으로 먼저 0.0001초 만에 무료로 걸러내는 비용 절감 아키텍처**입니다.
* 💡 **학교·일상 비유**:
  * 공항 입구의 **자동 금속 탐지기 문**입니다. 가방에 명백히 칼이나 위험물이 들어있는 승객은 비싼 감정사를 부를 필요도 없이 입구 금속 탐지기 삐- 소리와 함께 즉시 돌려보내는 것과 같습니다.
* 🏗️ **내 앱(끄적끄적 아지트)에서의 실제 활용 & 작동 시나리오**:
  * **적용 위치**: [vibe-ai/index.ts](file:///Users/seunghyeonmaegmini/vibe_agit/supabase/functions/vibe-ai/index.ts#L73-L108)의 `INAPPROPRIATE_WORDS`
  * **작동 흐름**:
    학생이 댓글에 욕설이나 `ㅅㅂ`, `ㅂㅅ` 같은 초성을 입력하면, OpenAI API를 호출하기 전에 엣지 함수 내부 정규식이 먼저 감지합니다. API 호출을 즉시 취소하고(비용 0원 발생), 학생에게 다정한 교육적 수정 안내를 반환합니다.
* 🎯 **왜 썼는가? (도입 효과)**:
  * 전체 부적절 댓글 검사 비용의 **70% 이상을 0원으로 절감**하여 한 달 AI 사용료를 몇천 원 수준으로 방어합니다.

### 6.4 결정론적 AI (Deterministic AI) & 글자수 슬라이싱 (Token Slicing)
* 📖 **전문용어 개념 해설**:
  * AI가 시인처럼 매번 다른 감성적인 답변을 길게 늘어놓지 않도록, `temperature: 0` 설정으로 **동일한 입력에는 항상 100% 동일한 판정 결과를 내게 하고, 불필요한 토큰 낭비를 막기 위해 입력 텍스트를 엄격히 자르는(Slicing) 기법**입니다.
* 💡 **학교·일상 비유**:
  * 수능 채점관에게 "너의 주관적인 감정으로 점수를 주지 말고, **채점 기준표에 따라 O, X 객관식으로 딱 떨어지게 채점하라**"고 엄격한 지침을 주는 것과 같습니다.
* 🏗️ **내 앱(끄적끄적 아지트)에서의 실제 활용 & 작동 시나리오**:
  * **적용 위치**: `vibe-ai`의 `temperature: 0`, `maxOutputTokens: 100`, `content.slice(0, 200)`
  * **작동 흐름**: 학생이 아무리 긴 텍스트를 넣어도 AI에게는 앞 200자만 전달되며, AI는 오직 `{"safe": true, "reason": "..."}` 형식의 최소 글자 JSON으로만 응답합니다.
* 🎯 **왜 썼는가? (도입 효과)**:
  * AI 응답 대기 시간이 5초에서 0.5초로 줄어들고 토큰 요금이 90% 이상 절약됩니다.

## 8. 바이브 코딩 & 설계 원칙 (Vibe Coding Principles & Methodology)

AI 페어 프로그래밍으로 빠르게 개발하면서도 코드가 누더기가 되지 않고 단단한 엔터프라이즈급 안정성을 유지하는 **끄적끄적 아지트의 5대 코딩 철학**입니다.

### 8.1 단일 진실 공급원 (SSOT: Single Source of Truth)
* 📖 **개념**: 동일한 데이터나 비즈니스 규칙(예: 작가 레벨 점수표, 댓글 금칙어 목록, 성취기준 코드)을 여러 파일에 복사-붙여넣기 하지 않고, **오직 단 하나의 원본 파일에만 정의한 뒤 다른 모든 곳에서 이를 import하여 참조하는 원칙**입니다.
* 💡 **비유**: 학교의 공식 표준시계입니다. 교실마다 시계를 제각각 맞춰두면 종 칠 때 혼란이 생기므로, 본관 중앙 시계 하나만 보고 모든 교실이 시간을 맞추는 것과 같습니다.
* 🏗️ **적용**: `src/constants/writerLevels.js`, `src/constants/teacherGuides.js`.

### 8.2 멱등성 (Idempotency) & Event Key
* 📖 **개념**: **동일한 요청을 한 번 실행하든, 네트워크 렉으로 열 번을 연속으로 실행하든 결과가 항상 동일하게 유지되는 성질**입니다.
* 💡 **비유**: 엘리베이터의 5층 버튼입니다. 5층 버튼을 한 번 누르든, 조급해서 10번을 연타하든 엘리베이터는 5층에 딱 한 번만 멈춥니다.
* 🏗️ **적용**: 모든 글 제출 및 포인트 적립 RPC는 클라이언트가 생성한 고유 `event_key`를 인자로 받습니다. 학생이 네트워크 렉으로 '제출' 버튼을 따닥- 2번 연타해도, DB는 동일한 `event_key`를 감지하여 글을 1편만 등록하고 포인트도 1번만 지급합니다.

### 8.3 무파괴 모듈화 (Graceful Degradation & Default OFF)
* 📖 **개념**: 새로운 기능(신규 게임, 신규 도구)을 추가할 때 기존 코어 시스템을 건드리지 않고 모듈로 분리하며, **기본 상태는 꺼짐(OFF)으로 두어 선생님이 명시적으로 켰을 때만 작동하게 함으로써 기존 시스템의 안전을 영구히 보장하는 원칙**입니다.
* 🏗️ **적용**: `classes.enabled_modules` JSONB 컬럼과 `src/modules/registry.js`. 신규 모듈에 심각한 버그가 생겨도 해당 모듈만 OFF하면 국어 글쓰기 수업은 1초의 중단도 없이 평화롭게 지속됩니다.

### 8.4 로컬 우선 반복 & 원샷 마감 (Local-First Iteration & Single-Shot Release)
* 📖 **개념**: 코드를 고칠 때마다 매번 원격 서버에 배포하여 테스트하지 않고, **로컬 개발 환경과 내장 단위 테스트에서 100% 완벽하게 검증한 뒤, 사용자가 '배포'를 승인했을 때 단 한 번만 원샷으로 안전하게 마감 배포하는 작업 절차**입니다.
* 🏗️ **적용**: [AGENTS.md](file:///Users/seunghyeonmaegmini/vibe_agit/AGENTS.md)의 반복 수정·마감 규칙. 로컬에서 `npm test`와 `npm run checklist`를 통과한 검증된 코드만 `origin/main`으로 푸시되어 Docker 컨테이너로 빌드됩니다.

### 8.5 심층 방어 (Defense in Depth / 다중 보안 레이어)
* 📖 **개념**: 단 하나의 보안 장치에만 의존하지 않고, **프론트엔드 유효성 검사 → API 게이트웨이 토큰 검증 → 엣지 함수 사전 필터 → DB RPC 비즈니스 검증 → DB RLS 행 보안**에 이르는 다중 방어선을 겹겹이 쌓아 올리는 보안 설계입니다.
* 💡 **비유**: 성을 지킬 때 해자(물웅덩이)를 파고, 외성을 쌓고, 내성을 쌓고, 마지막에 금고 문에 자물쇠를 거는 5중 방어선과 같습니다. 하나가 뚫려도 다음 방어선이 시스템을 안전하게 지킵니다.

## 9. 실제 구현된 기능 모듈 해설 (src/modules/ 실전 분석)

`src/modules/` 디렉토리에 구축된 핵심 기능 모듈들이 실제로 어떻게 작동하는지 분석한 내용입니다.

### 9.1 `class-agit` (우리반 글 2.5D 전시관 & 학급 문집 출판)
* 📁 **위치**: `src/modules/class-agit/`
  * `gallery`: 2.5D 입체 메타버스 갤러리 뷰. 학생들의 작품이 가상 미술관 액자에 걸려 전시되며, 클릭 시 감상 모달이 열립니다.
  * `anthology`: 학기 말 실제 인쇄용 A4 PDF 문집 제작 엔진. 표지 디자인, 목차, 학생별 글 배치를 위지윅 형태로 편집합니다.
  * `selection`: 문집에 실을 대표 작품을 교사와 학생이 상호 추천/선정하는 워크스페이스.
  * `api`: 대용량 작품 조회를 위한 전용 RPC 및 정적 캐시 레이어.

### 9.2 `community` (친구 아지트 & 이웃 아지트)
* 📁 **위치**: `src/modules/community/`
  * `friends-hideout`: 우리 반 친구들의 최신 글을 모아보는 학급 전용 소셜 피드. 공감 스티커와 따뜻한 댓글을 주고받습니다.
  * `neighbor-agit`: 다른 학교나 옆 반과 코드로 안전하게 연결되는 연합 아지트. 선생님의 승인을 거친 우수 작품만 선별 교류합니다.

### 9.3 `game` (학습 게이미피케이션 엔진)
* 📁 **위치**: `src/modules/game/`
  * `dragon`: 글을 성실히 쓸 때마다 경험치를 얻어 알에서 깨어나 5단계로 진화하는 나만의 학습 파트너 드래곤 육성 모듈.
  * `vocab-tower`: 초등 국어 필수 어휘를 계단식 퀴즈로 정복하며 탑을 쌓아 올리는 어휘력 증진 게임.
  * `legacy`: 과거 단일형 드래곤/어휘의 탑 운영 호환성을 보장하고 안전한 분할 이전을 지원하는 레거시 호환 브리지.

### 9.4 `tool` (전체 화면 학급 활동 도구함)
* 📁 **위치**: `src/modules/tool/`
  * `class-board`: 교실 전자칠판에 띄우는 스마트 대시보드 (아날로그/디지털 시계, 수업 집중 타이머, 오늘의 중요 공지).
  * `class-notice`: 선생님이 등록하는 학급 알림장 및 템플릿 공지 관리.
  * `class-timetable`: 학급 시간표 관리. 학년을 고르면 2022 개정 교육과정 과목이 단추로 배열되고, 기초 시간표를 한 번 입력해 두면 그 주에만 바뀐 수업을 따로 저장해 기록으로 남긴다(우리 반 스크린 `시간표` 위젯이 오늘·내일·이번 주를 보여 줌).
  * `classroom-arrangement`: 짝꿍 바꾸기 날 유용한 학생 자리 배치 랜덤/지정 시뮬레이터.
  * `meal-board`: 나이스(NEIS) 교육행정 정보 시스템과 연동되어 오늘의 영양 만점 급식 식단표와 칼로리를 보여주는 급식판.

### 9.5 `writing` (풍부한 글쓰기 파이프라인 & 발자국)
* 📁 **위치**: `src/modules/writing/`
  * `diary`: 그림일기 및 자유 주제 일기 작성 파이프라인.
  * `reading-log`: 읽은 책의 표지 검색, 독서 감상문 작성, 학급 독서마라톤 누적 페이지 달리기 연동.
  * `spelling-learning`: 틀리기 쉬운 맞춤법과 띄어쓰기를 스스로 교정해보는 자기주도 맞춤법 학습터.
  * `idea-market`: 글감이 떠오르지 않을 때 친구들의 기발한 생각과 질문을 사고파는 생각 시장.
  * `writing-footprint`: 한 학기 동안 학생이 작성한 글자 수, 제출 편수, 어휘 성장을 시각화한 포트폴리오(성장 발자국).
  * `evaluation`: 2022 개정 초등 국어과 성취기준(3~4학년군 / 5~6학년군)에 맞춘 학생 맞춤형 국어 평어 자동 생성 지원.
  * `drafts`: 네트워크가 끊기거나 실수로 창을 닫아도 소중한 글이 날아가지 않도록 보호하는 로컬/원격 임시저장 및 이어쓰기.
  * `editor-settings`: 최소 글자 수, 줄바꿈 허용, 맞춤법 사전 온오프 등 교실 수업에 맞춘 에디터 환경 설정.
  * `engagement`: 학급 친구들의 글쓰기 참여율, 조회수, 공감 지표를 안전하게 산출하는 참여도 분석기.
  * `lab-activities`: 연구소(`/lab`)에서 기획된 고급 글쓰기 활동과 연계 템플릿을 아지트로 가져오는 브리지.
  * `mission-card-layout`: 태블릿과 PC 화면 비율에 맞추어 글쓰기 과제 카드를 가장 보기 좋게 배치하는 카드 그리드 레이아웃.
  * `mission-form`: 교사가 마감일, 필수 질문, 첨부 파일, 보상 포인트를 설정하여 새 글쓰기 과제를 발행하는 출제 폼.
  * `mission-types`: 편지글, 주장하는 글, 관찰 보고서, 시 등 다양한 글쓰기 갈래별 특화 입력 템플릿 명세.
  * `mission-workspace`: 학생이 선생님의 안내와 참고 자료를 보며 집중해서 글을 작성하는 풀스크린 작업 공간.
  * `policy`: 글쓰기 완료 인정 최소 분량, 문단 수, 기본 포인트 및 글자수 비례 반복 보너스 정책 규칙.
  * `presentation`: 교실 전자칠판 앞에서 학급 전체 학생의 글을 한 편씩 넘겨보며 함께 감상하고 토론하는 발표 모드.
  * `reactions`: 친구 글에 남길 수 있는 따뜻한 칭찬, 응원, 공감 스티커와 감상 반응 인터랙션 모음.
  * `references`: 글을 쓸 때 막히지 않도록 선생님 안내글, 핵심 질문, 예시 문장을 옆에 띄워두고 보는 참고 자료 패널.
  * `submission-board`: 학급 학생 중 누가 과제를 냈고 누가 아직 안 냈는지 한눈에 파악하고 피드백을 주는 제출 현황 보드.
  * `title-status`: 기록가(글쓰기), 독서가(독서록), 어휘가(어휘탑) 등 학기 시즌별 칭호 획득 상태와 진척도 관리.
  * `tools`: 글자수 세기, 맞춤법 찾아보기, 사전 검색 등 글을 쓰며 언제든 꺼내 쓸 수 있는 글쓰기 보조 도구함.

### 9.6 기타 지원 모듈
* `points`: 모든 모듈의 포인트 적립/차감을 원자적으로 중계하는 금융 장부 코어 모듈.
* `card-layout`: 반응형 화면 크기에 맞춰 글 카드를 최적의 그리드로 정렬해 주는 공용 카드 레이아웃.
* `dashboard`: 교사와 학생 대시보드의 위젯 배치 관리.
* `feedback`: 교사의 정밀 피드백(칭찬, 다듬기, 격려) 카테고리 관리.
* `notifications`: 새 댓글, 과제 검토 완료, 칭호 획득 실시간 알림 센터.
