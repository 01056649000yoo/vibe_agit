### 1,000명 동시 사용 점검 (2026-08-08 코드·운영 통계 재진단)

현재 맥미니(M4 10코어·16GB), PostgREST 풀 25, PostgreSQL 연결 한도 100이다. 500 웹소켓 실측은 통과했지만
Realtime `max_concurrent_users=600`이라 **1,000명이 학생 화면의 구독을 모두 열면 400명은 실시간 연결을 보장할 수 없다.**
DB 크기보다 학생 홈의 중복 조회·짧은 폴링·첫 방문 정적 파일 전송이 먼저 병목이 될 가능성이 높다.

- [x] **P0 학생 홈 부트스트랩 RPC**: 로그인 직후 조건에 따라 약 18~21회 발생하는 요청을 코어 상태 1회 +
      열린 선택 모듈 조회만 남긴다. 포인트·펫·학급 모듈/편집 설정·할 일·반려 수·일기/독서록 오늘 상태·새 소식 수를
      `get_student_home_bootstrap_v1()` 한 응답으로 묶고, 모듈의 상세 데이터는 실제로 열 때만 전용 RPC로 읽는다.
- [x] **P0 lightweight 조회 오류 제거**: 학생 홈에서는 해당 훅 자체를 제거하고 bootstrap의 학급 설정을 재사용해
      설정 1행조차 별도 조회하지 않는다. 전체 활동 집계는 실제 아지트 화면을 열 때만 기존 전체 훅이 담당한다.
- [x] **P0 짧은 폴링 통합**: 모듈 설정 10초(1,000명=100회/초), 편집 설정 30초(33회/초), 학생 인증 120초
      (8회/초)를 각 기능 타이머로 따로 돌리지 않는다. 로그인/화면 복귀/교사 변경 응답을 공용 갱신기로 합치고,
      수업 중 상시 폴링은 최소 3~5분 + 무작위 지연으로 낮춘다. 2026-08-25 이후 과제 글 반려·승인 두 신호만
      12초 코어 폴링 예외이며, 전체 목록·설정·인증 폴링은 다시 늘리지 않는다.
- [x] **P0 Realtime 1,000명 정책 결정**: 학생 상시 Realtime을 모두 제거했다. 승인·회수·포인트·다시쓰기 결과는
      단일 이벤트 원장에 기록하고 공용 홈 bootstrap이 최신 미확인 1건과 개수만 읽는다. 로그인·새로고침·홈 복귀와
      4~6분 분산 동기화로 수렴하며, 실제 목록은 학생이 활동 알림 창을 열 때만 최대 50건을 읽는다.
      2026-08-25부터 과제 글 반려·승인만 12초 최소 신호 폴링으로 먼저 알리고 나머지 흐름은 유지한다.
- [x] **P0 접힌 카드 지연 조회**: 독서마라톤은 접힌 홈 카드에서도 전체 순위·최근 기록까지 읽는다. 홈에는 목표·내 거리만
      주는 compact RPC를 쓰고, 펼칠 때 전체 순위를 조회한다. 일기/독서록 상태도 부트스트랩 결과를 재사용한다.
- [x] **P1 글 제출 원자화**: 현재 과제 제출은 기존 글 조회→upsert→장르별 후처리/보상의 2~3요청이다.
      `submit_assignment_post_v1()` 같은 기능 전용 RPC가 글 저장·원본 보존·미션 버전 확인·후속 보상을 한 트랜잭션으로 끝낸다.

- [x] **P1 중복 인덱스 정리(운영 적용 완료)**: 운영 DB에 동일 키 인덱스 14묶음이 있다. 실제 실행 계획과 제약 인덱스를 확인한 뒤

### 적용 후 현재 부하 실측 (2026-08-08)

- 학생 복구 로그인은 `get_student_by_auth`+홈 bootstrap **2회**, 새 코드 로그인은 익명 인증·코드 바인딩·토큰 갱신·

- 학생은 글쓰기 진입 2회, 변경이 있을 때만 2분마다 DB 초안 1회, 최종 제출 RPC 1회+홈 갱신 1회다.
