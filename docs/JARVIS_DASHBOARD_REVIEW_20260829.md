# 자비스 개인 대시보드 점검·개편 제안 (2026-08-29)

## 결론

자비스는 현재 **개인용 학급 운영 기록 허브**로서 기능 범위가 잘 잡혀 있고, Docker 운영 상태도
가볍고 안정적이다. 지금 필요한 것은 기능의 전면 재작성보다 다음 네 가지다.

1. Docker 이관 전에 쓰던 호스트 서버를 정리해 **운영본을 하나로 통일**한다.
2. 첫 화면을 누적 건수·개발 설명이 아니라 **오늘 할 일과 주의가 필요한 항목** 중심으로 바꾼다.
3. 완료 업무·오래 갱신되지 않은 프로젝트를 접어 **현재 행동할 항목만 먼저 보이게** 한다.
4. 인증·검사·동기화 주기를 보완해 이후 업데이트를 안전하게 반복할 기반을 만든다.

대규모 사용자 서비스용 복잡한 Realtime·마이크로서비스·분산 캐시는 필요하지 않다. 혼자 쓰는 앱답게
빠른 기록, 한눈에 보는 우선순위, 단순한 복구가 더 중요하다.

## 확인 범위와 현재 상태

- 외부 접속은 Cloudflare Tunnel `localhost:8001` → `jarvis-caddy` → Docker `frontend:3000` 경로다.
- Docker `jarvis-frontend`와 `jarvis-caddy`는 정상 실행 중이며 점검 시 메모리는 각각 약 54MB·20MB,
  CPU는 사실상 유휴 상태였다.
- 공개 루트는 비로그인 상태에서 로그인으로 307 이동하고, Docker 로그인 화면은 로컬에서 200을 반환했다.
- 최근 48시간 Docker 프런트 로그에 애플리케이션 오류·경고가 없었다.
- 운영 의존성은 Next.js 15.5.24·React 19.2.5이며 `npm audit --omit=dev`는 0건이다.
- TypeScript 검사는 `npx tsc --noEmit --incremental false`로 통과했다.
- 현재 데이터 규모는 업무 161, 일정 164, 학급기록 62, 보안저장소 39, 프로젝트 8,
  프로젝트 기록 49, 메모 11, 첨부 22건이다. 데이터량 자체는 매우 작다.
- 업무는 완료 158, 진행예정 2, 진행중 1건이다. 프로젝트 8개는 모두 `진행중`으로 남아 있다.
- 연결 가능한 인증 브라우저가 없어 실제 화면을 클릭하는 눈검사는 하지 못했다. 반응형 CSS·컴포넌트·
  공개/로컬 HTTP 응답·운영 로그를 기준으로 분석했다.

## 잘 되어 있는 부분

- 로그인 허용 이메일을 제한하고, DB 읽기·쓰기와 민감 자료 처리를 서버에 모아 두었다.
- 학급기록·평가·보안저장소는 보조 PIN 잠금이 있고, 첨부 다운로드도 서버에서 소유 경로를 확인한다.
- 컨테이너는 비root, 읽기 전용 파일시스템, capability 제거, `no-new-privileges`가 적용돼 있다.
- CSP·HSTS·frame 차단·nosniff 등 기본 응답 보안 헤더가 적용돼 있다.
- Markdown 원본 → DB → Google Tasks/Calendar 동기화 구조가 이미 동작하며, 변경 범위별 캐시 무효화도 있다.
- 데스크톱 사이드바가 좁은 화면에서 가로 스크롤형 헤더로 바뀌고, 표 일부는 모바일 카드로 전환된다.

## 우선순위별 개선안

### P0 — 기능 업데이트 전에 먼저

#### 1. 운영 서버를 Docker 하나로 통일

외부 Tunnel은 새 Docker를 쓰지만 `com.jarvis.frontend` LaunchAgent가 예전 Next 서버를 3003에서 계속
실행하고 있다. 호스트 Caddy의 `app` 주소도 아직 3003을 가리킨다. 따라서 현재는 새 Docker와 구 호스트
서버가 동시에 200을 반환한다. 어느 경로로 접속했는지에 따라 서로 다른 빌드가 보일 수 있고, 업데이트·
장애 대응 때 기준점이 갈린다.

- 3003 직접 소비자가 없는지 마지막 확인
- 호스트 Caddy의 자비스 경로를 Docker 3004로 맞추거나 중복 경로 자체를 제거
- `com.jarvis.frontend` LaunchAgent 중지·비활성 보존
- 캐시 무효화 주소를 `127.0.0.1:3004` 하나로 축소
- 현재 매번 남는 공개 `/api/revalidate` 403 호출 제거

#### 2. Git 복구 기준과 개인정보 제외 범위 확정

현재 저장소는 프런트 코드·Compose만 한 번 커밋돼 있고 원격이 없다. 반면 실제 운영을 담당하는 `scripts/`
등은 untracked이며, 개인 Markdown 자료 폴더도 대량으로 untracked다. 지금 상태에서 실수로 `git add -A`를
하면 개인 자료를 섞을 수 있고, 동기화 스크립트 변경은 Git으로 되돌릴 수 없다.

- private 원격 저장소 연결
- 개인 데이터 폴더는 `.gitignore`에 명시적으로 제외
- 비밀이 없는 운영 스크립트·LaunchAgent 템플릿·배포 문서는 선별해 버전 관리
- 배포 직전 태그 또는 작은 커밋으로 즉시 롤백 가능한 기준점 생성

#### 3. 모든 Server Action의 인증 규칙 통일

Middleware는 Next Server Action POST를 로그인 리다이렉트에서 제외하므로 각 Action 자체 인증이 필수다.
일반 수정·삭제 Action은 대부분 `requireSignedIn()`을 호출하지만, 평가·학급기록·보안저장소 잠금 해제/잠금과
첨부 PIN 확인 Action에는 같은 검사가 없다. 현재 단일 허용 계정 구조 때문에 바로 자료가 노출되는 형태는
아니지만, 규칙이 둘로 갈려 있어 이후 기능 추가 때 사고가 나기 쉽다.

- 모든 unlock/lock/verify Action 첫 단계에서 로그인 확인
- 첨부 잠금 쿠키의 `secure: false`를 공용 `secureCookie()` 규칙으로 통일
- 값이 단순 `true`인 잠금 쿠키를 만료 시간이 있는 서버 서명 토큰으로 변경
- PIN 실패 횟수 제한과 짧은 지연 추가
- “Server Action은 반드시 자체 인증”을 자동 검사로 고정

#### 4. 업데이트를 막아 줄 검사 추가

현재 별도 테스트 파일이 없고 `npm run lint`는 ESLint 설정 질문을 띄우므로 자동 배포 검사로 쓸 수 없다.

- ESLint CLI 설정 후 무인 `npm run lint`
- 인증 없는 Action, 허용되지 않은 파일 경로, 잠금 첨부 다운로드를 검사하는 단위 테스트
- 로그인 이동 → 로그인 화면 → 인증 후 홈 → 업무 상태 변경의 최소 스모크 테스트
- `typecheck + lint + test + build`를 한 명령 또는 CI로 묶기

### P1 — 체감이 가장 큰 화면 개편

#### 1. 홈을 `오늘` 중심으로 재구성

현재 첫 화면의 카드 4개는 누적 업무·일정·학급기록·보안저장소 건수를 보여 주고, 아래에는 전체 업무와
개발자용 `Architecture`·`Adaptability` 설명이 있다. 개인 운영 화면에서는 다음 구성이 더 유용하다.

- **오늘**: 오늘 수업, 오늘 일정, 기한이 지난/임박한 미완료 업무
- **이번 주**: 다음 7일 일정과 진행예정 업무
- **주의 필요**: 30일 이상 업데이트 없는 진행중 프로젝트, 동기화 실패, 백업 경고
- **최근 기록**: 최근 프로젝트 업데이트·메모·학급기록의 제목과 시각
- 상단 빠른 등록: `업무`, `메모`, `일정` 세 가지

개발 구조 설명 카드 두 개는 홈에서 제거하고 README 또는 운영 문서로 옮긴다. 민감 기록은 홈에서 내용이
아니라 건수·잠금 상태만 보여 준다.

#### 2. 완료 업무 158건을 기본 화면에서 접기

홈과 업무 화면은 현재 161건을 모두 카드로 렌더링하며 그중 158건이 완료다. 완료 열은 기본 접힘으로 두고
최근 완료 10건만 펼쳐 보거나, `완료 보기` 필터와 월별 보관함을 제공한다. 상단 숫자도 `전체 161`보다
`진행중 1 / 예정 2 / 지연 0`처럼 행동 가능한 수치가 우선이어야 한다.

#### 3. 프로젝트 건강 상태 추가

8개 프로젝트가 모두 `진행중`이라 상태 자체가 구분 역할을 못 한다.

- 카드에 마지막 업데이트 날짜와 경과 일수 표시
- 30일 이상 갱신되지 않으면 `점검 필요`
- 홈에서 바로 한 줄 업데이트 추가
- 완료·보류 전환을 빠르게 하고, 종료된 프로젝트는 기본 목록에서 접기

#### 4. 첨부파일과 검색 동선 보완

`/attachments` 전체 보기 화면은 있지만 기본 내비게이션에는 없고, 모바일에서는 사이드바 첨부 패널이
숨겨진다. 내비게이션에 `첨부파일`을 추가하고, 다음 단계로 업무·프로젝트·메모·일정을 한 번에 찾는 통합
검색을 둔다. 학급기록·보안저장소 검색 결과는 해당 섹션이 잠금 해제된 동안만 노출한다.

### P2 — 운영 부하와 장기 유지보수

#### 1. 4초 자동 새로고침 완화

업무·프로젝트·메모·시간표·학급기록·평가·보안저장소 화면은 활성 상태에서 4초마다 `router.refresh()`를
호출한다. 한 화면을 한 시간 열어 두면 약 900회 요청이다. 파일 watcher가 이미 변경 시 캐시 태그를
무효화하므로 다음처럼 줄이는 편이 맞다.

- 창 포커스 복귀 때 즉시 새로고침
- 평상시 30~60초 간격 또는 수동 새로고침
- 저장 동작 직후에는 지금처럼 즉시 갱신
- 동기화가 정말 즉시 보여야 할 때만 가벼운 변경 버전 확인 사용

#### 2. Google Tasks 풀링과 로그 축소

현재 LaunchAgent는 60초마다 Google Tasks 165건을 전부 비교하며, 최근 로그에서는 매회 변경 0건이었다.
하루 약 1,440회 실행·약 23만 건 비교가 된다.

- 기본 주기를 5분으로 늘리고 앱 포커스/수동 동기화 제공
- 가능하면 최근 갱신 시각 기준 증분 조회
- 변경 0건은 매회 파일 로그에 남기지 않고 시간대별 요약
- 재검증 URL은 Docker 한 개만 호출해 성공 1줄만 기록

#### 3. 목록 상한과 보관 정책

현재 주요 DB 조회는 모든 행을 읽는다. 지금 데이터량에서는 빠르지만 완료 업무·지난 일정·기록이 계속 쌓이면
홈 렌더링과 직렬화가 불필요하게 커진다.

- 홈은 오늘/7일/최근 N건 전용 조회
- 완료 업무와 지난 일정은 페이지 또는 연·월 필터
- 프로젝트 업데이트는 프로젝트별 최근 N건과 전체 기록을 분리
- 전체 첨부·민감 기록도 페이지 상한 적용

#### 4. 조용한 상태 표시

별도 복잡한 관제 화면 대신 사이드바 하단에 다음만 작은 상태로 보여 주면 충분하다.

- 마지막 Markdown→DB 동기화 시각
- Google Tasks/Calendar 마지막 성공 시각
- 오늘 백업 3/3 상태(아지트 관리자 원장의 요약만 읽기)
- 배포 버전 또는 커밋 짧은 해시

정상이면 한 줄 초록 상태만 보이고, 실패했을 때만 상세를 펼친다.

## 권장 실행 순서

1. **운영 기준 정리** — private Git·개인 자료 ignore·운영 스크립트 선별 추적 → 3003 구 서버 제거 →
   재검증 주소 하나로 통일
2. **안전망** — Server Action 인증 통일·서명 잠금 쿠키·PIN 제한 → ESLint/테스트/빌드 게이트
3. **홈 개편** — 오늘/이번 주/주의/최근 기록 → 완료 업무 접기 → 프로젝트 노후 표시
4. **동선 개선** — 빠른 등록·첨부 내비게이션·통합 검색
5. **운영 다듬기** — 4초 새로고침·1분 Google Tasks 풀링 축소 → 목록 페이지·상태 표시

## 1차 업데이트 완료 기준

- 외부·로컬 어느 경로에서도 같은 Docker 빌드만 응답한다.
- 자비스 코드와 비밀 없는 운영 스크립트를 private 원격에서 복구할 수 있고, 개인 자료는 Git 대상이 아니다.
- 인증 없이 모든 Server Action이 실패하며 잠금 쿠키를 임의로 만들어도 민감 자료를 열 수 없다.
- 홈 첫 화면에서 오늘 일정, 미완료 3건, 오래된 진행 프로젝트를 스크롤 최소화 상태로 확인할 수 있다.
- 완료 158건 때문에 초기 화면이 길어지지 않는다.
- `lint`, 타입 검사, 테스트, 빌드가 질문 없이 한 번에 통과한다.
- 자동 갱신·Google Tasks 풀링을 줄여도 파일 수정·업무 완료가 정해진 시간 안에 화면과 DB에 반영된다.
