# 우리반 아지트 작품 찾기·순서 정리 개편 계획

상태: **2026-09-05 구현·회귀 검증 완료, 사용자 요청에 따라 운영 배포.**
개편 전 기준은 운영 배포된 `e595ed3`이다. 제품 범위 정본은 [CLASS_AGIT_PLAN.md](../CLASS_AGIT_PLAN.md).

## 1. 현재 불편의 원인

- 독립된 미션 목록이 없다. `get_class_agit_candidates_v1`은 최신 글 20편부터 보여 주며 검색은 제목·학생 이름뿐이다.
  미션 이름은 글 아래 설명으로만 나오고, 미션 ID 필터·미션 검색·이전 페이지 이동은 없다.
- `TeacherEntry.jsx`의 다음 후보는 현재 페이지를 교체한다. 미션/학생별로 찾던 위치를 복원하는 구조도 없다.
- 넓은 관리 화면의 기본 열 비율은 후보 약 35%·선택 목록 약 65%다. 선택 행의 제목과 조작 줄이 분리되어
  한 작품에 큰 높이를 쓰고, 매 행에 이동·전문·철회·빼기 버튼을 반복한다. 좁아지면 두 영역이 세로로 쌓인다.
- 한 편씩 전문 창을 열고 수록을 확인해야 담을 수 있다. 여러 미션에서 여러 편을 모으는 작업이 반복된다.
- 후보 RPC는 원문 표시/해시 구성 함수를 목록에서도 호출한다. 미션별 탐색을 추가할 때 이 경로를 그대로
  학급 전체 미션에 반복하면 안 된다.
- `getCandidates`는 전시 편집과 문집의 `anthology/SourcePicker.jsx`가 함께 쓴다. 한 소비자만 바꾸지 않는다.

## 2. 화면 구조: 2단계 안에서 두 작업을 전환

기존 **1 기본 설정 → 2 작품 선택·순서 → 3 미리보기 → 4 외부 읽기 공유**는 유지한다.
2단계에 `작품 찾기`와 `담은 작품 정리 · 24/120` 두 보기를 둔다. 처음에는 작품 찾기를 연다.
선택 작품의 큰 패널을 상시 띄우지 않고, 찾을 때는 미션과 글 목록에 공간을 집중한다.

| 영역 | 작품 찾기 | 담은 작품 정리 |
|---|---|---|
| 위쪽 | 미션명 찾기, 글 제목·학생 검색, 전체 미션/현재 미션 검색 범위 | 총 편수·작가 수·전시실 수, 정렬/이동/빼기 도구 |
| 본문 왼쪽 | 학급 미션 목록, 폭 약 220~240px | 별도 후보 패널 없음 |
| 본문 나머지 | 선택 미션의 넓은 글 목록, 체크박스로 여러 편 선택 | 담은 작품을 간결한 행으로 표시, 방 경계 표시 |
| 아래쪽 | 선택 N편 · 전시에 담음 M/120편 · 선택 작품 담기 · 담은 작품 정리 | 작품 더 찾기 · 초안 저장 · 미리보기로 |

미션명 검색과 글 검색은 대상이 명확한 별도 입력으로 표시한다. 필터·조회 위치·스크롤·선택은 두 보기를
왕복해도 유지한다. 미리보기로 가는 동작은 지금처럼 초안을 저장하고, 실패하면 편집을 그대로 남긴다.
초안에 담기·순서 변경으로 이미 발행한 전시본을 바꾸지 않는다.

## 3. 내 학급 미션을 빠짐없이 찾기

- 글 페이지에서 미션 이름을 추출하지 않고 **현재 담당 학급의 실제 미션 목록**을 독립적으로 조회한다.
- 기본 범위는 `전체 미션`이며 보관 미션도 포함한다. `사용 중 / 보관함` 필터와 미션명 검색을 제공한다.
  최근순으로 시작하고 과거 미션까지 더 보거나 검색할 수 있다. 제출 글이 0편인 미션도 숨기지 않는다.
- 미션 행은 `미션명 / 장르·등록일 / 검토할 글 N편 / 이 전시에 담은 M편`을 표시한다.
  삭제된 미션은 새 후보로 복구하지 않는다.
- 아직 전시에 지원하지 않는 장르의 미션도 목록에는 나타낸다. `전시 지원 준비 중` 등 이유를 표시하고
  선택은 막는다. 이번 UI 개편이 보고서·회의록 등의 전시 렌더러 지원을 자동으로 확대하지는 않는다.
- 미션의 글 수는 학급 공개·제출·확인 등 기본 상태에 따른 **검토 대상 수**다. 최종 수록 가능 여부는
  담는 시점의 원문·형식·권한 검사로 정한다. 원문 전체를 재가공해서 모든 미션의 숫자를 만들지 않는다.
- 미션을 고르면 같은 화면 오른쪽에서 글이 바뀐다. 다른 메뉴로 이동하거나 미션 관리 화면에 들어가지 않는다.
- `전체 미션에서 글 찾기`는 서버가 전체 대상에서 검색한다. 이미 불러온 20/50편만 검색하는 방식은 쓰지 않는다.
- `아직 이 전시에 작품이 없는 학생` 필터를 제공하고, 학생별 수록 편수는 교사의 참여 점검에만 쓴다.

## 4. 여러 작품을 한 번에 담기

글 목록은 `체크 / 학생 / 작품 제목·짧은 미리보기 / 수록 상태 / 읽기`의 행 형태다.
미션 안에서는 기본 학생 이름순, 전체 검색에서는 최근 수정순이며 정렬 기준을 명시한다.
이미 담은 글은 `담음`으로 표시해 중복 선택을 막는다.

1. 미션에서 체크박스로 작품 여러 편을 고른다. `이 페이지 선택`은 현재 화면의 선택 가능한 작품에만 적용한다.
2. 다른 미션이나 다음 페이지를 열어도 선택은 유지한다. 선택 내역에서 미션별로 확인하거나 한 번에 해제할 수 있다.
3. `선택 작품 담기`를 누르면 선택 ID를 **한 묶음 요청**으로 검증하고 정상 작품은 초안 끝에 바로 담는다.
4. 수록할 수 없는 작품이 섞였을 때만 제외 사유와 `문제없는 N편만 담기`를 보여 준다.
5. 필요하면 목록의 `읽기`로 전문을 확인한다. 의사 확인 체크나 일괄 확인 화면은 두지 않는다.
6. 기존 작품 순서와 선택 순서를 보존한다. 담기는 초안 편집이며 저장·학급 공개·외부 발행은 별도로 실행한다.

한 번의 선택/검증은 최대 50편, 전시 전체는 120편이다. 남은 자리를 초과하면 자동으로 일부만 담지 않고
선택을 줄이도록 안내한다. 미션 전체에 50편이 넘으면 페이지를 나누어 담는다.
회수·권한 변경·형식 오류가 있는 항목은 이유를 표시한다. `문제없는 N편만 담기`도 교사가 명시적으로
고르는 동작이며 조용히 누락하지 않는다. 실패한 검증 뒤에는 기존 초안과 체크를 보존한다.

## 5. 담은 작품은 짧은 목록으로 정리

- 큰 카드와 모든 행의 반복 버튼을 없애고 `순번 / 제목 / 학생 / 미션 / 전시실` 중심으로 표시한다.
  PC 행 높이는 약 48~60px를 목표로 하고 제목은 최대 두 줄까지 읽히게 한다. 긴 제목 전체는 읽기에서 확인한다.
- 여러 행을 선택하면 공용 도구줄에서 `맨 앞 / 맨 뒤 / 지정 순번 / 초안에서 빼기`를 적용한다.
  그룹 안의 현재 순서는 보존하며 단일 작품도 같은 도구를 사용한다.
- `미션별로 모으기 / 학생 이름순 / 담은 순서`는 전체 순서를 바꾸는 명시적 작업이다.
  자동으로 수시 재정렬하지 않고, 미리 결과를 안내한 뒤 적용하며 저장 전 되돌리기를 제공한다.
- `3전시실 맨 앞으로`는 전체 배열의 해당 방 시작 위치로 옮기는 동작이다. 방마다 12편으로 다시 나누고
  나머지 작품의 상대 순서를 유지한다. 미션 하나가 반드시 전시실 하나라는 제약은 만들지 않는다.
- 행 제목을 누르면 읽기를 열고 이전/다음으로 이어 본다. `원글 변경됨 / 수록 철회됨`은 행에 표시한다.
- `초안에서 빼기`와 `현재 공개판에서도 수록 철회`는 구분한다. 공개판 철회는 상세 메뉴의 기존 확인 절차를
  유지하며 공용 빼기 버튼이 즉시 공개판을 철회하는 동작이 되어서는 안 된다.
- 드래그 이동은 후속 편의 기능으로 둔다. 1차는 지정 순번·여러 편 이동과 키보드로 120편 정리가 가능해야 한다.

## 6. 데이터·구현 범위

| 경로 | 계획 |
|---|---|
| 미션 목록 | 교사 전용 목록 RPC, 기본 50개·최대 100개 페이지, 미션 검색·보관 범위·등록시각/ID 커서 |
| 글 목록 | 미션 ID·학생/제목 검색·정렬·안정 커서, 기본 30편·최대 50편, 요약만 반환 |
| 선택 작품 검증 | 최대 50개 ID를 한 번 검증해 순서/원문 버전/내용/제외 사유 반환. 학급 범위 밖의 정보는 반환하지 않음 |
| 초안 저장·발행 | 기존 revision·원문 재검증·120편 상한 사용. 미리 본 결과를 신뢰해 검사를 건너뛰지 않음 |

- 실제 조회는 2단계의 작품 찾기를 처음 열 때 시작한다. 현재 `TeacherEntry`가 전시 열기/생성부터 후보를
  미리 읽는 경로도 옮긴다. 학생 홈·공개 감상에는 미션/후보 조회·폴링·Realtime을 추가하지 않는다.
- 미션과 글은 각 표의 `class_id`로 직접 제한하고 조인에도 학급 범위를 넣는다. 미션/정렬 기준에 맞는 인덱스와
  페이지 상한을 둔다. 전체 미션을 찾을 수 있다는 것은 본문을 한꺼번에 모두 내려받는다는 뜻이 아니다.
- 여러 미션의 숫자는 제한된 미션 페이지를 대상으로 가벼운 일괄 집계를 사용한다. 미션별 별도 요청과
  원문 표시/해시 함수 반복 호출을 금지한다. 원문/해시는 전문 열기·선택 묶음 검증·저장/발행 때만 필요하다.
- 목록 캐시는 `dataCache` + `classKey()`의 메모리 범위로 미션·검색·정렬·커서를 포함한다. 오류 시 오래된 목록으로
  수록을 확정하지 않는다. 선택/초안은 편집기 상태이며 브라우저 영구 저장소에 학생 글을 새로 보관하지 않는다.
- 늦은 응답은 요청 순번/취소로 무시하고, 미션별 커서·페이지 위치를 보관한다. 학급/전시 변경 시 선택을 격리한다.
- 새 목록 API는 모듈의 공용 작품 탐색 계층에 두고 전시와 문집 후보 창을 함께 점검한다. 문집 100편·별도 동의는
  유지한다. RPC 판을 교체하면 모든 소비자·DB 본문·정책·다른 앱을 확인하고 구형 함수는 같은 마이그레이션에서 정리한다.
- 컴포넌트는 미션 목록·글 목록·선택 요약줄·수록 불가 안내·순서 목록으로 나눈다. `ExhibitionWorkbench`는 단계와
  초안 상태를 연결한다. 공용 Button·입력 토큰·기존 GuideInfoButton/TeacherGuideButton 계약을 사용한다.

## 7. 좁은 화면

- 실제 편집기 가용 폭을 기준으로 배치한다. 화면이 좁으면 미션 목록을 `미션 선택` 버튼의 펼침 목록으로 바꾸고
  글 목록에 전체 폭을 준다. 오른쪽에 작은 세 번째 선택 패널을 만들지 않는다.
- 모바일은 학생·제목 두 줄 목록과 명확한 체크 영역, 하단 선택 요약/담기 버튼을 사용한다.
- 순서 정리는 여러 편 선택 후 위치 이동을 기본으로 한다. 작고 촘촘한 화살표나 드래그에만 의존하지 않는다.
- 미션·글·순서 목록은 각각 높이를 제한하고 스크롤 위치를 보존한다. 긴 목록 아래까지 화면 전체를 내려야 담기/이동 버튼을 찾는 일을 줄이며, 하단 도구줄은 문서 흐름에 두어 앱 내비게이션을 덮지 않는다.

## 8. 구현 순서와 완료 기준

1. **DB 없는 시안:** 미션 60개 이상·보관/빈/미지원 미션·합성 글 1,000편·선택 0/30/120편으로 새 2단계를 확인한다.
2. **조회 연결:** 실제 전체 미션 탐색·미션별 글/전체 검색·페이지 복원·지연 로딩·명시적 오류 상태를 구현한다.
3. **일괄 담기:** 선택 유지·한 묶음 검증·즉시 담기·중복/회수/원문 변경·상한과 실패 보존을 연결한다.
4. **순서 정리:** 간결한 목록·여러 편 지정 위치 이동·미션/학생 정렬·되돌리기·방당 12편·초안 저장을 연결한다.
5. **회귀 확인:** 전시/문집 API 소비자, 도움말, 기존 4단계·공개본 불변·30일/시범 학급 정책을 함께 검증한다.

- 최근 20편에 없는 오래된 미션도 검색/페이지로 찾을 수 있고 0편/보관/미지원 이유가 구분되어 보인다.
- 미션 3개에서 10편씩 모아도 체크가 사라지지 않으며, 30편 담기를 위해 전문 창 30개를 열 필요가 없다.
