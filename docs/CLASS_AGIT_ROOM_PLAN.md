# 주제별 전시실 구성 개편안

2026-09-05 요청을 반영한 **구현·배포 명세**다. 실제 교사·학생·외부 공유 코드와 새 마이그레이션을 검증했다. 사용자 배포 요청으로 SQL `61247`과 외부 Edge를 운영 반영했으며 main 푸시로 앱을 자동 배포한다.

## 1. 구성 원칙

- 전시 하나의 선정 작품은 최대 **120편**, 전시실 하나는 최대 **20편**이다.
- 20편은 채워야 하는 수가 아니다. 1편·13편·20편 등 주제에 맞는 수로 방을 마감할 수 있다.
- 방 개수는 작품 수에서 계산하지 않는다. **기존 최대 10실을 독립된 상한으로 유지**한다.
  20편씩 채우면 6실이지만, 12편씩 10실이나 여러 작은 주제방도 가능하다.
- 한 작품은 같은 전시 안에서 한 방에만 배정한다. 방 사이 이동은 복제가 아니다.
- 선정했지만 방을 정하지 않은 작품은 `미배정`으로 보관한다. 미배정도 120편에 포함한다.
- 초안에는 빈 방을 저장할 수 있고, 학생/외부 감상에서는 빈 방을 숨긴다. 발행 전에는 미배정 작품을
  방에 넣거나 전시 선정 목록에서 빼도록 안내해 의도치 않은 누락을 막는다.

| 전시실 | 주제 | 작품 | 같은 정원 디자인 안의 배경 예시 |
|---|---|---:|---|
| 1실 | 봄을 발견한 날 | 13/20편 | 연두 벽·초록 식물 |
| 2실 | 우리가 꿈꾸는 미래 | 20/20편 | 하늘빛 벽·밝은 햇살 |
| 3실 | 마음을 담은 시 | 8/20편 | 살구빛 벽·꽃 장식 |

이 예시는 총 41/120편이다. 1실의 남은 7자리를 채우지 않아도 2실을 사용할 수 있다.

## 2. 교사 화면

현재 네 단계는 유지하고 2단계를 **작품·전시실 구성**으로 정리한다.

1. 상단에 `전시 전체 41/120편`, 전시실 이름·편수가 보이는 가로 목록과 `+ 전시실`을 둔다.
   메뉴가 많으면 줄을 바꾸어 표시하고 좁은 화면에서도 이름과 편수를 고를 수 있다.
2. 방을 고르면 이름(주제), 짧은 소개, 배경 변형을 편집한다. `미배정`도 같은 위치에서 고른다.
3. `작품 찾기`에서는 기존 넓은 미션/검색 목록을 유지한다. 선택 결과를 현재 방에 바로 담을 수 있고,
   `2실 · 우리가 꿈꾸는 미래에 5편 담기`처럼 목적지를 버튼에 표시한다.
4. 미션 하나를 방 하나로 만드는 편의를 제공한다. 미션명은 방 제목의 초기값일 뿐이며,
   여러 미션의 작품을 한 방에 넣거나 같은 미션을 여러 방에 나눌 수 있다.
5. `담은 작품 정리`는 선택한 방의 간결한 목록을 보여 준다. 여러 편 선택 → `다른 전시실로 이동`,
   방 안 순서 변경, 방 자체의 앞/뒤 이동을 지원한다. 드래그 없이 버튼만으로도 처리할 수 있게 한다.
6. 13편이 있는 방에 8편을 넣으려 하면 `남은 자리 7편`을 알리고 목적지/선택 수를 바꾸게 한다.
   자동으로 일부만 담거나 다음 방으로 넘기지 않는다. 여러 편 이동도 전체 성공 또는 전체 유지다.
7. 작품이 있는 방 삭제는 `작품을 미배정으로 옮기고 전시실 삭제`로 처리한다. 방 삭제와 작품 선정 취소를
   구분하며, 학생 원글은 어느 쪽에서도 삭제하지 않는다. 확인창은 기존 공용 대화상자를 사용한다.

앱의 버튼·글자·메뉴 틀을 재사용한다. 선택 목록을 다시 좁은 좌측 칸에 넣거나 상시 세 개 열로 늘리지 않는다.
기존 미션 검색, 선택 상태, 일괄 원글 검증, 저장 충돌 시 편집 보존을 유지한다.

## 3. 전시실 모습과 감상 흐름

- 1단계의 전시 디자인(정원·미술관·서재·별빛)은 전체 분위기다. 각 디자인에 4종의 배경 변형을 둔다.
  새 방은 서로 다른 변형을 기본 배정하며 교사가 배경 선택 목록에서 바꾸고 3단계 미리보기로 확인할 수 있다.
- 배경 차이는 벽/바닥 색과 조명·장식 배치로 표현한다. 임의 업로드나 방별 AI 이미지 생성은 도입하지 않는다.
  선택한 변형 ID를 방에 저장해 방 순서를 바꿔도 색이 임의로 바뀌지 않게 한다.
- 학생/외부 방문자에게 `02 · 우리가 꿈꾸는 미래 · 20편`과 방 소개를 보여 준다.
  로비에서도 주제별 방으로 바로 들어갈 수 있고, 색뿐 아니라 이름·번호로 구분한다.
- 현재 액자는 4열·3행 기준이다. 20개를 기존 높이에 압축하지 않고 작품 수에 따라 최대 5행까지
  공간 높이를 늘린다. 제목·터치 영역의 가독성을 유지하고 모바일은 넓은 장면 탐색과 목록 보기를 제공한다.
- 13편인 방은 마지막 행의 남은 자리를 비워 둔다. 빈 액자나 부족하다는 경고는 감상 화면에 표시하지 않는다.
- 작품 전문의 이전/다음이 다른 방으로 넘어가면 도착한 방의 주제를 함께 표시한다.
  닫기/뒤로가기는 기존 학생 내비게이션 계약에 따라 출발한 방과 액자로 복귀한다.

## 4. 저장·공개·회수

이전 구현의 다음 자동 계산을 명시적 방 구성으로 교체했다. 아래 목록은 변경 전의 비교 기준이다.

- 프론트 `policy.js`: `worksPerRoom=12`, `maxRooms=ceil(maxWorks/worksPerRoom)`.
- `gallery/roomLayout.js`: 전체 작품 배열을 12편씩 잘라 방을 생성한다.
- DB `class_agit_refresh_catalog_v1`: 보이는 작품 순서 `n`에서 `(n-1)/12+1`로 방을 다시 계산한다.
  따라서 현재 구조에서는 작품 회수 후 다른 방의 작품까지 앞 방으로 이동할 수 있다.
- 교사·학생·외부 읽기 RPC, 엄격한 응답 검사, 외부 Edge 입력 검증, 개발 샘플에도 12편 계산이 있다.

변경 계약:

1. 초안에 안정적인 방 ID, 방 순서, 제목, 소개, 배경 변형을 저장하고 각 선정 작품에 방 ID/방 안 순서를 둔다.
   서버는 담당 학급, 방 소속, 중복 배정, 20편/120편/최대 방 수, 문자열·변형 ID, revision을 함께 검증한다.
   새 표를 쓰면 직접 권한을 닫고 기존 전시 관리 RPC를 통해 하나의 트랜잭션으로 저장한다.
2. 학급 발행판과 외부 발행판에 **방 구성도 복사·동결**한다. 초안에서 방명/배경/작품 순서를 바꿔도
   현재 공개판은 바뀌지 않으며 명시적인 공개판 갱신 때 반영한다.
3. 일반 원본 수정으로 글 내용이나 방 배치가 바뀌지 않는다. 원글 회수·삭제 등 기존 차단 사유는
   즉시 읽기를 막되 **남은 작품을 다른 방으로 재배치하지 않는다**.
4. 새 외부 발행은 전시에 담은 전체 작품을 포함한다. 기존 일부 작품만 발행한 공개본과 이후 수록 철회에도
   원래 방의 주제/배경/소속을 유지한다. 비어 버린 방만 감상 목록에서
   숨긴다. 안정적인 방 식별자와 표시 순서를 분리해 번호의 빈틈을 불법 응답으로 취급하지 않도록 한다.
5. 현재 저장된 초안과 공개판은 각각 **기존 12편 단위 방 배치 그대로** 명시적 구성으로 전환한다.
   기존 공개판의 제목/본문/링크/만료/공개 범위를 바꾸지 않는다. 예전 10실도 그대로 열려야 한다.
6. 기존 브라우저의 엄격한 DTO 검사와 12편 상한 때문에 DB와 화면을 따로 바꾸면 오류가 날 수 있다.
   구현 시 응답 버전/호환 전략을 먼저 정하고, DB 선반영 구간과 이전 탭의 새로고침 흐름을 검사한다.
   적용된 SQL을 수정하지 않고 새 마이그레이션으로 처리한다.

문집은 독립 기능이다. 100편 상한·판형·디자인은 그대로 두고 전시 가져오기만 `방 순서 → 방 안 순서`를 따른다.
방 주제를 문집의 별도 장 제목으로 자동 만드는 기능은 이번 범위에 포함하지 않는다.

## 5. 조회와 변경 대상

- 감상할 때는 현재처럼 발행된 목차/요약만 읽는다. 방 요청당 최대 **20편 요약**, 전문은 선택한 **1편**만 읽는다.
- 방 이름/배경은 기존 목차 응답에 함께 담는다. 원본 글 재조회, 방별 추가 폴링, 홈 추가 요청을 넣지 않는다.
- 20편은 12편보다 요약 행 상한이 약 67% 늘지만 전체 120편의 본문을 읽는 것은 아니다.
  실제 응답 크기·지연은 측정하고, 기존 12편 기준 부하 측정치를 새 버전의 수용량으로 단정하지 않는다.
- 최대 30일, 만료/해지/회수 차단, 요청 예산, 진남초 4학년 1반만 시범 운영과 외부 공유 OFF는 유지한다.

## 로컬 검증 기록

- 합성 DB 롤백: 13+20+8 저장·학급/외부 발행, 21편 방/121편 전시 거부, 20×6=120·기존 10실 읽기,
  미배정 발행 차단, 구형 저장 거부, 원본/초안 수정 후 내용·주제·배경 고정, 첫 방 전체 회수 후 2·3실 유지, 만료 차단.
- 원본 조회 함수를 오류로 대체해도 20편 요약 읽기가 성공했다. 합성 짧은 글의 DB 함수 50회 순차 호출은
  총 15.54ms, 요약 JSON 3,573바이트였다. 로컬 DB 단독 측정이며 네트워크·Edge·동시 접속 수용량 측정은 아니다.
- 브라우저: 교사 13+20+8 배정/저장, 로비 주제 목록, PC 20편 5행, 390px 큰 액자/가로 넘침 없음,
  전문 닫기 후 원래 액자 초점 복귀, 전체 41편 외부 발행과 13/20/8 주제 목차 확인. 작은 화면의 불필요한 세로 공간을 수정했다.
- 전용 93개·구조 335개·보안 정적 271개, 전체 보안 검사, 변경 파일 린트(0경고)를 통과했다. 배포 마감 전체 892개와 빌드도 통과했다. 운영 DB 290/290·Edge 반영 완료. 실제 학교망·동시 부하 인수는 후속이며 시범 범위는 확대하지 않았다.
