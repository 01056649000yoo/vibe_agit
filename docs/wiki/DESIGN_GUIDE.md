# 화면 디자인 가이드

교사·학생 화면을 다듬을 때 지키는 규칙. **정본은 코드**(`src/styles/design-system.css`)이고
이 문서는 그 값을 언제 어떻게 쓰는지 설명한다. 값이 바뀌면 코드가 먼저고 이 글이 따라온다.

## 왜 이 문서가 생겼나

2026-08-25에 실제로 세어 본 숫자다.

| 항목 | 실측 |
|---|---|
| 코드에 박힌 고유 색상 | **1,851종** (토큰은 27종) |
| 모서리 굴림 종류 | **35종** |
| 인라인 `style={{}}` 쓰는 파일 | **152개** |
| 공용 `Button` vs 직접 `<button>` | 279 vs **394** |
| 학생 화면 글자 계단 적용률 | **0%** (172곳 전부 손으로 적음) |

디자인 시스템은 2026-08-05부터 있었지만 **아무 문서도 그것을 가리키지 않았다.** 그래서 새 화면을
만들 때마다 있는 줄 모르고 값을 새로 적었고, 색이 680종에서 1,851종으로 늘었다.

## 규칙

### 1. 값을 화면에서 직접 적지 않는다

색·글자·간격·모서리는 `--ui-*` 토큰만 쓴다. 토큰에 없는 값이 필요하면
**토큰을 늘릴지 먼저 판단**하고, 정말 그 화면에만 필요한 것일 때만 직접 적는다.

```
✅ font-size: var(--ui-text-sm);   color: var(--ui-ink-muted);
❌ font-size: .74rem;              color: #64748b;
```

기능 고유색(뱃지·그래프·상태 강조)은 허용한다. 본문·표면·테두리·포커스는 공통 토큰을 지킨다.

### 2. 글자는 일곱 단계뿐이다

| 단계 | 크기 | 쓰는 곳 |
|---|---|---|
| `--ui-text-xs` | 0.80rem | **뱃지·꼬리표 전용.** 읽어야 하는 문장에 쓰지 않는다 |
| `--ui-text-sm` | 0.90rem | 보조 설명 |
| `--ui-text-md` | 1.00rem | 본문 |
| `--ui-text-lg` | 1.15rem | 카드 제목 |
| `--ui-text-xl` | 1.35rem | 구역 제목 |
| `--ui-text-2xl` | 1.50rem | **화면 제목** |
| `--ui-text-3xl` | 2.00rem | 전체 화면 로딩·마법사 전용 |

**바닥이 0.80rem인 이유**: 그 아래는 초등학생이 태블릿에서 못 읽는다. 실제로 `.45rem`(7.2px)까지
있었고 "글씨가 너무 작다"는 지적을 여러 번 받았다.

아이콘·이모지는 글자가 아니다. 계단에 끼우지 않는다.
다만 **글자 옆에 붙어 같이 커져야 하는 작은 이모지**는 예외로 계단에 올린다.

#### ⚠️ `sm` 으로 올릴지 `xs` 로 둘지

기계적으로 올리면 안 된다. **좁은 칸에 든 짧은 꼬리표는 `xs` 가 맞다.**

`.68rem` 을 `sm`(0.9rem)으로 올렸다가 `지금 할 일` 카드의 `작성 중인 과제` 가 **두 줄로 밀린 적이
있다**(2026-08-25). 32% 커진 탓이다. 같은 이유로 하단 내비의 아이콘 밑 글자도 `xs` 로 뒀다.

판단 기준은 **글자 수와 칸 폭**이다.

| 이런 것 | 단계 |
|---|---|
| 아이콘 옆·밑의 짧은 꼬리표, 좁은 칸 안의 낱말 | `xs` |
| 읽는 문장, 넉넉한 칸 안의 설명 | `sm` 이상 |

올린 뒤 **가장 긴 글자가 든 경우**를 실제 화면에서 본다. `작성 중인 과제`처럼 제일 긴 것이
기준이지 평균이 기준이 아니다.

### 2-1. 게임 화면은 계단이 아니라 `clamp` 를 쓴다

학생 게임 화면(어휘의 탑·작가수호룡)은 **고정 px 칸 40곳·격자 35곳**이라 글자만 키우면
칸을 넘치거나 겹친다. 교사 화면처럼 계단으로 일괄 교체하지 않는다.

대신 `clamp()` 로 **바닥만 올리고 위쪽은 화면이 넓을 때만** 커지게 한다.

```css
/* 전 */ font-size: .58rem;
/* 후 */ font-size: clamp(.64rem, 1.3vw, .72rem);
```

여기서 지키는 것은 "본문처럼 크게"가 아니라 **"안 보일 만큼 작은 것은 없앤다"** 이다.
게임 화면은 오래 읽는 곳이 아니라 보고 누르는 곳이라 기준이 다르다.

⚠️ `aspect-ratio` 로 크기가 정해진 칸(지도의 층 표시 등)은 글자를 키워도 **칸이 안 늘어난다.**
위쪽을 크게 열지 말고 좁게 잡는다. 그리고 좁은 화면(`@media`) 규칙만 고치면 넓은 화면이 그대로
작으니 **기본 규칙과 함께** 고친다.

### 2-2. 폭은 화면보다 커지지 않게 적는다

좁은 화면에서 배치가 뒤틀리는 원인은 대부분 **고정 폭**이다. `width: 340px` 짜리 칸은 320px 폰에서
반드시 넘치고, 넘친 만큼 오른쪽이 잘린다(`body { overflow-x: hidden }` 이 감추고 있어 눈에는 안 보인다).

```css
/* ❌ */ width: 340px;                          grid-template-columns: repeat(6, minmax(92px, 1fr));
/* ✅ */ width: min(340px, 100%);               grid-template-columns: repeat(4, minmax(0, 1fr));
```

새 화면은 처음부터 이렇게 적는다. 이미 있는 169곳 정리는 ROADMAP Stage 5 에 있다.

⚠️ `transform: scale` 로 화면을 통째로 줄이지 않는다. 글자와 터치 영역이 함께 작아져
지금까지 고쳐 온 "글씨가 작다"가 되살아난다.

### 3. 공용 부품을 먼저 쓴다

| 필요한 것 | 쓸 것 |
|---|---|
| 버튼 | `components/common/Button` |
| 카드 표면 | `components/common/Card` |
| 가운데 창 | `components/common/CenteredDialog` |
| 설명 아이콘 | `components/common/GuideInfoButton` (작은 글자 옆은 `size="sm"`) |
| 교사 메뉴 안내 | `components/teacher/TeacherGuideButton` + `constants/teacherGuides.js` |

직접 만들기 전에 **왜 공용 부품으로 안 되는지** 주석에 적는다. 적을 수 없으면 공용 부품을 쓴다.

### 4. 교사와 학생이 같은 말을 쓴다

같은 것을 가리키는 이름은 두 화면에서 **글자까지 같아야 한다.** 교사가 「다시 볼 낱말」이라고
부르는 것을 학생 화면에서 「복습 낱말」이라 부르면, 둘이 같은 화면을 보며 다른 말을 하게 된다.

이름이 갈리기 쉬운 곳은 **두 파일을 한꺼번에 보는 검사**를 만든다.

### 5. 게임 화면 안에서는 공용 `Modal`을 쓸 수 없다

학생 게임 실행 화면이 `zIndex: 20000`이고 공용 `Modal`은 9999다. 그 안에서 창을 열면
**화면 뒤에 숨고 몸통 스크롤만 잠겨 학생이 닫지도 못한다**(2026-08-17 실제 발생).
게임 모듈 안에서는 그 모듈의 오버레이(`vocab-journey__overlay` 같은 것)를 쓴다.

## 지키는 방법 — 문서가 아니라 검사

말로 적은 규칙은 잊는다. **옮긴 화면은 검사가 지킨다.**

`tests/teacherTypeScale.test.mjs`가 목록에 적힌 파일들을 한꺼번에 보고,
하드코딩한 글자 크기가 들어오면 실패한다. 배포 관문(`npm run test:all`)이 이를 막는다.

새 화면을 계단으로 옮겼으면 그 검사의 `MIGRATED` 목록에 **파일 경로 한 줄만 추가**한다.

```js
const MIGRATED = [
    'src/components/teacher/TeacherSettingsHub.jsx',
    // ... 옮긴 파일을 여기 추가
];
```

⚠️ 검사를 새로 만들거나 고쳤으면 **일부러 깨뜨려 실패하는 것까지 본다.** 통과만 하고 아무것도
안 보는 검사가 실제로 나온 적이 있다(2026-08-24, 아이콘 기준 때문에 화면 제목을 통째로 놓쳤다).

## 아직 안 옮긴 곳

옮길 때마다 이 목록을 줄이고 검사 목록을 늘린다.

| 곳 | 상태 |
|---|---|
| 교사 화면 | 계단 421곳 / 하드코딩 219곳 — **약 66% 완료** |
| 학생 화면 | 계단 116곳 / 하드코딩 56곳 — **약 67% 완료**(2026-08-25) |
| 학생 화면 중 남은 곳 | `AgitPlayground.css`(16) · `MyAgitPanel.jsx`(15) — **놀이터·아지트 패널** |
| 모듈 화면 | 어휘의 탑·작가수호룡 교사 화면만 완료. 나머지 미착수 |
| 색·모서리·간격 | 글자만 옮겼다. 색 1,851종은 그대로다 |

**남은 학생 화면 둘은 좁은 칸이 많다.** 놀이터 카드와 아지트 패널은 작은 칸에 글자를 욱여넣은
자리가 많아, 키우면 칸이 터지거나 글자가 잘릴 수 있다. **한 파일씩 바꾸고 실제 화면에서 확인한다.**

### 옮길 때 지키는 순서

글이 많고 칸이 넉넉한 화면부터 옮긴다. 좁은 칸(하단 내비·뱃지·놀이터 카드)은 마지막에 하고,
바꾼 뒤 반드시 눈으로 본다. 아이콘·이모지는 글자가 아니므로 계단에 올리지 않는다 —
다만 **글자 옆에 붙어 같이 커져야 하는 작은 이모지는 예외**로 계단에 올린다.

## 글쓰기 연구소도 같은 계단을 쓴다

연구소(`~/writing-helper`)는 별도 저장소·별도 스택(Next.js + Tailwind)이지만 **같은 값**을 쓴다.
Tailwind 기본 크기를 `@theme`에서 아지트 계단으로 다시 정의해 두어, `text-*` 클래스를 쓰면
자동으로 따라온다.

⚠️ 저장소가 달라 서로의 파일을 읽을 수 없다. **같은 숫자를 양쪽에 적어 두고 각자 검사한다.**
한쪽 값을 바꾸면 다른 쪽도 같은 작업에서 함께 바꾼다.

| 저장소 | 값이 있는 곳 | 검사 |
|---|---|---|
| 아지트 | `src/styles/design-system.css` | `tests/teacherTypeScale.test.mjs` |
| 연구소 | `src/app/globals.css`의 `@theme` | `tests/ui-consistency.test.mjs` |
