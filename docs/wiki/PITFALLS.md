# 되풀이하지 말 것

같은 실수를 두 번 하지 않기 위한 **짧은 목록**이다. 한 줄에 하나, 근거가 되는 기록으로 이어 둔다.

> 규칙: 사고를 겪거나 잘못 판단했으면 **여기 한 줄**을 더한다. 설명은 WORKLOG 항목에 적고
> 여기에는 **다음 사람이 3초 만에 읽을 문장**만 남긴다. **갈래마다 다섯 줄 안으로** 유지하고 넘치면
> 오래된 것부터 지운다 (이 파일이 길어지면 아무도 안 읽어 목적을 잃는다).

## 배포·운영

- **마이그레이션을 앱보다 먼저 적용한다.** 순서가 바뀌면 화면에는 기능이 보이는데 저장이 거절된다.
  `npm run migrate` → 배포. (2026-09-02)
- **도커의 한도는 맥 디스크가 아니다.** 데이터는 외장 SSD 위 `Docker.raw`(상한 32GB) 안에 있다.
  맥이 93GB 남아도 도커는 찰 수 있다. 관문·정리는 `scripts/trim-docker-cache.sh` 가 도커 안쪽을 본다. (2026-09-02)
- **실행 이미지에서 도구를 지우기 전에 실행 명령부터 본다.** 단축링크는 `npm run start` 가 실행 손잡이라
  npm 을 먼저 지우면 컨테이너가 시작조차 못 했다. (2026-09-02)
- **연구소(`writing-helper`)는 만지기 전에 `git fetch`.** 로컬이 74커밋 뒤처진 채 고쳤다가 푸시가 거부됐다. (2026-08-27)

## 판단·확인

- **원인을 추정으로 단정하지 않는다.** "배포가 검사기 이미지를 지웠다"고 기록했다가 확인해 보니
  그 단계는 빌드 캐시만 지웠다. 모르면 **모른다고 적는다.** (2026-09-02)
- **취약점 검사기는 라이브러리가 있는지만 본다.** 그 코드가 실행되는지는 사람이 확인해야 한다.
  판단을 남길 때는 근거와 **유효기간**을 함께 적는다(`src/constants/serviceFindingNotes.js`). (2026-09-02)
- **새로 넣은 검사는 일부러 망가뜨려 실패하는 것까지 본다.** 통과만 하고 아무것도 안 보는 검사가 실제로 나왔다.
  2026-09-04에 두 번 더 나왔다 — 정규식이 `window.confirm` 을 놓쳤고, 다른 갈래의 해제를 세어 누락을 가렸다.
  `${…}`가 들어간 화면 문구는 백틱인지도 본다. 작은따옴표면 빌드까지 통과한 채 식이 그대로 보인다.
- **공유기 포트는 바깥 번호로 본다.** 22번이 열렸는지만 확인하고 "닫혀 있다"고 읽었는데, 실제 규칙은
  **외부 10022 → 내부 22** 였다. 안쪽 번호와 바깥 번호는 다를 수 있다. (2026-09-03)
- **스모크의 `LIMIT 1`은 원하는 상태를 먼저 좁힌다.** 같은 시각·무작위 UUID 행 중 하나를 뽑으면 한 번은
  통과하고 다음에는 이미 처리한 행을 골라 실패한다. (2026-09-04)

## 화면

- **백지로 두면 아무도 채우지 않는다.** 제보 창이 백지라 교사 203명 중 제보가 0건이었다.
  목록형 기능은 기본값을 담아 줄 길을 함께 만든다. (2026-08-21 / 2026-09-02)
- **좁은 칸에 조작 아이콘을 늘어놓으면 정작 내용이 안 보인다.** 글 상세 사이드바는 380px 이라
  아이콘 넷이면 문장 폭이 4분의 3으로 줄었다. 평소에는 내용만, 조작은 모드를 나눠 꺼낸다. (2026-09-02)
- **화면을 바꿨으면 배포 전에 실제로 렌더링해 본다.** `?dev-lab=<시나리오>` 로 DB 없이 띄운다.
  눈으로 안 보고 넘긴 날 두 번 다 사용자가 먼저 발견했다. (2026-09-02)
- **화면을 고쳤으면 도움말도 같은 커밋에서 고친다.** 기능을 처음 만들 때만 적고 그 뒤 세 번 고치는 동안
  도움말을 안 건드려, 하루 만에 실제 화면과 어긋났다(`teacherGuides.js`·운영 문서 세 곳). (2026-09-03)
- **셸 heredoc 안에서 정규식을 쓰면 `\b` 가 진짜 백스페이스 문자(0x08)로 박힌다.** 검사는 통과하는데
  아무것도 잡지 못하고, `grep` 으로 보면 멀쩡해 보인다. 정규식을 파일에 쓸 땐 Edit 도구를 쓰거나
  `String.fromCharCode(92)` 로 역슬래시를 직접 넣는다. (2026-09-03)
- **그림 위에 글자를 얹기 전에 그 자리에 무엇이 오는지 본다.** 트랙의 `출발`·`목표` 를 선 위에 뒀더니
  위로 어긋난 점과 겹쳤다. 겹치는 축을 피해 선 양옆으로 옮기면 자리도 덜 먹는다. (2026-09-03)
- **화면을 손으로 만든 HTML 로 재지 않는다.** 마크업을 잘못 잘라 틀린 수치를 두 번 읽었다.
  진짜 부품·진짜 CSS 로 띄우는 `src/dev/` 미리보기를 만드는 편이 빠르고 정확했다.
  dev-lab 은 `import.meta.env.DEV` 라 **개발 서버에서만** 뜬다(`vite preview` 로는 안 된다). (2026-09-03)
- **겹침·정렬 같은 그림 문제는 눈이 아니라 좌표로 검사한다.** 자리 계산을 `.jsx` 밖 `.js` 로 꺼내면
  `node --test` 가 직접 부를 수 있다. 그렇게 만든 검사가 눈으로 못 본 버그 둘을 바로 잡았다.
  (이때 import 에 **확장자를 적는다** — Vite 는 없어도 찾지만 Node 는 못 찾는다.) (2026-09-03)
- **고치려던 문제를 새 부품이 그대로 되풀이하지 않는지 그려 보고 확인한다.** "브라우저 기본 창은
  긴 이름이 잘린다"를 이유로 앱 안 창으로 옮겨 놓고, 새 창 제목이 `white-space: nowrap` 이라
  똑같이 잘렸다. 코드만 읽었으면 못 봤다. (2026-09-03)
- **`window.confirm` 은 크롬이 막으면 조용히 거짓을 돌려준다.** "추가 대화상자를 표시하지 않음"이
  켜지면 창이 아예 안 뜨고 코드는 "취소를 눌렀다"고 판단해, 버튼을 눌러도 아무 일이 없다.
  사람은 원인을 알 길이 없다. 새 흐름에는 `useConfirmDialog` 를 쓴다. (2026-09-03)
- **훅은 이른 `return` 보다 위에 둔다.** `useMemo` 를 `if (loading) return ...` 아래에 넣었더니
  렌더마다 훅 순서가 달라졌다(`react-hooks/rules-of-hooks`). **빌드는 통과했다** — lint 를 안 돌렸으면
  그대로 배포될 뻔했다. 커밋 전 `npx eslint src tests` 를 꼭 본다. (2026-09-03)
- **한 화면이 틀렸으면 같은 숫자를 쓰는 다른 화면도 본다.** 개인전 숫자칸이 틀렸다는 제보였는데
  같은 원인으로 모둠 대항전도 틀렸고, 현황 창도 같은 숫자를 따로 계산하고 있었다. (2026-09-03)
- **native dialog도 Tab 끝·Shift+Tab 시작을 직접 검사한다.** 내장 브라우저에서 끝 버튼 다음에
  초점이 문서 밖으로 빠졌다. 명시적으로 처음/마지막 컨트롤을 순환시키고, 액자 초점 복귀는
  dialog가 닫혀 배경의 inert 상태가 풀린 뒤 수행한다. (2026-09-05)

- **2026-09-05: 업무용 원글/편집 버전 충돌에 SQLSTATE `40001`을 쓰지 않는다.** PostgREST 14.12에서 같은 요청을 계속 재시도해 HTTP 응답이 끝나지 않는 것을 격리 검사로 재현했다. 새 입력/새로고침이 필요한 충돌은 `PT409`를 쓰고 실제 HTTP 409까지 검사한다. `61240/61241`에 반영. [PostgREST 원인 기록](https://github.com/PostgREST/postgrest/issues/3673).

- **전시 발행의 잠금은 원글 회수와 함께 시험한다.** 부모·전시를 잠근 뒤 원글을 기다리면 회수 트리거와 교착할 수 있다. 발행 잠금은 NOWAIT/짧은 상한과 `PT409`로 끝내고 동시 HTTP 검사로 확인한다. (2026-09-05, `61243`)
