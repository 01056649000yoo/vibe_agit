# 2026-09-28 보안 점검 — 브라우저 공개 RPC 권한 경계 전수 호출

## 기준·범위
- 브라우저 역할(`authenticated`·`anon`)에 EXECUTE 가 열린 `public` 함수 전부(확장 함수·트리거 제외, 점검 시 334호출).
- "누가 부르면 막혀야 하나" 를 네 신원으로 실제 호출해 확인했다.
  ① 어느 학급에도 속하지 않은 가짜 로그인 사용자 ② 비로그인(`anon`) ③ 다른 반 승인 교사 ④ 다른 반 학생.
- 인자는 실제 학급·학생·글·과제 ID(글이 가장 많은 학생의 학급)를 넣었다. 값은 이 기록에 적지 않는다.

## 확인 방법
- 운영 `agit-db` 에서 `pg_proc` 과 `has_function_privilege` 로 대상 목록과 인자 형식을 뽑아 호출 스크립트를 만들었다.
- 함수마다 `SAVEPOINT … ROLLBACK TO SAVEPOINT`, 전체는 `BEGIN … ROLLBACK`. `request.jwt.claim(s)` 로 신원을 바꾸고
  `SET LOCAL ROLE` 로 역할을 맞췄다. 문장 8초·잠금 2초 제한.
- 결과를 "막힘(오류) / 빈 결과 / 데이터를 돌려줌" 으로 나누고, ①이 막혔는데 ③·④가 통과한 호출을 한 줄씩 읽었다.

## 결과
- **다른 반 자료를 돌려준 호출: 0건.** ③·④가 통과한 호출은 모두 `auth.uid()` 본인 자료(내 알림·내 포인트·내 독서 기록 등)였다.
- **권한 상승 1건(고침)**: `setup_teacher_profile(text,text,text)` 이 익명 세션·학생 연결 계정을 거르지 않았다.
  학생 코드 로그인 때문에 인증 서버의 익명 가입이 켜져 있어, 공개 anon 키만으로 익명 세션을 만든 뒤 이 함수를 부르면
  구글 로그인 없이 `TEACHER` 프로필이 생기고, `auto_approval` 이 켜져 있어 곧바로 **승인 교사**가 됐다(롤백 안에서 재현).
  - 영향: 다른 반 자료는 여전히 볼 수 없다(교사 권한은 담당 학급 기준). 대신 가짜 교사 계정을 제한 없이 만들고
    교사 AI·모두의 아지트 초대 같은 교사 기능을 쓸 수 있었다.
  - 악용 흔적: 익명 계정 5,816개 중 교사 프로필을 가진 것 **0개**, 학생에 연결된 교사 프로필 0개(점검 시).
  - `vibe-ai`·`send-feedback` 엣지 함수는 이미 `is_anonymous` 를 걸렀고 이 함수만 빠져 있었다.

## 고친 것
- `supabase/migrations/20261355_setup_teacher_profile_rejects_anonymous.sql` — `auth.users.is_anonymous` 와 `students.auth_id`
  (DB 의 실제 상태)로 판정해 거절. 나머지 본문·권한은 그대로.
- 검사 `tests/sql/20261355_setup_teacher_profile_rejects_anonymous.smoke.sql` — ①익명 ②학생 계정은 거절, ③실제 승인 교사는 그대로.
  **수정 전 운영 정의에서 실패**(익명 세션이 교사 프로필을 만들었다)하고 수정본을 실으면 통과하는 것을 확인.
- 전체 롤백 스모크 러너 `npm run smoke:all` 을 `npm run test:security` 에 넣어, 이런 스모크가 다시 방치되지 않게 했다.
