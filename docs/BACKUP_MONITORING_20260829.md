# 3개 앱 통합 백업 7일 모니터링

> 목적: 새 앱별 백업 원장과 관리자 대시보드가 실제 자동 실행에서도 일주일 연속 맞는지 확인한다.
> 원문 로그·경로·비밀 값은 이 문서에 복사하지 않는다.

## 시작과 합격 기준

- 시작: 운영 반영 뒤 처음으로 오전 4시 통합 백업이 `PASS`이고 앱 결과가 3/3으로 기록된 날.
- 기간: 시작일을 1일차로 하여 7일 연속.
- 일일 합격:
  - 최신 통합 백업 `PASS`, 26시간 안쪽
  - 아지트·샘링크·자비스 앱 결과 3/3 `PASS`
  - 필수 산출물 7개, 내장·암호화 Drive·외장 SSD 모두 정상
  - 03:30 샘링크 보조 백업이 빈 덤프가 아니고 종료 오류 없음
  - `backup_failed` 운영 경고 없음
  - 아지트·샘링크·자비스 공개 진입점의 기대 HTTP 응답 유지
- 복구 합격: 기간 중 최신 복구 리허설이 40일 안쪽 `PASS`. 앱별 기록 전인 과거 리허설은
  새 스크립트로 한 번 실제 실행한 뒤 3/3 결과로 교체한다.

## 시작 전 점검 — 2026-08-28 23:56 KST

- `com.samlink.db-backup` 03:30, `com.agit.backup` 04:00,
  `com.agit.restore-rehearsal` 매월 1일 04:40, `com.agit.service-health` 5분 간격 예약이
  실제 사용자 세션에 모두 로드되어 있다.
- 최근 통합 백업·샘링크 보조 백업의 LaunchAgent 종료 코드는 0이고, 상태 점검도 최근 5회 연속
  앱 200으로 끝났다. 운영 DB의 열린 `backup_failed` 경고는 0건이다.
- 앱별 원장은 운영 DB에 있고 `anon`·`authenticated` 직접 조회 권한이 없다. 8월 28일까지의
  8개 산출물 백업은 전환 전 기록이라 앱 결과 0행이며, 화면에서는 `앱별 기록 전`으로 보인다.
- 제한된 작업 환경에서 상태 스크립트를 한 번 실행해 로컬 포트·Docker 소켓이 막히면서 stderr에
  `app_down`·`DB 무응답` 두 줄이 남았다. 같은 시각 호스트 권한으로 다시 실행한 결과 앱 200·DB 정상이고
  DB 경고도 생성되지 않았으므로 운영 장애가 아닌 점검 환경의 거짓 실패로 판정했다.
- 8월 29일 00:02에는 새 7개 산출물 실행이 앱 결과 3행 전까지 `RUNNING`을 유지하고 3행 완료 뒤
  부모를 `PASS/FAIL`로 확정하는 트리거를 운영 적용했다. 전이 ROLLBACK 스모크, 전체 574개 회귀,
  보안 검사와 실제 5분 점검을 통과했으며 열린 백업 경고는 계속 0건이다.

검사기는 DB 원장과 실제 세 사본·보조 덤프·복구·경고·서비스를 읽기만 하며, 출력 한 줄의 안전한
개수와 상태를 위 표에 옮긴다. 아지트는 NAT 루프백 제약 때문에 공개 Host/TLS를 로컬 Caddy에 직접
연결하고, 샘링크·자비스는 실제 공개 주소를 확인한다. 원문 로그나 파일명 목록은 문서에 복사하지 않는다.
`com.agit.backup-monitor`가 매일 04:15에 같은 명령을 자동 실행하므로 세션이 없어도 원본 판정이
`~/Library/Logs/agit-backup-monitor.stdout.log`에 날짜별 한 줄로 남는다.
