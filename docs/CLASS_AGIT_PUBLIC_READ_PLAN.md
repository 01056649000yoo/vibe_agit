# 우리반 아지트 공개본 조회 개선안

상태: 2026-09-05 검증 후 사용자 배포 요청으로 `61242/61243`을 운영 적용하고 전용 Edge 입구를 설치했다. 앱은 같은 변경 커밋의 Deploy 대상으로 확정했다.
제품 범위 정본은 [CLASS_AGIT_PLAN.md](../CLASS_AGIT_PLAN.md), 측정 기록은 [PERFORMANCE_HARNESS.md](../PERFORMANCE_HARNESS.md).
전시 120편 확장을 포함하며 외부 공유 OFF·진남초 4학년 1반 시범 운영을 유지한다.

## 1. 적용한 구조

**발행 때 콘텐츠를 확정하고, 감상 때는 그 공개본만 읽는다. 원글의 공개 자격 변화는 변경 시점에 공개본의 열람 상태에 반영한다.**

- 방/작품 감상에서 원글·미션·학생 원문 조회와 본문 분해·해시 재계산을 없앤다.
- 매 요청에는 작은 공개 제어 정보(토큰·만료·해지·현재 판·시범 학급·관리자 허용)를 확인한다.
- 로비는 목차, 방은 12편 요약, 작품은 전문 1편만 읽는다. 공개본 전체 JSON을 꺼내 잘라 주지 않는다.
- 초안·내부 공개본·외부 공개본은 각자 내용을 유지한다. 외부 표시 이름과 내부 학생 이름을 섞지 않는다.
- 변경 반영은 학생 앱이나 교사 브라우저에 맡기지 않고 DB의 같은 트랜잭션 안에서 처리한다.

## 2. 현재 구현에서 재사용할 것과 교체할 것

| 현재 구현 | 변경 방향 |
|---|---|
| 외부 작품별 `class_agit_external_items.snapshot` | 재사용. 발행 때 만든 제목·가림 이름·본문을 읽는다 |
| 외부 조회의 `class_agit_current_source_v1` 호출 | 감상 경로에서 제거. 발행/재발행 때만 원문을 검증하고, 자격 변경은 별도 상태 조건으로 철회한다 |
| `snapshot - 'blocks'`로 방 요약 생성 | 본문과 독립된 요약 컬럼을 발행 때 저장하고 해당 컬럼만 SELECT한다 |
| 조회 때 `row_number()`로 전체 작품의 방 구성 계산 | 발행/철회 때 표시 위치·방 번호·방별 편수를 미리 계산한다 |
| 내부 `published_snapshot`의 전체 작품 배열 전개 | 공개 작품 전용 행으로 분리. 초안 항목을 공개본 대신 사용하지 않는다 |
| 원글 회수·학생 비활성/전출 시 철회 트리거 | 재사용·보강. 원글·학생·미션의 공개 권한/소속 변경을 변경 시점에 반영한다 |
| 읽기 RPC 안의 공통 요청 카운터 갱신 | API 입구의 짧은 트랜잭션에서 끝내고 콘텐츠 읽기와 분리한다 |

외부 표시는 이미 저장되어 있다. 새 파일 저장소나 공개 정적 파일로 이전하지 않는다.
작품 본문을 포함한 큰 JSON에서 일부 필드만 빼는 방법은 본문 저장값을 처리할 수 있으므로,
요약을 독립 컬럼에 두어 목록 조회에서 큰 값을 참조하지 않게 한다.
[PostgreSQL TOAST 설명](https://www.postgresql.org/docs/17/storage-toast.html)

## 3. 저장 단위와 조회 예산

| 단위 | 저장 내용 | 언제 갱신하나 |
|---|---|---|
| 공개 제어 정보 | 공개판 번호, 허용 학급/공개 상태, 만료/해지, 외부 토큰 해시 | 발행·공유 설정 변경 |
| 공개 목차 | 확정 전시 제목/소개, 열람 가능한 총 편수, 최대 10실의 편수, 노출 상태 버전 | 발행·철회·배치 변경 |
| 작품 요약 | 확정 제목·표시 이름·장르·짧은 미리보기, 원래 작품 번호, 표시 순서·방/자리 | 발행; 배치는 철회 시에도 갱신 |
| 작품 본문 | 발행 시 확정한 전문·시의 연/행 | 재발행 시에만 교체 |
| 내부 연결/철회 상태 | 원글·학생·미션·수록 확인 세대, 철회 여부/사유 | 발행·해당 원본 상태 변경 |

외부는 기존 공유/작품 표에 요약·배치·목차를 추가하는 방향을 우선한다.
내부 전시는 초안과 독립된 공개 작품 표를 추가하고 현재 판 번호로 읽는다.
`class_agit_published_items`에 내부 확정 제목·표시 이름·전문을 저장한다. `class_agit_publication_catalog`는 내부/외부 목차를, `class_agit_publication_slots`는 본문 없는 방별 배치를 저장한다. 외부 전문은 기존 `class_agit_external_items.snapshot`을 그대로 쓴다.

인덱스는 학급을 직접 범위로 하여 아래 조회를 지원한다.

- 방 요약: `(class_id, 공개본 식별자, 판 번호, room_no, display_position)`의 열람 가능 항목.
- 작품 상세: `(class_id, 공개본 식별자, 판 번호, work_no)`로 한 행.
- 변경 전파: `(class_id, post_id)`, `(class_id, student_id)`, `(class_id, mission_id)`에서 영향을 받는 공개본만 찾는다.
- 현재 판만 제공하며 과거 판 요청은 충돌/재확인 응답으로 돌린다. 원문/학생 ID는 외부 DTO에 포함하지 않는다.

| 사용자 동작 | 원글 본문 조회 | 공개본 조회 |
|---|---:|---|
| 전시 발행/갱신 | 선택한 최대 120편을 한 번 검증 | 확정본·요약·배치 작성 |
| 전시 입장 | 0 | 제어 정보 + 작은 전시 목차 |
| 전시실 이동 | 0 | 제어 정보/목차 + 해당 방 요약 최대 12편 |
| 작품 읽기 | 0 | 제어 정보 + 해당 작품 전문 1편 |
| 작품 닫기/방 재확인 | 0 | 해당 방의 최신 요약 |
| 원글 회수/전출 | 변경된 자료만 확인 | 연결된 항목 철회 + 영향을 받는 전시의 목차/배치 갱신 |

여기서 0은 원글 콘텐츠 조회가 없다는 뜻이다. 권한 확인용 학급/교사 승인·학생 본인 연결 같은 작은 조회는 남는다.

## 4. 발행·변경·감상의 처리 순서

### 발행

1. 담당 교사 권한, 학급 범위, 선택한 글의 자격·버전·수록 확인을 검사한다.
2. 선택한 작품의 확정 제목/본문·표시 이름을 준비한다. 일반 원문 수정은 공개본을 자동 교체하지 않는다.
3. 요약을 별도로 만들고, 방당 12편 기준의 배치·목차를 계산한다.
4. 모든 작업 성공 시 현재 공개판 번호를 바꾼다. 실패하면 기존 공개판을 유지한다.
5. 초안 저장은 이 절차를 실행하지 않는다. 기존 공개판은 교사의 공개판 갱신 동작으로만 바뀐다.

### 원본/공개 조건 변경

| 변화 | 공개본 처리 |
|---|---|
| 공개 자격을 유지한 일반 본문·제목·이름 수정 | 기존 확정 내용 유지. 교사 화면에서 변경됨을 표시하고 재발행 때 반영 |
| 원글 회수·비공개·확인 취소·반려·삭제 | 연결된 공개 항목 철회 |
| 원글의 학급/작성자/미션 연결 변경 | 영향을 받는 공개 항목을 닫고 새 수록 확인 요구 |
| 학생 비활성·전출·삭제 | 그 학생의 연결된 공개 항목 철회 |
| 미션 삭제·다른 학급으로 변경 | 연결된 공개 항목 철회 |
| 발행 후 원문의 내용·제목·구조·장르 수정 | **사용자의 2026-09-05 추가 결정:** 이미 확정한 전시 내용/형식 유지. 변경 원문은 재발행 때 자격을 다시 검사 |
| 교사의 작품 수록 철회 | 해당 범위/확인 세대의 항목만 철회. 내부·외부·문집 구분 유지 |
| 교사 승인 취소·학급 삭제·시범 제외·관리자 외부 OFF | 요청 시 작은 공개 제어 검사에서 전체 차단 |
| 링크 해지·만료·재발급 | 요청 시 현재 링크/만료 검사에서 차단. 작품 본문 재가공 불필요 |
| 철회된 원글을 다시 제출·공개 | 과거 공개 항목 자동 복원 금지. 새 확인과 발행 필요 |

본문·제목·이름·장르의 일반 수정과 공개 권한 철회를 분리한다. 원문 형식이 바뀌어도 안전하게 확정된 과거 내용을 다시 가공하거나 숨기지 않는다. 발행/재발행 때는 기존 원문 상한·지원 장르·수록 확인을 모두 검증한다.
미션 제목 변경처럼 공개 자격과 무관한 수정은 공개 항목 재작성이나 철회를 유발하지 않는다.

변경 대상만 검증하며, 원글 쓰기 코어의 UI/파이프라인은 수정하지 않는다. 모듈 소유 트리거/DB 함수로 연결한다.
원글 변경과 항목 철회·목차 갱신이 모두 성공하거나 모두 롤백되게 한다. 트리거는 원래 변경과 같은 트랜잭션에서 실행된다.
[PostgreSQL 트리거 동작](https://www.postgresql.org/docs/17/trigger-definition.html)

여러 글을 한 UPDATE로 회수하면 transition table로 변경 대상을 모아 각 전시의 작은 목차/배치를 한 번씩 갱신한다. 물리 삭제는 FK가 원글 ID를 비우기 전 BEFORE DELETE에서 철회한다.
모든 작품의 본문을 다시 만들거나 모든 학급을 훑지 않는다. 글 저장 지연이 감상 비용의 대가로 커지지 않는지도 측정한다.

### 작품 번호와 방 배치

- 공개판 안의 `published-120` 같은 작품 번호는 철회 후에도 다른 작품에 재사용하지 않는다.
- 현재처럼 철회된 자리를 제외하고 남은 작품을 12편씩 배치하되, 재배치는 변경 시에 수행한다.
- 공개판 번호와 별도로 노출 상태 버전을 둔다. 철회/재배치가 생기면 이를 올리고 오래된 방 정보는 재확인한다.
- 방 배치·목차·철회 상태가 일부만 보이지 않게 같은 트랜잭션으로 처리하고, 감상은 일관된 상태를 읽는다.
- 감상 함수는 STABLE로 한 SQL 문장의 동일한 MVCC 스냅샷을 사용하므로 메타데이터/요약/본문을 일관되게 읽으며 쓰기 잠금을 잡지 않는다. 발행/저장은 충돌하는 원글·부모·전시 잠금을 기다리지 않고 PT409로 다시 확인하도록 안내한다.
  원글 수정↔발행, 전출↔발행, 여러 작품 동시 회수의 교착/부분 노출을 필수 회귀 시나리오로 둔다.
- 차단의 기준은 변경 커밋 이후 시작한 다음 조회다. 이미 전달한 글을 브라우저에서 원격 삭제한다고 설명하지 않는다.

## 5. 요청 제한은 콘텐츠 읽기와 분리

외부 읽기는 `class-agit-public-read` Edge 입구를 사용한다. 브라우저 직접 읽기 RPC는 닫았다.

1. 브라우저가 토큰/방/작품/판 번호를 한 번의 POST로 전달한다. 입력 형식·크기부터 제한한다.
2. 서버 전용 함수에서 전역/공유별 요청 예산을 차감한다. 이 짧은 DB 트랜잭션을 즉시 끝낸다.
3. 통과한 요청만 읽기 전용 함수로 확정 공개본을 조회한다. 토큰·해지·만료·현재 권한은 여기서 다시 검증한다.
4. 비공개 본문·토큰을 로그에 남기지 않고, 성공/실패 응답 모두 기존 no-store/no-referrer 정책을 적용한다.

브라우저 호출은 한 번이며 서버 내부 DB 작업은 짧은 예산 검사와 콘텐츠 읽기 두 번으로 분리된다.
예산을 한 번 소진했다고 해지/만료 검사를 생략하지 않는다. 브라우저에 별도의 재사용 가능한 조회 허가증을 발급하지 않는다.
카운터 행은 유지하되 긴 콘텐츠 조회 동안 잠금을 잡지 않는다. 실제 20개 동시 요청 p95는 기존 약 2.1초에서 약 61ms로 줄었다(아래 측정 범위 참조).

우회 방지: 내부 읽기/예산 함수는 서버 전용 역할만 실행한다. 기존 익명/일반 인증 역할의 직접 읽기 RPC를
열어 둔 채 API에만 제한을 거는 방식은 사용하지 않는다. 함수 권한·호출처·운영 Edge 허용 목록·오류 응답을 함께 바꾼다.
공유 IP의 학부모/학교 접속을 위해 IP별 강한 제한 대신 기존 전역/전시 단위 예산을 우선 유지한다.
전역 3,000회/분·공유 600회/분을 단순히 올려 병목을 가리지 않는다. 필요한 방문 규모는 별도 측정 후 조정한다.

## 6. 캐시 정책

첫 구현에서는 브라우저/CDN에 공개 작품을 캐시하지 않고 DB의 확정본과 인덱스로 개선 폭을 먼저 측정한다.
공개 해지 후에도 정적 파일 주소가 살아 있는 형태로 바꾸지 않는다.
나중에 추가 캐시가 필요하면 서버 내부에 확정 콘텐츠만 두고 현재 접근 허용 여부는 매 요청 확인한다.
캐시 키는 공개본·판·노출 버전을 포함해야 하고, 만료 시간만으로 철회를 처리하지 않는다.
학생 홈 폴링·외부 페이지의 상시 연결은 추가하지 않는다.


## 6A. 전시 기간 (구현)

- 바로 시작 또는 예약 시작과 종료 시각을 설정한다. 최대 **30 × 24시간**이며 정확히 30일은 허용, 1초 초과·역순·무한 날짜는 거부한다.
- DB 제약과 발행/종료 변경 RPC가 같은 `class_agit_valid_share_period_v1` 규칙을 사용한다. 과거 시작 입력은 발행 과정의 5분 오차만 허용한다.
- 시작 전·종료 시각 이후는 예산 검사와 실제 읽기에서 다시 차단한다. 크론 실행 여부에 의존하지 않는다.
- 주소 재발급은 기존 시작·종료를 그대로 보존한다. 종료 변경도 **원래 시작부터 30일 이내**이며, 만료/해지 후 연장은 거부한다. 다시 전시하려면 작품과 외부 공개 의사를 확인해 새 판을 발행한다.
- 이미 열린 화면은 서버가 알려 준 남은 시간으로 일회성 종료 타이머를 둔다. 탭/기기 복귀 시에도 확인하며 폴링은 하지 않는다. 이미 전달된 파일·본문 자체를 회수한다는 보장은 하지 않는다.

## 7. 구현 순서와 기존 자료 전환

1. **공개본 저장 구조/변경 반영부터 구현:** 외부 요약/배치 추가, 내부 공개 항목 분리, 자격 변화·철회 전파 보강.
2. **기존 공개본 전환:** 원글에서 새 내용을 만들어 덮지 않고 기존 확정 스냅샷에서 요약/본문/배치를 옮긴다.
   전환 때만 현재 자격을 한 번 확인해 노출 불가능한 항목을 닫는다. `revoked_at`·확인 세대·판 번호·토큰 해시·만료는 보존한다.
3. **새 읽기 경로 연결:** 로비/방/전문이 공개본만 읽도록 교사 공개판 확인·학생·외부 경로를 함께 변경한다.
   전환이 끝난 공개본만 새 조회를 허용하고, 미완료 상태에서는 전체 원글 재조회로 조용히 되돌아가지 않는다.
4. **외부 요청 제한 분리:** 서버 입구·서버 전용 역할·직접 RPC 권한 폐쇄를 연결한다.
5. **단계별 기능/부하 검사 후 배포:** 외부 OFF 동안 전환하고 합격 후 별도 공개 결정. 운영 적용은 사용자 배포 요청 때 진행한다.

이미 적용된 `20261241`은 고치지 않고 120편 확장 이후 새 마이그레이션으로 진행한다.
폐기 함수/구형 경로는 실제 호출처와 DB 함수·RLS·다른 앱까지 확인해 같은 마이그레이션에서 정리한다.
호환을 위해 남길 함수가 있으면 실제 소비자·종료 조건을 기록하며 요청 제한 우회 경로는 남기지 않는다.
이 설계가 전시 편집·미션별 후보 UI 개편을 막지는 않지만, 외부 공개를 켜기 전에는 1~5를 끝낸다.

## 8. 합격 기준

- **조회 경로:** 로비/방/전문에서 `student_posts` 본문 조회·본문 분해·해시 재계산 0회.
  SELECT 목록과 실행 계획/함수 호출 추적을 함께 검사해 다른 함수 안의 원글 재조회도 잡는다.
- **응답/저장:** 120편·10실, 방 12편 요약·본문 1편. 요약 최대 25KB(제목/가림 이름의 허용 최대 길이 포함), 전문 20,000자 계약 유지.
- **독립성:** 일반 원글 수정/초안 편집은 기존 판을 바꾸지 않으며 재발행이 실패하면 기존 판·목차가 그대로 남는다.
- **안전성:** 원글/학생/미션/학급/교사 승인/링크의 변경 표 전체, 과거 번호/판, 철회 후 복구 방지, 내부 실명·외부 가림 이름 분리를 검사한다.
- **원자성:** 원글 변경이나 목차 갱신 실패 시 함께 롤백, 동시 회수/발행 때 부분 노출·잘못된 작품 연결 없음.
- **목록 안정성:** 1·12·13·60·61·120편과 중간 작품 철회, 마지막 방 제거, 재발행 후 오래된 주소를 검사한다.
- **우회 방지:** anon/authenticated가 DB 직접 호출로 예산 검사를 건너뛸 수 없음. 초과 요청은 일관된 429로 처리.
- **성능:** 같은 최장 글 시험의 20개 동시 요청에서 p95 500ms 미만을 1차 목표로 하되 측정 전 달성했다고 간주하지 않는다.
- **혼합 부하:** 일반 글/최장 글, 한 전시/여러 전시에서 100명→300명으로 단계적으로 늘려 10분 유지.
  실제 읽는 시간을 포함하고 최초 동시 입장과 지속 감상을 구분한다. 허용 요청 예산 안의 성능과 예산 초과 차단 시험을 분리한다.
  예: 여러 링크에 분산한 300명과 한 링크의 300명은 공유별 600회/분 제한 때문에 같은 시나리오가 아니다.
- **본 서비스 영향:** 학생 홈·글 저장의 기존 기준, API 오류율 1% 미만, DB 연결 80/100 미만·CPU 지속 70% 미만·swap 0을 함께 본다.
  의도적으로 한도를 초과한 429는 기능 오류와 별도로 집계한다.
- **검사 묶음:** 전용 계약·아키텍처·보안·롤백 스모크·격리 HTTP·위 동시성 시나리오. 새 검사는 결함 변이를 실제로 차단하는지도 확인한다.

새 구조의 변경 비용은 발행/회수 같은 드문 쓰기 시점에 집중된다. 따라서 부하 검사는 읽기 성능뿐 아니라
원글 한 편을 수정하거나 학생을 전출시킬 때 영향을 받는 여러 전시를 처리하는 시간도 포함해야 한다.

- 저장/조회/권한/기간: `supabase/migrations/20261243_class_agit_frozen_public_reads.sql`
- 서버 입구: `supabase/functions/class-agit-public-read/{index.ts,handler.js}`

- 전용 계약: `tests/classAgitFrozenReads.test.mjs`
- 배포는 `61242 → 61243` 검증/적용 후 앱과 Edge 두 파일을 함께 반영한다. 2026-09-05 운영 원장 286/286·대기 0과 Edge 설치를 확인했다. `scripts/sync-class-agit-public-read.sh`를 Actions와 로컬 배포가 공용으로 쓴다. 외부 OFF 상태에서 전환하며 공개 스위치는 자동으로 켜지 않는다.

- 기존 읽기 도우미는 교체한 두 학생 RPC 외 DB 소비자/정책이 없고 다른 네 앱의 배포본에도 참조가 없어 같은 마이그레이션에서 제거했다.


## 10. 검증 결과와 운영 규모

- 전용 계약 66개, 아키텍처 308개, 보안 정적 244개 통과. 전체 보안 검사(실제 RPC 표면·롤백 마이그레이션·역할 스모크·운영 설정)도 통과했다.
- `smoke:class-agit`는 120편 용량과 고정 공개본·기간·철회·권한을 최신 두 마이그레이션 위에서 검증하고 모두 롤백한다.
- 격리 HTTP에서 실제 Edge → REST → DB 경로의 200/404/409/429, 직접 RPC 폐쇄, 토큰 회전, 기간 제한, 두 원자적 변경의 동시 실행을 검증했다. 임시 DB와 컨테이너는 제거했다.
- 일반 원본 제목/본문/이름/미션 형식 변경 전후 공개본 해시가 같았다. 원본 읽기 도우미를 의도적으로 실패시키고도 교사·학생·외부 감상 5경로가 정상 동작했다.
- 같은 120편 최장 글 전시에서 20개 동시 요청 p95 약 61ms. 100명/1전시와 300명/3전시에 각 10분간 1인당 20초 한 동작을 모사해 감상 3,000/9,000회, 오류·429 모두 0이었다. 감상 p95는 12.6/10.7ms, DB 연결 최대 26/100이었다.
- 브라우저에서 예약 시작/종료 입력, 30일 초과 거절, 새 주소 발행, 만료 후 새 확인/재발행, 기존 판을 유지한 종료 시각 변경, 새로고침 없이 열린 전시의 자동 만료를 확인했다. 모바일 390px에서도 날짜 입력과 버튼이 가로로 넘치지 않았다.

전시당 약 100명의 지속 감상을 초기 운영 기준으로 제안한다. 전시 600회/분·전체 3,000회/분 제한은
요청 수이며 사람 수가 아니다. 여러 전시의 300명 결과를 하나의 전시에 적용하지 않는다.

**범위/미검증:** 측정은 같은 맥미니의 격리 합성 자료와 로컬 HTTP 경로다. 외부 회선/TLS/운영 Kong/앱 최초
정적 자산 로딩은 제외했다. 병행한 학생 홈과 시험용 원글 UPDATE는 각각 2초 한 번이며 전체 학생 저장/제출
파이프라인이 아니다. 호스트 swap이 이미 사용 중이고 사전 자원 기준치를 수집하지 않아 공용 1,000명 혼합
부하의 CPU/swap 합격선을 통과했다고 판단하지 않는다. 자원 단위와 측정 표는
[PERFORMANCE_HARNESS.md](../PERFORMANCE_HARNESS.md)의 후속 측정에 기록했다.
