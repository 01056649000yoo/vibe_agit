# 끄적끄적 아지트 디자인 시스템 v1

## 목표

학생·교사·관리자 화면의 개성은 유지하되, 같은 역할의 표면·글자·버튼·모달은 같은 규칙을 사용한다.
현재 기능을 다시 디자인하는 작업이 아니라 앞으로 UI가 더 흩어지지 않게 기준선을 세우는 작업이다.

2026-08-05 1차 감사 기준으로 소스에는 고유 6자리 색상값 약 680개, `borderRadius` 표현 46종,
인라인 스타일 사용 파일 112개가 있다. 한 번에 기계적으로 치환하지 않고, 공용 부품과 자주 쓰는 화면부터 점진적으로 옮긴다.

## 파일

- `design-system.css`: 의미 기반 색상·글자·간격·모서리·그림자·터치 크기·포커스 토큰
- `components/common/Button.jsx`: 버튼 종류와 `xs/sm/md/lg` 크기
- `components/common/Card.jsx`: 정적인 표면과 선택적인 `interactive` 카드
- `components/common/CenteredDialog.jsx`: 중앙 모달의 배치·헤더·닫기·Esc·본문 스크롤
- `dev/UiPreview.jsx`: DB 없이 공통 디자인과 태블릿 반응형을 확인하는 개발 전용 작업실

개발 서버에서 `?ui-preview=1`을 붙이면 UI 작업실만 로드한다.

## 새 화면 규칙

1. 본문·보조 글자·페이지·표면·테두리·포커스는 `--ui-*` 의미 토큰을 사용한다.
2. 기능 고유 색은 뱃지·그래프·상태 강조에만 사용한다. 기능 고유 색으로 기본 본문이나 카드 테두리를 다시 정의하지 않는다.
3. 일반 버튼은 `Button`을 사용한다. 주요 행동은 `primary`, 보조 행동은 `outline/ghost`, 삭제는 `danger`다.
4. `sm` 이하가 보여도 태블릿 터치 환경에서는 공통 CSS가 최소 44px 터치 높이를 보장한다.
5. 클릭되지 않는 카드는 움직이지 않는다. 클릭 카드만 `interactive`를 켠다.
6. 중앙 모달은 가능한 한 `CenteredDialog`를 사용한다. 별도 구현 시에도 중앙 배치·Esc·바깥 클릭·본문 스크롤·SVG 닫기 버튼을 지킨다.
7. 학생 글쓰기 코어는 기능 로직을 수정하지 않고 공용 버튼·카드·도구 슬롯의 스타일만 적용한다.

## 단계적 적용 순서

1. 공용 Button/Card/Modal과 개발 프리뷰
2. 학생 글쓰기·독서록의 입력 주변 UI
3. 학생 홈·나의 아지트·친구 아지트
4. 교사 글쓰기 관리·학급 운영·학급 발자국
5. 관리자와 보관 중인 레거시 모듈

기존 원시 값을 전역 검색·치환하지 않는다. 화면 단위로 적용하고 PC·태블릿 세로·태블릿 가로를 확인한 뒤 다음 화면으로 넘어간다.
