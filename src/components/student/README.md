# 학생 내비게이션 계약

학생 화면에서 새 메뉴·목록·편집기·전체 화면 판을 추가할 때 지키는 공통 계약이다. 화면 버튼뿐 아니라
브라우저와 안드로이드 기기의 뒤로가기까지 같은 부모로 돌아가야 한다.

## 화면 유형별 원칙

| 유형 | 현재 예 | 하단 메뉴 활성 | 화면·브라우저·기기 뒤로가기 |
|---|---|---|---|
| 루트 | `main` | 홈 | 앱 안에 머무름 |
| 최상위 메뉴 | 과제, 독서록, 친구 아지트 | 자기 메뉴 | 항상 메인 대시보드 |
| 최상위 메뉴의 하위 화면 | 과제 편집기 | 부모 메뉴 | 부모 목록 |
| 같은 경로 안의 편집 상태 | 독서록·일기의 `mode: editor` | 부모 메뉴 | 같은 경로의 목록 상태 |
| 메인 위 전체 화면 오버레이 | 나의 아지트, 아지트 놀이터 | 자기 메뉴 | 오버레이를 닫고 메인 대시보드 |
| 문맥 진입 화면 | 과제에서 연 친구 글 | 실제 화면 메뉴 | 명시한 문맥 부모(현재는 과제 목록) |

최상위 메뉴끼리는 형제다. 과제에서 독서록으로 옮겨도 독서록의 부모는 과제가 아니라 메인이다. 반면 과제
목록에서 편집기로 들어간 것은 실제 부모·자식 관계이므로 편집기의 부모는 과제 목록이다.

## 단일 원본

- 하단 메뉴의 ID·이름·아이콘·직접 페이지·오버레이 여부는
  `studentNavigation.js`의 `STUDENT_BOTTOM_NAV_TABS`에만 등록한다.
- `StudentBottomNav.jsx`에 메뉴 배열이나 `writing → mission_list` 같은 예외를 다시 적지 않는다.
- 하단 메뉴 클릭은 반드시 `App.jsx`의 `handleStudentBottomNavigation`을 거친다. 하단 메뉴에서
  `setInternalPage`를 직접 호출하면 이전 메뉴가 방문 기록의 부모가 되는 오류가 다시 생긴다.
- 화면 안의 공용 뒤로가기는 `handleCurrentStudentBack`으로 연결하고, 특수 부모는
  `getStudentBackDestination` 한 곳에만 추가한다.
- 현재 메뉴 강조는 `getStudentActiveBottomTab`에서 정한다. 새 하위 페이지가 생기면 어느 메뉴 소속인지 이
  함수에 명시하고, 하단 메뉴 소속이 아니면 억지로 홈을 활성화하지 않고 `null`을 사용한다.

## 학생 홈 전체 사용법

- 상단 `사용법` 창의 문구·순서·바로 가기는 `studentGuide.js`가 유일한 원본이다.
- 하단 메뉴에 있는 목적지는 `pageName`을 다시 적지 않고 `destination: { type: 'tab', tabId }`만 선언한다.
  실제 페이지와 나의 아지트·놀이터 오버레이 연결은 `studentNavigation.js`가 결정한다.
- 일기처럼 하단 메뉴가 아닌 최상위 화면은 `route`, 내 글 소식·활동 알림·글쓰기 발자국처럼 홈 안에서 여는
  창은 `dashboard-action`을 사용한다. 새 동작 종류를 임의로 늘리기 전에 기존 메뉴·모달로 갈 수 있는지 확인한다.
- 설명은 초등학생이 한 번에 읽을 수 있는 두 문장 이내로 쓰고, 모든 항목에 실제 이동 버튼을 둔다. 도움말을 여는
  상단 버튼은 공용 `GuideInfoButton`을 사용한다.
- 메뉴를 추가하거나 이름·공개 범위를 바꾸면 실제 화면과 `studentGuide.js`를 같은 작업에서 고치고
  `tests/studentGuide.test.mjs`와 `tests/studentNavigation.test.mjs`를 함께 실행한다.

## 방문 기록

- 학생 방문 기록에는 `studentPage`, `studentParams`, `studentParent`를 함께 저장한다. 이름만 저장하면 독서록
  편집기처럼 같은 페이지 이름을 쓰는 목록·편집 상태를 복원할 수 없다.
- 새 페이지에서 `window.history.pushState`나 `replaceState`를 직접 호출하지 않는다. 일반 페이지는 앱 셸의
  공용 기록 처리를 사용한다.
- 전체 화면 오버레이만 예외다. 새 오버레이는 메인 위에서 자기 기록을 정확히 한 번 쌓고 `popstate`에서
  닫는다. 닫기 버튼·ESC로 닫을 때 현재 기록이 자기 오버레이이면 그 기록도 함께 소비해야 한다.
- 브라우저 뒤로가기에서 복원된 화면을 앱이 다시 `pushState`하지 않도록 공용 `skipHistoryPushRef` 흐름을
  유지한다.

## 오버레이 열기 신호

- 대시보드가 마운트된 뒤 여는 신호는 일회용이다. 사용 직후 부모 콜백으로 `0`으로 초기화한다.
- 열림 상태는 부모에 알려 하단 메뉴 강조와 일치시킨다. 닫기·다른 메뉴 이동·대시보드 언마운트 때는 반드시
  활성 오버레이를 해제한다.
- 나의 아지트와 놀이터처럼 서로 배타적인 판은 하나를 열 때 다른 판·하위 게임·상점을 함께 닫는다.
- 신호를 단순한 `true`나 소진되지 않는 양수로 남기면 대시보드 재진입 때 예전 오버레이가 다시 열린다.

## 우리반 아지트 감상 경로

- `class_agit`은 하단 메뉴를 늘리지 않는 조건부 홈 카드다. `class_agit_available`와 학급 모듈 ON을 함께 검사하며
  홈 사용법도 같은 두 조건을 만족할 때만 표시한다.
- 문집은 전시 목록→문집 서가(`books`)→확정판 차례(`book`)→작품(`chapter`) 순서이며 `editionId`와 `chapter-1..100` 주소만 기록한다. 홈 신호는 전시 또는 학생 서가의 공개판 존재 여부다.
- `params`에는 전시 ID·mode·room·view·작품 번호·발행판 번호만 넣는다. 부모는 전문→같은 방/보기→로비→목록→홈이다.
  모듈의 `student/navigation.js`를 공용 부모 함수가 호출한다.
- 방 이동·보기 전환·작품 넘기기는 앱이 제공하는 `onReplace`로 현재 단계만 바꾸고 부모를 유지한다.
  전문을 닫으면 방을 다시 읽어 철회된 작품을 지우고 원래 액자 초점·가로 위치를 복원한다.
- 학생 계정/학급 전환은 읽기 호스트를 새로 만들며, 공개 신호가 사라진 뒤 과거 기록으로 재진입해도 홈으로 보낸다.
  서버도 매 요청에서 현재 학급·공개 상태를 재검증한다. 검사는 `tests/classAgitStudent.test.mjs`에 묶는다.

## 작성 중 화면

- 작성 중인 화면은 자체 저장·임시본·이탈 확인을 끝낸 뒤 전달받은 `onBack`을 호출한다. 내비게이션 셸이
  편집 내용을 직접 저장한다고 가정하지 않는다.
- 목록과 편집기가 같은 페이지 이름을 쓰면 `params.mode`처럼 직렬화 가능한 상태로 구분한다. 함수·DOM·큰
  본문 객체는 방문 기록 매개변수에 넣지 않는다.
- 새 글쓰기 화면을 `isStudentComposing` 대상에 추가해야 홈 주기 동기화가 작성 내용을 덮지 않는다.

## 새 메뉴 추가 순서

1. 하단 메뉴를 추가하는 경우에만 `STUDENT_BOTTOM_NAV_TABS`에 등록한다. 우리반 아지트 같은 조건부 홈 카드는 모듈 매니페스트의 `studentDashboard`로 등록한다.
2. 직접 페이지면 `App.jsx`에 지연 렌더 진입점을 붙이고, 오버레이면 메인 대시보드가 열기·닫기 상태를 소유한다.
3. `getStudentActiveBottomTab`과 `getStudentBackDestination`에 하위 화면·특수 부모가 필요한지 확인한다.
4. 페이지 머리말에는 공용 `StudentBackButton`을 사용하고 `onBack`을 앱 셸까지 연결한다.
5. `tests/studentNavigation.test.mjs`에 목적지, 활성 메뉴, 화면 버튼 뒤로가기, 브라우저 부모, 일회용 오버레이
   신호를 한꺼번에 추가한다.
6. 작성 화면이면 미저장·임시 저장 흐름을 확인하고, 오버레이면 반복 열기와 닫기 기록 누적을 확인한다.

## 금지하는 지름길

- 하단 메뉴 컴포넌트에 새 메뉴만 하드코딩하기
- 메뉴 클릭에서 `onNavigate('main')` 다음 별도 타이머로 목적지를 열기
- 최상위 메뉴 A에서 B로 갈 때 A를 B의 부모로 방문 기록에 남기기
- 화면별로 `홈으로`, `돌아가기` 버튼을 새로 만들기
- 오버레이 열기 신호를 소진하지 않거나 활성 메뉴 상태를 보고하지 않기
- 매개변수를 잃는 `studentPage` 이름만의 방문 기록 만들기

## 검증

자동 검사는 다음 명령으로 실행한다.

```bash
npm run test:architecture
npm run lint
npm run build
```

실기기에서는 최소한 `나의 아지트 → 과제 → 뒤로가기`, `놀이터 → 친구 아지트 → 뒤로가기`,
`독서록 목록 → 편집기 → 뒤로가기`, `과제 목록 → 편집기 → 뒤로가기`를 화면 버튼과 기기 뒤로가기 각각으로
확인한다. 최상위 메뉴는 메인, 하위 화면은 부모 목록으로 돌아가고 예전 오버레이가 다시 열리지 않아야 한다.
