# 수업 도구 모듈 추가 계약

쌤링크처럼 교사가 수업 중 사용하는 앱은 `src/modules/tool/<module-id>/`에 둔다.
앱 코드를 교사 대시보드에 직접 추가하지 않고 manifest와 `teacherEntry`로 연결한다.

```js
export const sampleToolManifest = {
  id: 'sample-tool',
  name: '샘플 수업 도구',
  description: '수업에서 사용하는 도구',
  icon: '🧰',
  part: 'tool',
  audience: 'teacher',
  teacherEntry: () => import('./TeacherEntry'),
  tool: {
    order: 10,
    launchMode: 'embedded'
  }
};
```

`src/modules/registry.js`에 manifest를 등록하면 교사 `수업 도구` 런처에 자동으로 표시된다.
선택하기 전에는 앱 코드를 로드하지 않는다. 외부 앱은 인증·데이터 계약을 먼저 정한 뒤 연결하며,
비밀 값이나 외부 앱 코드를 아지트 코어 셸에 직접 섞지 않는다.

## 현재 도구

- `class-board`: `우리 반 스크린`. 보드 셸은 위젯 목록·배치·저장·스크린 표시만 맡고, 텍스트·이미지·글쓰기 현황은
  `widgets/registry.js`에 등록된 독립 위젯이 소유한다. 왼쪽 자료의 위치·크기·핀 상태는 보드에 저장하며, 오른쪽
  현황은 담당 교사에게 현재 미션 이름표와 오늘의 일기·독서록 숫자만 전달하고 글 내용·내부 ID는 제외한다.
  스크린의 `화면 편집`도 같은 위젯 레지스트리·설정·배치 엔진을 재사용한다. 변경은 임시 보드에서 처리한 뒤
  교사가 저장하거나 취소하며, 오른쪽 현황은 편집할 수 없는 읽기 전용 영역으로 유지한다. 현황은 화면별 데이터가
  아니라 수업 중 즉시 접고 펼치는 표시 상태다. 편집 미리보기의 전체 16:9 화면이 하나의 고정 좌표계이고 현황은 오른쪽 30%를
  덮는 패널이므로, 접으면 갱신을 쉬면서 오른쪽 공간을 쓸 수 있지만 기존 자료의 위치·크기는 변하지 않는다. 실제
  `스크린 열기` 화면은 저장된 백분율 좌표를 유지하면서 머리말 아래 브라우저 가용 영역을 좌우 빈 여백 없이 채운다. 이미지 업로드가 끝나면 실제
  이미지 비율과 현재 콘텐츠 캔버스 크기로 위젯을 한 번 자동 맞추고, 이후 수동 크기 조절은 비율 제한 없이 허용한다.
  편집 중에는 이미지·텍스트 본체와 상단 이동 손잡이를 모두 드래그 표면으로 사용하며, 핀을 꽂으면 이동·크기
  변경을 함께 잠근다. 캡처 이미지는 편집 화면에서 `Ctrl+V`로 붙여넣을 수 있다. 선택 이미지 → 빈 이미지 칸 →
  새 이미지 칸 순서로 대상을 정하고, 파일 업로드와 같은 1920px·1MB 최적화·비공개 Storage 경로를 거쳐 실제
  비율로 한 번 맞춘다. 선택 위젯은 입력칸에 글을 쓰는 중이 아닐 때 `Esc`로 제거할 수 있으며 저장 전 확인을 거친다.
  표시 위젯은 바깥 여백·제목·조작부를 최소화하고 날씨·시간·뽑힌 이름 같은 핵심 정보가 남은 프레임을 채운다.
  저장된 스크린은 최대 20개 상단 탭으로 전환한다. 탭 목록과 같은 한 줄 작업바에서
  `새 탭`·`저장`·`삭제`·`복제`·`복구`를 처리한다. `삭제`는 기존 archive 경계로 목록에서만 제외하고, 삭제한
  목록은 교사가 명시적으로 `복구`를 열 때만 읽어 담당 학급 화면만 활성 탭으로 되돌린다. 날씨는 기기 위치를
  수집하지 않고 교사가 고른 국내 지역만 Open-Meteo에서 화면을 열 때 읽어 30분간 재사용한다. 타이머·스톱워치는
  브라우저 로컬 실행이고, 타이머 종료음과 이름 전환·선정 효과음도 브라우저에서 합성한다. 자유 배치 위젯은
  저장된 프레임 높이를 크기 프리셋보다 우선하고, 날씨·시간·뽑기 내부 글자·간격·조작부는 브라우저 화면이 아닌
  자신의 프레임 크기에 반응한다. 오늘 현황은 배경색 다섯 가지와 보여 줄 항목 다섯 가지를 교사가 고르며,
  항목 이름은 `writing-status/statusSections.js` 하나를 원본으로 화면·서버·저장 검증이 함께 쓴다.
  켠 항목만 서버가 계산하므로 항목을 늘려도 20초 폴링이 무거워지지 않는다. 학생 무작위 뽑기는
  담당 학급 이름 최대 100명을 한 번 읽는 위젯이다.
  식단표 위젯은 `얘들아, 밥 먹자!`의 학급별 학교 설정을 단일 원본으로 사용해 화면을 열 때 작업공간과 오늘 급식을
  각 한 번만 읽고 학생 이름·비고를 가져오지 않는다. 알림장 위젯은 오늘 날짜를 자동으로 붙이고 그날의 알림을
  `class_board_notices`(학급+날짜)에서 화면을 열 때 한 번 읽는다. 제목·색만 보드 JSON에 남으므로 알림을 고쳐도
  화면 배치와 보드 revision은 바뀌지 않으며, 발표 화면 머리말의 `알림장 쓰기`로 화면 편집 없이 바로 쓴다.
- `meal-board`: `얘들아, 밥 먹자!` 급식·학생별 비고 확인. 첫 화면으로 열리며, 나이스 키는 서버 함수만 읽고, 공개
  전체화면에는 학생 이름과 비고를 전달하지 않는다. 비고는 선택 사항이며 담당 학급 RPC로만 읽고 쓴다.
- `class-notice`: `알림장`. 날짜별 알림을 쓰고 지난 알림을 다시 보는 학급 기록 화면이다. 알림은 스크린이 아니라
  학급에 저장되므로 스크린 탭이나 알림장 위젯을 지워도 남는다. 작성 부품(`class-board/widgets/notice-board/
  NoticeComposer`)을 스크린 설정창·열린 스크린과 함께 쓰고, 목록만 전용 RPC로 최신순 40개씩 날짜 커서로 넘긴다.
- `classroom-arrangement`: 자리·역할 배치
- `samlink`: URL 단축하기(쌤링크). 필요한 경우 선택할 때만 외부 페이지를 지연 로드한다.

## 우리 반 스크린 위젯 계약

새 표시 기능은 `src/modules/tool/class-board/widgets/<widget-id>/`에 두고 `widgets/registry.js`에 매니페스트를
등록한다. 보드 셸에 위젯 ID 조건문을 추가하지 않는다. 매니페스트는 `id`, `version`, `projectorSafe`,
`defaultPlacement`, `createDefaultConfig`, 지연 `load`를 갖고, 설정 화면이 있으면 `loadSettings`도 선언한다.
실시간 데이터가 필요한 위젯은 자신의 요청 예산을 `requestBudget`에 적는다. 교실 표시용 학생 이름이 필요하면
담당 교사 권한·100명 상한·내부 ID와 본문 제외를 서버에서 강제한다. 보드는 위젯의 배치와 설정만 저장하며 살아
있는 현황 데이터는 저장하지 않는다.
날씨는 교사가 설정에서 명시적으로 지역을 검색하고 고른 좌표만 저장한다. 지역 검색은 행동당 최대 5건, 현재 날씨는
위젯을 열 때 1회·메모리 30분 캐시이며 폴링·Realtime·기기 위치 권한을 쓰지 않는다. 타이머·스톱워치는 외부 API나
폴링 없이 로컬에서 실행한다. 학생 무작위
뽑기는 담당 학급 전용 RPC로 활성 학생 이름만 최대 100명 한 번 읽고, 학생 ID·인증 ID·학생 코드는 반환하거나
보드 JSON에 저장하지 않는다. 뽑기 순서와 시간 도구의 실행 상태도 메모리에만 둔다.
식단표는 기존 급식 작업공간 RPC 1회와 나이스 Edge 함수 1회만 사용하며 폴링하지 않는다. 학교 코드는 보드 JSON에
복제하지 않는다. 알림장은 제목 80자·허용 색상만 보드 JSON에 저장하고 한 스크린에 하나만 둔다. 내용은 전용
RPC 두 개(읽기 1회·저장)로만 다루며 본문 2,000자와 오늘 기준 ±365일 날짜 범위를 서버가 강제한다.
자유 배치 본문을 직접 옮길 위젯은 보드 셸이 전달하는 `dragHandleProps`를 표시 컴포넌트의 최상위 요소에
펼친다. 셸은 클릭과 드래그를 3px 임계값으로 구분하고, 핀 상태에서는 이 속성을 전달하지 않는다.
별도 스크린 창에서 보드를 저장한 뒤 기존 교사 대시보드로 돌아오면 포커스·가시화·BFCache 복원 시점에 작업공간을
한 번 다시 읽는다. 750ms 안의 중복 복귀 이벤트는 합치고, 보드 ID·revision·활성 탭이 그대로면 React 상태를
교체하지 않는다. 대시보드에 미저장 편집이 있거나 저장·이미지 처리 중이면 서버 값으로 덮어쓰지 않는다.
별도 스크린의 설정창은 선택 위젯 DOM의 오른쪽 경계를 기준으로 화면에 고정한다. 이동 중 포인터와 프레임 크기,
브라우저 크기·스크롤 변화를 `requestAnimationFrame` 한 번으로 모아 다시 측정하며, 선택이 바뀌기 전의 위치는
표시하지 않는다. 빈 캔버스나 공용 닫기 버튼으로 선택을 해제하면 설정창도 함께 닫힌다.
클립보드 이미지는 `widgets/image/useClassBoardImagePaste.js`가 편집 중에만 감지한다. 텍스트 붙여넣기는 건드리지
않고 이미지 파일이 있을 때만 기본 동작을 막으며, 업로드 중 스크린이 바뀌면 다른 보드에 잘못 연결하지 않는다.
