# 이웃 아지트

여러 학급이 초대로 참여해 글을 나누는 후속 독립 모듈이다. 학급 생성·삭제를 담당하는 `ClassManager` 안에 기능 카드를 넣지 않는다.

`manifest.teacherEntry`는 교사 대시보드의 `학급운영도구` 오른쪽에 `이웃 아지트(제작 중)` 독립 메뉴를 제공하고
설정에는 중복 진입점을 두지 않는다. 관리자가 제한 공개 대상으로 고른 실제 학급의 교사는 공간 생성·초대·
참여 승인·학생 공개·글 검토·글/댓글 숨김을 실제 화면에서 처리한다. 대상이 아닌 학급은 데이터 없이 닫힌 상태만
표시한다. `manifest.studentEntry`는 공개 단계·제한 공개 학급·학급 모듈·교사 학생 공개·활성 공간 조건을 서버
bootstrap과 함께 통과한 학생에게만 홈 카드를 보여 준다.

제품 범위·최대 네 학급·호스트/게스트 권한·원본 글 보존·전용 RPC·관리자 내부 공개와 이번 주 구현 순서는
루트의 [`NEIGHBOR_AGIT_PLAN.md`](../../../../NEIGHBOR_AGIT_PLAN.md)를 정본으로 사용한다.

`policy.js`가 공개 단계(`internal/limited_beta/public_beta/paused`)와 공간당 최대 4학급·학급당 활성 공간 1개,
화면 노출 조건의 단일 원본이다. 이 판정은 화면을 안전하게 닫기 위한 보조 수단이며 권한 판정은 아니다.
다음 단계의 모든 전용 RPC가 실제 사용자·학급 연결과 같은 조건을 서버에서 다시 확인해야 한다.

Step 1~6 데이터·공간·글 검토·학생 피드·상호작용·관리자 내부 화면은
`20261199_neighbor_agit_data_foundation.sql`에 있다. 공개 단계 원장과 공간 자료에 초대 실패 제한·학생별
마지막 피드 방문·공개 단계 감사 이력을 더한 기반 표 12개와 `20261200`의 관리자 내부 테스트 학급 등록부 1개,
공간 생성·초대·신청·승인·
퇴장·종료·호스트 이전 RPC와 글 공개 신청·회수·교사 검토·긴급 숨김 RPC를 함께 만든다. `writingBridge.js`는
별도 글 사본이나 편집기를 만들지 않고 기존 `student_posts`와 임시 저장을 재사용한다는 단일 계약이다.
원글 제출 취소·회수는 이웃 공개를 즉시 회수하고, 공개 뒤 본문이 바뀌면 다시 원학급 교사 검토 대기로 돌린다.

학생 홈은 기존 `get_student_home_bootstrap_v1` 호출 한 번에서 접근 가능 여부·공간 ID·마지막 방문 뒤 새 글 수만
받는다. 공간을 열면 `get_neighbor_space_feed_v1`이 20편부터 최대 50편까지 공개시각+공유 ID 커서로 요약만
반환하고, 전문은 카드를 누를 때 `get_neighbor_shared_post_v1` 한 번으로 읽는다. 실명과 원본 학생·학급·글 ID는
브라우저 응답에 함께 내보내지 않고, 초대·교사 승인으로 닫힌 공간 안에서 등록 학생 이름과 교사가 정한 공개
학급명만 보여 준다. 폴링과 Realtime은 없다.

## 세 가지 활동

1. `전시·나눔`은 기존 제출 글 중 학생이 고른 개인 글을 담임이 확인한 뒤 모든 참여 학급에 전시한다.
2. `같이 쓰는 주제`는 호스트가 열면 모든 참여 학급에 같은 제목·안내의 기존 `writing_missions` 과제를 만들고,
   학생은 공용 편집기에서 쓴 뒤 담임 확인을 거쳐 활동 피드에 나눈다.
3. `글짝 교환`은 호스트가 활성 두 학급을 골라 같은 과제를 열고 제출을 마친 뒤 매칭한다. 인원 차이가 있으면
   적은 쪽 학생 한 명이 최대 두 명까지 맡으며, 그 범위로도 맞출 수 없으면 서버가 매칭을 막는다. 교환 글은
   본인과 서버가 배정한 상대만 목록·상세·댓글·공감·간직하기를 사용할 수 있다.

활동 요약은 최초 공간 피드 응답에 포함한다. 활동 글 목록은 학생이 활동을 열 때만 전용 RPC 한 번으로 최대
50편을 읽고, 글쓰기 화면에서 뒤로 가면 이웃 아지트로 돌아온다. 활동 종료 시 새 글쓰기 과제만 보관 처리하며
이미 교사가 승인해 공개된 글과 반응은 남긴다.

상세 화면에서 학생 한 명은 글 한 편에 줄바꿈 없는 300자 댓글 하나만 남기고 자기 댓글만 수정·삭제한다.
공감은 한 종류만 토글하며, 다른 학생의 글만 복사본 없이 참조로 간직한다. 각 쓰기 동작은 RPC 한 번의 응답으로
상세와 피드 합계를 갱신해 목록을 다시 읽지 않는다. 학생에게는 보이는 전체 합계와 최근 공개 댓글 최대 100개만,
교사에게는 참여 학급별 댓글·공감 합계만 제공하며 학생 순위·포인트에는 연결하지 않는다. 학생이 `내 글 공개 후보`
버튼을 열 때만 제출 글을 최대 50편 조회하고, 공개 신청·회수는 각각 전용 RPC 한 번으로 처리한다. 원글 회수나 공간 종료는
본문 접근을 막되 댓글·공감·간직하기 원장 행은 보존한다.

관리자 대시보드의 `운영 → 기능 공개` 탭은 처음 열 때 `get_neighbor_admin_dashboard_v1` 한 번으로 최근 공간
20개·등록된 관리자 테스트 학급 최대 100개·제한 공개 후보 최대 100개·선택 공간 미리보기 20편과 전체 합계를
읽는다. 실제 `profiles.role=ADMIN`만 내부 시험 공간을 만들고 제한 공개 학급과 공개 단계를 바꿀 수 있다. 내부
시험 공간은 등록된 2~4학급과 학생 공개 OFF로 시작하며 실제 운영 학급은 후보와 생성 RPC에서 제외한다.
`20261201_neighbor_limited_beta.sql`은 실제 교사 학급을 최대 8개까지 고르는 비공개 등록부·감사 원장과
`limited_beta` 권한 게이트, 교사 작업 공간·행동 묶음 RPC를 추가한다. 제한 공개는 두 학급 이상을 고른 뒤에만
시작하며 선택된 학급의 교사와, 그 교사가 별도로 학생 공개를 켠 학생에게만 열린다. 선택 해제 시 해당 학급의
모듈과 학생 공개도 같은 트랜잭션에서 꺼진다. 관리자 화면에는 `제한 공개 ↔ 정상 공개` 스위치를 두며, 정상 공개는
여섯 인수 항목이 모두 참이고 확인을 마쳐 서버 확인 토큰을 전달해야 허용된다. 모든 전환은 별도 감사
원장에 남는다. 일반 교사·학생 이름이나 원본 내부 ID는 미리보기 응답에 포함하지 않는다.

운영 적용 전에는 `npm run migrate:check`와 `npm run smoke:neighbor-agit`로 미적용 스키마까지 한 트랜잭션에서
직접 권한·최대 학급·호스트 제약과 실제 관리자·교사·학생 흐름을 모두 롤백 검증한다. 기존 `student_posts`·
학급 댓글·반응 RLS는 바꾸지 않는다. 2026-08-30 운영 DB 242/242 적용과 앱의 `internal` 배포를 완료했다.
실제 일반 교사의 관리자 RPC는 차단되고 실제 학생 bootstrap은 `neighbor_agit_available=false`이며, 공개 원장은
`internal`·인수 점검 0/6이다. 로그인할 수 없는 합성 교사 2명·학생 0명 학급 2개를 등록해 관리자 후보가
두 테스트 학급만 반환한다. 제한 공개 마이그레이션과 앱을 운영에 반영한 뒤에도 관리자가 실제 학급을 고르고
`limited_beta`로 전환하기 전에는 일반 교사·학생에게 열리지 않는다. `public_beta`는 별도 인수 절차를 유지한다.
