# 맞춤법 배움 데이터 모듈

공통 수첩과 500개 기반 랜덤 5문제, 학급별 승인 항목, 학생의 명시적 검색 집계, 학급 발자국 카드를 소유한다.

- 공통 수첩의 기본 자료는 사전형 400개와 100문제에서 만든 문장형 100개를 합친 500개다.
- 교사 진입은 `manifest.settingsEntry`로 통합 설정에 지연 등록한다. 수업 도구에는 노출하지 않는다.
- 설정 메뉴는 공통 확장 슬롯 규격(데스크톱 270px, 항목 좌우 15px, 최소 높이 68px)을 그대로 사용한다.
- 학생 입력 중에는 DB에 쓰지 않는다. 수첩 검색을 메모리에서 항목별로 합친 뒤 닫을 때 최대 20개를 RPC 한 번으로 저장한다.
- 학생 글·문장 원문은 저장하지 않는다. 기존 자료·사전 검색·문장은 고정 요약 키로 횟수만 남기고,
  미등록 후보는 2~15자·최대 2어절의 한글 표현만 저장한다.
- 교사 화면은 최근 30일 동안 학생 2명 이상 또는 3회 이상 반복된 미등록 표현만 최대 30개 추천한다.
  한두 번 검색한 표현은 개수만 `관찰 중`으로 보여 주며 원문 목록에는 바로 올리지 않는다.
- 찾은 항목도 **사전 항목의 표기**(예: `며칠 / 몇일`)를 함께 저장한다. 학생 글이 아니라 우리 사전의 이름이다.
  (2026-08-19 이전에는 저장하지 않아 교사 화면에 내부 키와 `미분류` 만 보였다. 라벨도 없는 필드를 읽고 있었다 —
  기본 자료의 배움 라벨은 `learningLabel` 이다.)
- 서비스 전체 누적 말뭉치는 `spelling_search_corpus`(+ 학급 수를 세는 `spelling_search_corpus_classes`)에 쌓는다.
  **학급·학생 식별자를 담지 않고, 2~15자·최대 2어절 후보만** 담는다. 과거 V1 학생 실행 권한은 닫고
  안전 기준 밖의 누적 표현은 제거하며, 교사 작업공간과 관리자 월간 검토도 같은 서버 필터를 통과한 후보만 반환한다.
  학급 통계는 학급 삭제와 함께 사라지지만 말뭉치는 남아, 나중에 "무엇을 자주 헷갈리는가"를 볼 수 있다.
- 기본 자료 500개는 모두 글쓰기 밑줄 규칙을 가진다. 명백한 오기는 바로 찾고, 둘 다 가능한 표현은 주변 문맥이 맞을 때만 찾는다.
- 기본 자료는 항목 ID·학습 라벨·큰 분류·세부 분류·검출 방식을 분리한다. 학습 라벨은 교사 검색과 학생 오답 묶음에 쓰고, 검사 표현 색인은 글에서 실제로 등장한 라벨 후보만 고른다.
- 기본·학급 검사는 여러 검사 표현을 한 번에 찾는 공용 후보 색인을 쓴다. 후보가 된 규칙만 문맥을 확인하되 기존 규칙 순서와 비중첩 위치·최대 50개 결과 계약은 유지한다.
- 500개 본문·규칙은 글쓰기 화면의 첫 렌더를 막지 않고 별도 청크로 한 번 내려받으며, 본문 검사는 입력을 멈춘 뒤 350ms 후 실행한다.
- 퀴즈는 기본 자료 500개 전체에서 수첩을 열 때마다 중복 없는 5문제만 무작위로 뽑는다. 풀이 진행과 점수는 서버에 저장하지 않는다.
- 학급 항목은 AI 초안 뒤 교사가 승인해야 학생 검색과 밑줄에 반영된다.
- 학급 발자국 카드는 `manifest.dashboardCards`로 등록하며 대시보드 본체에 기능 전용 카드를 하드코딩하지 않는다.
- 공통 데이터 승격은 후속 관리자 검수 흐름에서 다룬다. 학급 항목을 자동으로 공통 공개하지 않는다.

## 500개 분류와 파일

분류는 사람이 찾고 관리하기 위한 구조다. 글쓰기 검사 횟수를 늘리는 실행 단위가 아니다.

| 파일 | 큰 분류 | 개수 | 세부 분류 |
|---|---:|---:|---|
| `tools/spelling-lookup/catalog/grammarCatalog.js` | 문장 규칙 | 130 | 조사, 어미, 의존 명사·단위, 접두사·접미사, 부정 표현, 일반 띄어쓰기, 붙여 쓰는 낱말 |
| `tools/spelling-lookup/catalog/conjugationCatalog.js` | 용언 활용 | 55 | 되·돼, 준말, 피동·사동, 활용 형태 |
| `tools/spelling-lookup/catalog/meaningCatalog.js` | 뜻 구별 | 64 | 뜻과 쓰임 |
| `tools/spelling-lookup/catalog/wordCatalog.js` | 낱말 표기 | 156 | 일반 낱말, 부사 |
| `tools/spelling-lookup/catalog/compoundCatalog.js` | 합성어·사이시옷 | 49 | 사이시옷을 쓰는 말, 쓰지 않는 말 |
| `tools/spelling-lookup/catalog/loanwordCatalog.js` | 외래어 | 46 | 외래어 |

`catalog/index.js`가 여섯 파일을 `sortOrder` 순서의 단일 목록으로 합친다. `elementarySpellingEntries.js`는 이 목록의 모든 검사 표현을 공용 후보 색인 하나로 만들며, 본문을 분류별로 반복해서 훑지 않는다.

## 앞으로 항목을 추가하는 규칙

1. 뜻에 맞는 분류 파일 하나에만 추가하고 기존 `id`는 바꾸지 않는다. 새 `id`와 `sortOrder`는 전체에서 고유해야 한다.
2. 그 파일에서 허용하는 `subcategoryId`를 `catalog/schema.js`에서 골라 쓴다. 필요한 세부 분류가 없다면 먼저 스키마와 이 문서를 함께 고친다.
3. `detectionMode`를 실제 패턴에 맞게 고른다.
   - `exact`: 어느 문장에서나 틀린 표기인 단어. `text`와 `target`이 같다.
   - `phrase`: 띄어쓰기를 포함한 틀린 어구. `text` 자체에 공백이 있다.
   - `context`: 두 표기가 모두 가능하여 앞뒤 말을 함께 봐야 하는 경우. `text`는 문맥 전체, `target`은 밑줄을 그을 부분이다.
4. 맞는 문장에 밑줄이 생기지 않도록 바른 예문과 헷갈리기 쉬운 정상 반례를 준비한다. 문맥형을 짧은 단어 하나로 등록하지 않는다.
5. 검색용 `searchable`, 학생 설명, 바른 예문, 국립국어원 출처를 넣고 `npm run spelling:check`와 `npm run spelling:benchmark`를 실행한다.

분류·세부 분류·검출 방식이 빠졌거나 패턴과 방식이 맞지 않으면 모듈 로드 및 `spelling:check`가 실패한다. 5,000자 평균 검사가 2ms를 넘으면 `spelling:benchmark`가 실패한다. 항목 수가 늘어도 분류별 별도 루프나 본문 정규식을 추가하지 않고 공용 후보 색인에만 연결한다.
