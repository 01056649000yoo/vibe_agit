# 글쓰기 참고함

학생이 입력창을 가리지 않고 선생님 질문·자기 생각·연구소 결과 같은 자료를 펼쳐 두는 공통 셸이다.

- `WritingReferencePanel`은 열림 상태와 반응형 배치만 소유한다.
- 자료 출처는 `sections`에 문자열로 정리한 읽기 전용 항목을 전달한다.
- 패널은 DB 조회·폴링·Realtime·본문 삽입·저장 상태를 직접 소유하지 않는다.
- 넓은 PC에서는 입력창 오른쪽에 고정하고, 1180px 이하에서는 입력창 위에 놓아 본문 폭을 지킨다.
- 우측 배치에서는 작업공간 안에서 `position: sticky`로 움직여 긴 글의 현재 입력 위치에서도 참고할 수 있다.
- 버튼 오른쪽 안내칸이 가로·세로 화면의 배치 차이를 학생에게 설명한다.
- 열고 닫을 때 입력기를 다시 만들지 않으므로 작성 내용과 커서 선택 범위를 보존한다.

`LabReferenceSource`는 참고함을 열 때 `get_my_writing_references_v1`을 호출하고, 화면으로 돌아오거나 참고함을
다시 열면 서버 최신본을 다시 확인한다. 고정 개요 1건·과제 연결 결과·학생의 최근 완료 결과 ID를 먼저 좁힌 뒤
최대 20건만 읽으며, 폴링이나 Realtime은 사용하지 않는다. `selected_questions`·`one_line` 선택은 현재 참고함
표시만 바꾸며 본문을 자동 수정하지 않는다.

개요는 과제마다 학생 한 명에게 하나만 `writing_assignment_outline_pins`에 고정한다. 학생이 처음 고르거나 다른
개요로 바꿀 때는 개요 전체와 과제명을 확인 대화상자에서 보고 승인해야 하며, 교체는 현재 포인터를 바꾸고
`writing_assignment_outline_pin_events`에 이력을 남긴다. 최종 승인된 글은 같은 개요를 계속 읽을 수 있지만 다른
개요로 교체할 수 없다. 되돌려주기·재제출은 과제·학생 포인터를 그대로 쓰므로 흐름이 끊기지 않는다.

고정표에는 개요 내용 복사본이 아니라 연구소 `portable_results.id`만 저장한다. 연구소에서 같은 완성 개요를 더
고치면 같은 결과 ID의 내용과 `updated_at`이 갱신되고, 학생과 교사가 다음 조회에서 최신 내용을 받는다. 교사는
별도 목록 RPC를 호출하지 않고 기존 `get_teacher_post_detail_v1` 응답의 `outline_reference`로 이 내용을 확인한다.

교사는 과제 카드의 연구소 연결 버튼에서 결과 종류마다 활동방 하나를 고른다. 연결표는
`writing_mission_lab_sources`이며 브라우저 직접 권한 없이 담당 교사 관리 RPC와 학생 본인 조회 RPC로만 접근한다.
새 활동도 표준 결과 종류를 등록해 같은 어댑터에 붙이고, 활동별 조회 분기를 이 셸에 추가하지 않는다.
