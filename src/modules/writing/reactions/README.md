# 글 반응 모듈

자유 글쓰기·장르 글쓰기·앞으로 추가할 글쓰기 모드가 같은 반응 셸과 저장 계약을 쓰기 위한 공용 모듈이다.

## 불변 원칙

1. 반응 선택지는 `registry.js`의 프로필 한곳에서 관리한다. 화면에 반응 배열이나 장르별 조건문을 하드코딩하지 않는다.
2. 모든 장르 매니페스트는 `reactionProfile`을 선언한다. 자유 글쓰기처럼 매니페스트가 없는 글은 `standard`를 쓴다.
3. 프로필의 `type`은 전체 프로필에서 중복되지 않는다. 알림처럼 장르 정보가 없는 화면도 유형만으로 같은 아이콘과 문구를 찾는다.
4. 학생 한 명은 글 한 편에 반응 하나만 선택한다. 다른 반응을 누르면 기존 선택을 바꾸고 같은 반응을 다시 누르면 취소한다.
5. 반응 목록은 이미 받은 과제의 `input_template`로 브라우저에서 결정한다. 프로필을 받기 위한 DB 조회·폴링·Realtime을 추가하지 않는다.
6. 쓰기는 `toggle_my_post_reaction_v1` RPC 한 번만 사용한다. 서버는 글의 학급·공개 상태와 장르별 허용 반응을 다시 검증한다.
7. `post_reactions` 직접 INSERT·UPDATE·DELETE는 학생 브라우저에 열지 않는다. 조회는 기존 학급 공개 범위 RLS를 유지한다.
8. 교사 반응 모아보기는 과제 목록에 반응·댓글을 항상 싣지 않고, 창을 열 때 전용 RPC 한 번으로 최대 100편만 읽는다.

## 새 장르 연결

1. 기본 반응을 쓰더라도 장르 매니페스트에 `reactionProfile: 'standard'`를 명시한다.
2. 전용 반응이 필요하면 `registry.js`에 장르 ID와 같은 프로필을 등록하고 매니페스트가 그 ID를 가리키게 한다.
3. DB 마이그레이션의 내부 반응 카탈로그에도 같은 프로필·유형을 추가한다.
4. `npm run test:writing-reactions`, `npm run test:architecture`, `npm run migrate:check`를 통과한다.
