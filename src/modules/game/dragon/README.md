# 작가 수호룡 표현 계약

수호룡은 서로 다른 세 성장축을 한 화면에 합성한다.

- 작가 칭호: `presentation.js`의 4종 × 10단계 몸체 이미지
- 소통 칭호: `DragonAvatar`의 빛·별·궤도·문장·오로라 레이어
- 포인트 꾸미기: `decorCatalog.js`의 프레임·받침대·좌우 소품·문패 5개 고정 슬롯

꾸미기 상품이 늘어도 이 역할을 섞지 않는다. 포인트 상품은 물질적인 배경·가구·소품을 사용하고, 소통 효과 전용인
빛의 궤도·룬·수호 문장·단계 인장은 상품 장식으로 재사용하지 않는다.

## 교사 관리·시즌 계약

교사 화면은 `TeacherManager.jsx`가 소유하고 `get_teacher_dragon_growth_dashboard()` 한 번으로 현재 시즌·학급 성장·
학생별 수호룡·지난 시즌을 읽는다. 옛 먹이 비용·미접속 퇴화·교사 레벨 조정은 다시 넣지 않는다. 학생의 수호룡 단계는
교사가 정하는 값이 아니라 공용 작가 칭호의 인정 글·글자 수에서 계산하고, 소통 효과도 공용 소통 점수를 그대로 쓴다.
자율 일기와 독서록은 작가 성장에서 분리해 각각 기록가·독서가 칭호로 계산한다.

`단계 미리보기`는 교사가 수호룡 4종·작가 성장 10단계·소통 효과 7단계를 자유롭게 조합해 보는 읽기 전용 도구다.
공용 `getDragonStage()`·`getReaderDragonEffect()`·`DragonHideoutScene`을 그대로 사용하고 선택한 몸체 이미지 한 장만
불러온다. 성장 축하창도 교사가 버튼을 눌렀을 때만 지연 로딩하며, 미리보기 선택과 닫기는 DB·RPC·학생의 성장 확인
기록을 절대 쓰지 않는다.

`공방 미리보기`는 같은 교사 관리 화면에서 학생 상점의 `DRAGON_DECOR_SLOTS`와 `decorCatalog.js`를 그대로 읽어
상품명·가격·등급·작가·소통 단계 조건을 보여 주고, 선택한 5개 슬롯 조합을 공용 `DragonHideoutScene`에만 적용한다.
구매·장착 RPC를 호출하지 않으며 교사가 고른 미리보기 조합은 학생 포인트·소유권·장착 상태에 저장하지 않는다.

수호룡 시즌은 한 학기 동안 한 수호룡을 키우고 학기말에 작별하는 **학기 성장 구간**이다.

- 전용 테이블 `dragon_growth_seasons`를 사용한다. `agit_season_history`는 아지트 온 클래스 기록이므로 섞지 않는다.
- 상태는 `active → closing → closed` 세 단계다. 교사가 `open_teacher_dragon_season_closing()`을 실행하는 순간
  학생별 작가·소통·기록가·독서가 성장과 수호룡 모습이 `dragon_season_students.snapshot`에 동결된다.
- `closing` 동안 학생은 50~1,200자의 작별 편지를 직접 쓰며, 편지는 일반 글쓰기·칭호·포인트에 포함하지 않는다.
  완성한 편지는 최종 수호룡 모습과 함께 브라우저 Canvas로 PNG를 만들므로 AI나 외부 이미지 서비스 비용이 없다.
- 교사는 `finalize_teacher_dragon_season()`으로 시즌을 보관하고, 준비된 시점에 `start_teacher_dragon_season()`으로
  새 학기를 별도 시작한다. 종료와 새 시작을 한 버튼으로 묶지 않는다.
- 새 학기는 작가·소통·기록가·독서가 학기 집계를 0부터 다시 세고 수호룡 종류·교감·성장 확인만 초기화한다.
  기존 글, 포인트, 구입·장착 소품, 지난 수호룡·작별 편지는 그대로 보존한다.
- 본인 칭호·친구 아지트·교사 대시보드는 모두 같은 시즌 시작/동결 시점을 사용한다. 전체 글쓰기 발자국은 과거 기록을 계속 보존한다.
- 과제는 교사 승인, 자율 글은 학생 작성 완료라는 `writing_counts_as_completed()`의 단일 판정을 그대로 사용한다.
- 학급 글 조회는 `student_posts.class_id`로 직접 제한하고 학급 조인에 `class_id`를 함께 넣으며 최대 100명·10만 활동 상한을 둔다.

## 프레임 등록 계약

`HIDEOUT_BACKGROUNDS` 이름과 저장 ID는 기존 데이터 호환 때문에 유지하지만, 새 화면에서는 전체 배경이 아니라
네 모서리 프레임 테마로 렌더링한다. 새 프레임도 기존 필드와 함께 `readerTone`을 반드시 선언한다.

```js
newBackground: {
    id: 'new-background',
    name: '새 프레임',
    color: 'linear-gradient(...)',
    border: '#...',
    textColor: '#...',
    subColor: '#...',
    glow: 'rgba(...)',
    rarity: 'starter',
    readerTone: 'light' // light | dark | vivid
}
```

- 중앙 장면은 밝은 중립 실내로 고정하고 프레임만 색·재질·모서리 형태를 바꾼다.
- `readerTone`은 예전 카드와 호환용 표시에서도 소통 효과 대비를 지키는 안전 계약이다.

`getReaderSceneTheme()`가 보호 무대·외곽선·입자 대비를 CSS 변수로 바꾸고 모든 `DragonAvatar`에 적용한다.
등록값이 없거나 잘못돼도 `light` 안전 기본값을 사용한다.

## 아지트 공방 5개 슬롯 계약

꾸미기는 자유 배치가 아니라 아래 슬롯에 하나씩만 장착한다.

- `wallpaper`: UI 명칭은 **프레임**. 기존 `pet_data.background/ownedItems`를 그대로 읽는 호환 키
- `pedestal`: 수호룡 아래 받침대
- `leftProp` / `rightProp`: 수호룡 바깥쪽의 소품
- `nameplate`: 학생 이름과 드래곤 이름을 보여 주는 문패

새 저장값은 `pet_data.equippedDecor`와 `ownedDecorItems`에 둔다. 기존 배경을 구입한 학생은 별도 변환 없이
`normalizeDragonDecor()`에서 새 프레임 소유권으로 인정한다. 프레임을 새로 장착할 때는 `background`도 함께 갱신해
교사 레거시 화면과 예전 카드가 계속 같은 테마를 표시한다.

구매·장착은 클라이언트가 가격이나 전체 `pet_data`를 보내서 덮어쓰지 않는다. `buy_my_dragon_decor`와
`equip_my_dragon_decor`가 서버 카탈로그의 가격·슬롯·소유·작가·소통 단계·획득 방식·본인 여부를 검증한다. 나의 수호룡 방과 친구
아지트는 같은 `DragonHideoutScene`을 사용하므로 장식 렌더러를 두 군데에 복사하지 않는다.

가격과 구매 단계는 `DRAGON_DECOR_RARITIES` 한 곳에서 정한다. 입문은 300P/작가 1, 일반은 700P/작가 3,
희귀는 1,500P/작가 5, 영웅은 3,000P/작가 7이다. 전설 5종은 상점 상품이 아니라 작가 10·소통 7을 모두
달성했을 때 `claim_my_dragon_legendary_decor_reward()` 한 번으로 소유·장착하는 `전설의 황금 성소` 선물이다.
클라이언트는 전설 아이템을 일반 구매 RPC로 보낼 수 없고 서버가 두 칭호를 다시 계산한다.

성장 단계와 별개로 포인트를 쓸 선택지는 컬렉션의 `levelFree` 계약으로 둔다. `햇살 정원` 5종은 각 800P,
`푸른 파도 항구` 5종은 각 1,000P, `꿈빛 서재` 5종은 각 1,200P이며 모두 작가·소통 1단계부터 살 수 있다.
이 15종은 희귀도를 가장해 성장 상품 가격을 우회하지 않고 아이템의 명시 가격·단계를 사용한다. 새 자유 구매
세트를 추가할 때도 세트 안 5개 슬롯의 가격·단계는 같게 유지하고 서버 카탈로그에 동일하게 등록한다.

### 좌우 소품 에셋 계약

- 왼쪽은 **기록·마법** 역할로 제한한다: 연대기·씨앗 기록대, 항해 지도대, 이야기 등불, 수정 군락, 화로, 룬석,
  마법의 샘·봉화·깃발.
- 오른쪽은 **교감·관측·보물·휴식** 역할로 제한한다: 날개석, 천구의·조개 관측대, 보물고, 독서 둥지·의자,
  정령 샘·수정알·모루·유물.
- 일반 가정용 가구나 작은 기호형 CSS 도형은 추가하지 않는다. 드래곤 몸체와 같은 부드러운 3D 판타지 재질과
  명확한 실루엣을 사용한다.
- 상품의 `image`는 `/assets/dragons/decor/*.webp`에 둔 투명 512×512 WebP이며 개별 100KB 이하로 유지한다.
  장면과 공방 미리보기 모두 지연 로딩·비동기 디코딩으로 읽는다.
- 이미 판매한 상품의 ID·소유권은 바꾸지 않는다. 경제 개편으로 가격을 조정해도 기존 구매자에게 추가 차감하지 않으며,
  모습과 표시 이름을 개선할 때도 기존 ID에 새 에셋을 대응한다.
- 새 원본을 투명 PNG로 만든 뒤 `scripts/process-dragon-decor.py`로 크기·여백·용량을 동일하게 맞춘다.

### 문패 에셋 계약

- 문패는 색만 바꾸지 않고 목재·뿌리·황동 날개·월광 수정·고대 룬·별자리·용암·폭풍·전설 황금의 재질과 실루엣을 달리한다.
- 에셋에는 글자를 넣지 않는다. 중앙을 넓고 차분하게 비워 `DragonHideoutScene`이 학생 이름과 수호룡 이름을 HTML로
  겹쳐 표시한다. 이름이 바뀌거나 친구 아지트에서 보여도 같은 에셋을 다시 만들 필요가 없다.
- 상품의 `image`는 `/assets/dragons/nameplates/*.webp`에 둔 투명 640×256 WebP이며 개별 90KB 이하로 유지한다.
  `scripts/process-dragon-nameplates.py`로 크기·여백·용량을 맞춘다.
- 등급별 효과는 수집 차이가 보이되 이름을 가리지 않게 테두리에만 둔다. 수정은 맥동광, 룬은 청록 빛줄기, 별자리는
  별 반짝임, 용암은 불씨 맥동, 전설은 황금 빛 훑기를 사용한다. `prefers-reduced-motion`에서는 정지한다.
- 기존 `nameplate-simple/oak/brass/crystal` ID와 소유권은 유지한다. 최상위 전설 문패는 작가 10·독자 7단계
  달성 선물 세트에 포함한다.

## 고정 레이어 순서

1. 배경
2. 뒤쪽 가구·환경 소품
3. 소통 효과 보호 무대·후광
4. 소통 효과 오로라·궤도
5. 작가 수호룡 몸체
6. 소통 효과 별·룬·단계 인장
7. 앞쪽 가구·장착 소품

앞쪽 소품은 드래곤 몸 일부를 가릴 수 있지만 소통 효과의 단계 인장과 상단 문장은 가리지 않아야 한다. 수호룡 표시 영역은
가능하면 정사각형을 유지하고, 외부 카드가 `overflow: hidden`을 쓸 때도 효과가 보이도록 최소 6%의 내부 안전 여백을 둔다.

## 성능·접근성

- 소통 효과는 별도 래스터 이미지를 만들지 않고 CSS/SVG 레이어만 사용한다.
- 좌우 소품은 512px 투명 WebP를 사용하고 실제 장착된 두 장만 지연 로딩한다.
- 문패는 640×256 투명 WebP 한 장과 가벼운 CSS 테두리 효과를 사용한다.
- 반복 애니메이션은 `transform`과 `opacity` 위주로 유지한다.
- `prefers-reduced-motion: reduce`에서는 정적인 최종 문양만 보여준다.
- 단계 차이는 색만이 아니라 별·궤도·왕관·오로라·이중 문장의 형태로도 구분한다.
