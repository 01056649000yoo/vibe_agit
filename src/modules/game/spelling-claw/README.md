# 수호룡의 인형뽑기 (spelling-claw) — 학생 공개(2단계, 2026-10-02)

맞춤법 퀴즈를 풀어 코인을 얻고, 코인으로 3D 인형뽑기를 해 상품을 받는 놀이터 모듈이다.
학생 노출은 다른 놀이처럼 **학급별 켜기/끄기**(`enabled_modules`, 처음 값 OFF)다. 실험실(`?dev-lab=spelling-claw`)은 교사 화면을 학급 없이 연다.

## 서버가 정하는 것 (2026-10-02)
- **Edge 함수 `supabase/functions/spelling-claw/`**: `quiz-start`(문제 10개를 만들어 정답째 DB 에 두고 정답 없는 문제만 보냄) ·
  `quiz-answer`(한 문제씩 채점, 순서대로 한 번씩) · `play-finish`(잡은 인형을 받아 상품 추첨).
  이 폴더의 `prizeTable.js`·`spellingQuizBuilder.js`·`plushCatalog.js` 가 **원본**이고, 앱의 같은 이름 파일은 다시 내보내기만 한다
  (Edge 함수는 폴더째 배포되므로 폴더 밖을 import 하면 운영에서 죽는다).
- **`20261363_spelling_claw_server.sql`**: 학급 설정(저장 단추)·퀴즈 기록·뽑기 장부(코인 = 한 판). 코인은 그날만·하루 기회 수까지,
  지급(포인트 `spelling_claw`·수호룡 아이템·선물 기록)과 학생 홈 알림을 **한 트랜잭션**에서. 같은 판을 다시 보내도 한 번만 준다.
- 인형을 잡았는지만은 학생 기기(3D)가 알린다. 그래서 한 판 상품은 최대 2개(`CLAW_MAX_PRIZES_PER_PLAY`), 하루 판 수는 기회 수까지로 묶었다.
- 수호룡 아이템은 지급 직전 상점 구매(`buy_my_dragon_decor`)와 같은 조건을 SQL 이 다시 본다. 어긋나면(그사이 가짐 등) 10P.
- 화면은 `clawServerSession.js`(학생)·`clawSession.js` 의 `createLocalClawSession`(교사 미리보기, DB 안 씀)이라는 같은 모양의 두 세션으로 돈다.
  미리보기는 서버 규칙의 흉내다 — 규칙(코인·최소 포인트·상품 수)을 바꾸면 SQL·미리보기·스모크를 함께 고친다.

## 선생님 결정 (2026-10-01)
- 맞춤법 10문제 중 **교사가 정한 개수 이상** 맞히면 코인 1개. 하루 기회(코인) 수도 교사가 정한다.
- 집기에 실패해도, 하루 기회를 다 쓰고 하나도 못 뽑았으면 **교사가 정한 최소 포인트**를 준다(문제를 풀었으니).
- 수호룡 아이템은 **학생이 지금 단계에서 상점에서 살 수 있는 것만**. 전설(만렙 선물)·업적·무료·가진 것은 빠진다. 예외 없음.
- 코인은 공부로만 얻는다 — 포인트로 코인을 사는 길은 만들지 않는다. 꽝 없음, 확률 공개.

## 파일
- `engine/clawEngine.js` — 원본 `10만들기_인형뽑기.html` 의 기계·집게·인형 물리(three.js 0.170 + Rapier 0.14)를 옮긴 것.
  화면과 맞닿는 부분만 바꿨다(코인·문제·도감은 밖으로, `emit` 으로 알림). 물리 수치는 원본 그대로.
- `ClawMachineStage.jsx` — 엔진을 **열 때만** 불러오는 화면. 코인은 `onSpendCoin` 이 참일 때만 한 판을 시작한다.
- `plushCatalog.js` — 동물 인형 8종(`public/assets/claw/plush/*.glb`). 포켓몬은 저작권 때문에 넣지 않는다.
  동물 모델은 Tripo AI **유료 요금제**로 만든 것을 지인에게 받았다 — 공개 서비스 사용 가능(2026-10-02 선생님 확인).
- `quiz/spellingQuizBuilder.js` — 퀴즈 만들기·채점의 **하나뿐인 원본**. 사전 항목에서 그때그때 문제를 만든다
  (기본 500 + 관리자가 게시한 공통 자료 + 우리 반 학급 자료 → 게시하면 다음 퀴즈부터 저절로 출제, 적용 중지하면 빠짐).
  유형: 고르기·빈칸 고르기(객관식), 고쳐 쓰기·띄어 쓰기(주관식). 빈칸 쓰기는 정답이 하나로 안 정해져 뺐다.
  난이도 쉬움/보통/어려움 = 주관식 3/4/6개. 앱 전용 import 가 없어 2단계 서버(Deno)도 같은 파일을 쓴다.
  앱 사전과 공개 파일(`public/spelling/*.json`)이 같은 문제를 만드는지 검사가 본다.
- `prizeTable.js` — 상품 설정의 **하나뿐인 원본**: 기본값(`CLAW_DEFAULT_PRIZE_SETTINGS`)·검증(`normalizeClawPrizeSettings`)·
  추첨(`rollClawPrize`)·확률 공개(`describeClawOdds`)·합계(`sumClawPrizeSettings`). 설정은 **상품마다 확률(%)**(포인트 금액별·선물별·아이템 등급별, 합 100%).
  추첨과 확률 공개는 같은 `planOf` 를 거쳐 어긋나지 않고, 그 학생이 받을 아이템이 없는 등급의 몫은 포인트로 간다(다른 상품 확률은 그대로).
  2단계에서 교사 설정은 학급 설정(DB)에 두고, 서버(Deno)도 이 파일로 검증·추첨한다(앱 전용 import 없음).
- `TeacherManager.jsx` — 교사 화면 탭 셋: `🛠️ 교사 관리`(학급 설정·상품 설정, **저장 단추**) / `📜 뽑기 내역`(서버 원장, 보이는 동안 12초) / `🧒 학생 화면 미리보기`.
- `ClawPlayScreen.jsx` — 학생이 보는 화면 한 장(학생 놀이터 `StudentEntry.jsx` 와 교사 미리보기가 함께 쓴다). 정답·상품을 스스로 정하지 않는다.
- `ClawPrizeSettings.jsx` — 교사 상품 설정 판(2026-10-02): 상품마다 확률(%) 입력, 합계 100% 표시·`100%로 맞추기`, 한눈에 보기 막대.
  학급 설정과 함께 `저장` 단추로 서버(`spelling_claw_class_settings`)에 저장한다(합 100%일 때만, 먼저 저장된 값은 덮어쓰지 않음).

## 학생 홈 알림 (2026-10-02 결정)
- 하루 기회를 다 쓰고 하나도 못 뽑아 **최소 포인트를 받으면** 학생 홈 활동 알림으로 알린다(`spelling-claw.consolation_awarded`,
  표시는 `manifest.notifications`). 2단계 서버가 포인트를 줄 때 같은 트랜잭션에서 `notification_emit_v1` 을 부르고,
  `event_key` 는 학생·날짜로 정해 하루 한 번만 남긴다. 폴링·Realtime 은 더하지 않는다(`modules/notifications/README.md`).

## 상품 알림 (2026-10-02 선생님 요청)
- 뽑은 본인: `spelling-claw.prize_awarded`(포인트·선물·수호룡 아이템), 반 전체: 선생님 선물 당첨 시 `spelling-claw.class_gift_won`
  (같은 반 다른 학생마다 한 건, 이름 포함 — 교사 설정 `선물 당첨을 반 전체에 알리기` 기본 켬으로 끌 수 있게).
- 2단계 서버가 상품을 줄 때 **같은 트랜잭션에서** `notification_emit_v1` 로 남긴다. event_key 는 판 id(재시도해도 한 번).
  선물 확률 기본 1%(2026-10-02)라 한 반에 한 달 한두 건 안팎이므로 반 전체 알림 행 수는 아주 적다.

## 뽑기 내역·큰 상품 축하 (2026-10-02 선생님 요청)
- 선생님 선물·수호룡 아이템이 나오면 화면 가득 축하한다(`ClawCelebration`, 4.5초 뒤 저절로 닫힘, 움직임 줄이기면 꽃가루 끔). 포인트는 노란 띠만.
- 교사 화면 `📜 뽑기 내역` 탭: 누가·언제·어떤 인형·어떤 상품. 서버 상품 원장(`spelling_claw_plays`)에서 학급 내역을 읽고,
  **탭이 보이는 동안만 12초마다** 새로 고친다(교사 화면 폴링 예외 규칙, 숨은 탭에서는 멈춤, 오류면 30~120초 후퇴, Realtime 없음 —
  `PERFORMANCE_HARNESS.md`). 한 번에 최근 100건. 실험실(학급 없음)은 미리보기에서 뽑은 것만.
