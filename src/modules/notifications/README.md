# 학생 활동 알림 계약

학생 홈의 `활동 알림`은 기능별 폴링을 추가하지 않는다. 로그인·새로고침·공용 홈
재검증에서 `get_student_home_bootstrap_v1`이 최신 미확인 1건과 개수만 내려준다.
학생이 알림 창을 열었을 때만 목록 RPC를 최대 50건까지 호출한다. Realtime 연결은 없다.

새 기능이 활동 알림을 추가할 때는 다음 세 곳만 확장한다.

1. 기능 전용 상태 변경 RPC 안에서 내부 전용 `notification_emit_v1`을 호출한다. 업무 상태와
   알림 저장은 같은 트랜잭션이어야 하며, 재시도해도 같은 `event_key`를 사용한다. payload 계약을
   바꿀 때는 `event_version`을 올리고 이전 버전 표시 호환을 유지한다.
2. 기능 매니페스트의 `notifications`에 `eventType`, 표시 문구, 아이콘, 이동 동작을 등록한다.
   공용 `confirm`·`rewrite`·`post` 동작으로 부족하면 `custom`과 모듈 소유 `handleAction`을 쓴다.
3. 알림 상세 이동에 새로운 공용 동작이 꼭 필요할 때만 알림 셸을 확장한다.

친구 반응·친구/교사 댓글은 이 원장에 넣지 않는다. 해당 소식은 헤더의 `내 글 소식`과
`last_feedback_check` 흐름에서만 확인한다.

원장을 도입하기 전의 승인·포인트 내역은 활동 알림으로 소급 생성하지 않는다. 과거 원장을 한꺼번에
미확인 알림으로 만들면 학생에게 오래된 소식이 쏟아지므로, 운영 마이그레이션 적용 뒤 발생한 이벤트부터 기록한다.
