# 학생 활동 알림 계약

학생 홈의 `활동 알림` 목록은 기능별 폴링을 추가하지 않는다. 로그인·새로고침·공용 홈
재검증에서 `get_student_home_bootstrap_v1`이 최신 미확인 1건과 개수만 내려준다.
학생이 알림 창을 열었을 때만 목록 RPC를 최대 50건까지 호출한다. Realtime 연결은 없다.

수업 중 교사가 과제 글을 반려하거나 승인한 두 경우만 코어 상단 배너 예외다.
반려에는 처음 되돌려주기뿐 아니라 강제 회수한 글을 다시 학생에게 넘겨 실제 `다시쓰기 중` 상태로
복구하는 경우도 포함한다. 이미 같은 다시쓰기 상태인 행의 재저장은 새 알림을 만들지 않는다.
`poll_my_priority_writing_notifications_v1`을 보이는 학생 탭에서 12초마다 호출하되 최초 호출은
0~12초로 분산한다. 숨은 탭에서는 멈추고 화면·네트워크 복귀 시 즉시 확인하며, 진행 중인 요청과 겹치지 않고
실패 시 30~120초로 후퇴한다. RPC는 bootstrap `generated_at` 뒤 학생 본인의 신호를 최대 10건만
읽고 ID·유형·대상 ID·시각만 반환한다. 배너는 읽음 상태를 바꾸거나 화면을 이동시키지 않는다.

새 기능이 활동 알림을 추가할 때는 다음 세 곳만 확장한다.

1. 기능 전용 상태 변경 RPC 안에서 내부 전용 `notification_emit_v1`을 호출한다. 업무 상태와
   알림 저장은 같은 트랜잭션이어야 하며, 재시도해도 같은 `event_key`를 사용한다. payload 계약을
   바꿀 때는 `event_version`을 올리고 이전 버전 표시 호환을 유지한다.
2. 기능 매니페스트의 `notifications`에 `eventType`, 표시 문구, 아이콘, 이동 동작을 등록한다.
   공용 `confirm`·`rewrite`·`post` 동작으로 부족하면 `custom`과 모듈 소유 `handleAction`을 쓴다.
3. 알림 상세 이동에 새로운 공용 동작이 꼭 필요할 때만 알림 셸을 확장한다.

## 두 갈래 (2026-08-17)

친구 반응·친구/교사 댓글도 이 원장을 쓴다. `last_feedback_check` 시각 하나로는 "1번은
읽고 2번은 안 읽음"을 표현할 수 없어 알림별 확인이 불가능했고, 배지 조회가 반응·댓글 두
표를 조인해 이력이 쌓일수록 무거워졌기 때문이다. 대신 `module_id`로 갈래를 나눈다.

| 갈래 | `module_id` | 보는 곳 | 확인 방법 |
| --- | --- | --- | --- |
| 내 글 소식 | `feedback` | 헤더 🔔 | 항목마다 `확인`, 한 번에 `모두 확인` |
| 활동 알림 | 그 외(`writing`·`points`…) | 홈 패널 | 알림마다 `확인했어요` |

갈래를 합치지 않는 이유는 성격이 다르기 때문이다. 승인·반려는 해야 할 일이고 반응·댓글은
재미다. 한 목록에 섞으면 중요한 반려 알림이 반응 스무 개에 묻힌다.

조회·읽음 RPC는 `p_module_ids`/`p_exclude_module_ids`로 갈래를 고른다. 홈 부트스트랩은
`feedback_notifications`와 `activity_notifications`를 따로 내려준다.

읽음 처리 뒤에는 **반드시 `studentHomeApi.invalidate()`로 홈 캐시를 비운다.** 화면 상태만
바꾸면 학생이 다른 메뉴에 갔다 오는 순간 대시보드가 새로 만들어지며 옛 개수를 다시 적용해
방금 지운 배지가 되살아난다.

`last_feedback_check` 컬럼은 비상 롤백용으로만 남겨 둔다. 새 코드는 읽지 않는다.

원장을 도입하기 전의 승인·포인트 내역은 활동 알림으로 소급 생성하지 않는다. 과거 원장을 한꺼번에
미확인 알림으로 만들면 학생에게 오래된 소식이 쏟아지므로, 운영 마이그레이션 적용 뒤 발생한 이벤트부터 기록한다.

## 칭호 성장 알림 (2026-08-31)

- 작가 칭호는 수호룡 외형 변화가 핵심이므로 기존 성장 축하 모달을 유지한다.
- 소통·기록가·독서가는 `titles.level_up` 활동 알림 한 종류를 사용한다. 표시 이름·단계 이름은
  `writing/title-status/titleTracks.js`를 원본으로 삼고, 알림을 누르면 나의 아지트에서 해당 칭호 상세를 연다.
- 기록가·독서가의 해당 단계 보상을 받을 수 있으면 알림 payload의 `reward_claimable`로 수령 가능 문구를 덧붙인다.
- `student_activity_title_notification_state`는 학생·시즌·칭호별 마지막 알림 단계만 비공개로 보관한다. 운영
  도입 시 기존 학생의 현재 단계를 기준선으로 넣어 소급 알림을 막고, 이후 단계가 올라갈 때만 최종 단계 한 건을 낸다.
- 댓글·반응·일기/독서록 교사 확인과 상태 갱신은 같은 트랜잭션 안에서 이 원장을 동기화한다. 별도 칭호 폴링이나
  Realtime 구독을 추가하지 않는다.
