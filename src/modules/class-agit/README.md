# 우리반 아지트

## 외부 공유 작품 편집·샘링크 (2026-09-05 로컬 수정)

- 외부 작품 목록을 주제별 표로 펼쳐 제목·지은이·전시 주제를 수정한다. 검색·주제 필터, 모바일 작품별 배치를 제공한다.
- 임의의 ‘새싹 작가’ 표시는 새 편집에서 쓰지 않는다. 원래 지은이를 채우며 교사가 변경할 수 있다.
  외부 제목/지은이/방 소속/주제는 발행 시 고정하고 다시 열 때 복원한다. 학생 원글과 학급 전시는 수정하지 않는다.
- `61248`의 `display_version=2`는 전체 유효 작품·20편/방·120편/전시·기존 주제 ID·표시 길이를 서버에서 검증한다.
  이전 탭의 version 1 발행과 이미 발행한 내용은 그대로 호환한다.
- 주소와 QR코드를 함께 표시하고 1,024px PNG 저장을 제공한다. QR은 `qrcode`를 지연 로드해 브라우저에서 만들며 외부 QR 서비스로 주소를 보내지 않는다. 재발급/해지 때 표시도 함께 갱신한다.
- 같은 DB의 `samlink.short_links`를 발행 트랜잭션에서 연결한다. 목적지는 서버의 아지트 도메인과 검증한 토큰으로만 만들고
  144비트 난수 slug를 사용한다. 브라우저에는 샘링크 주소만 반환하고 샘링크 API 키·공용 단축 API 호출은 필요 없다.
  샘링크에 작품 본문은 복사하지 않으며 목적지 토큰은 비공개 목적지 열에만 저장한다.
- 응답 유실 재시도는 같은 토큰/주소를 반환한다. 기간 변경·재발급·해지·전시 삭제는 단축주소도 같은 트랜잭션으로 반영한다.
  신규 발급은 전시별 5초 제한, 30일 만료와 기존 읽기 예산은 유지한다.
- 배포 시 `61248`은 진남초 4학년 1반만 지정된 pilot인 경우에만 외부 허용을 켠다. 다른 운영 상태의 범위를 넓히지 않는다.
  현재는 로컬 구현·합성 롤백 검증 단계이며 SQL과 운영 설정은 아직 적용하지 않았다.
- 검증: 전용 98개·구조 340개·보안 정적 276개·전체 보안 하네스·변경 파일 lint 0경고 통과.
  합성 DB에서 표시 편집·20편 제한·주소/만료/회전/해지/삭제·동일 요청 재시도·학생 차단을 전체 롤백 검증했다.
  PC/390px 실제 화면에서 41편 제목/지은이/주제 편집·검색·샘링크 발행·재접속 복원·공개 목차를 확인했고 모바일 가로 넘침은 없다.
  운영 샘링크의 실제 공개 주소 발급·리디렉션 확인은 배포 후 수행한다.

  초안 저장→학생 공개 켜기→학급 공개→공개판 확인을 점검한다. 저장 충돌·원글 수정/회수·조회 실패 버튼 제공.

운영 모듈이 `src/dev/`를 가져오지 않으며 실제 권한은 SQL 역할 스모크로 따로 검증한다.

- `/?dev-lab=class-agit-release`: 전시 가져오기→문집 확정/출력→학생 서가, 외부 주소 발급/만료/해지, 공개 단계 통합 샘플. 100편 문집 버튼 제공.

## 저장·공개·철회

전시 편집은 `1 기본 설정 → 2 작품·전시실 구성 → 3 미리보기 → 4 외부 읽기 공유` 탭으로 진행한다.
이름·소개·학급 ON/전시 공개는 1단계, 후보 검색·작품 담기·순서는 2단계, 초안/공개판 감상은 3단계다.
2단계 첫 진입에만 미션/후보를 읽는다. `작품 찾기`는 실제 미션 목록·넓은 요약 목록·여러 편 선택·즉시 담기를,
`담은 작품 정리`는 간결한 행·여러 편 이동·명시적 정렬·저장 전 직전 변경 되돌리기를 제공한다.
전시와 문집은 `selection/SourceBrowser.jsx`를 함께 사용하며 수록 범위와 120/100편 상한은 별개다.
목록 캐시는 `dataCache` + `classKey()` 메모리 30초이고 실패 시 낡은 성공을 대신 쓰지 않는다.
정리의 담은 순서는 현재 편집 세션의 시작 순서와 이후 추가 순서다. 다음 편집 세션에서는 저장된 순서로 시작한다.
상세는 [작품 선택 개편](../../../docs/CLASS_AGIT_SELECTION_PLAN.md).
다음 단계 버튼은 미저장 초안을 저장한 뒤 이동하며 실패하면 입력과 단계를 유지한다. 직접 탭 이동도 초안을
보존하고, 4단계 진입은 저장된 전시를 기준으로 한다. 외부 공유는 처음 열 때만 조회하며 탭을 오가도 입력과
새 주소를 유지한다. 전시 변경 후 공유 설정을 다시 준비할 때는 기존 입력·새 주소 유실을 확인한다.
이번 탭 구성은 UI 변경이며 운영 시범 학급·외부 공유 허용 설정을 바꾸지 않는다.

관리 화면은 `management.css`의 `class-agit-management` 범위에서 공용 `--ui-*` 토큰과 `Button`을 사용한다.
전시 목록·단계 편집·문집·외부 공유·공개 단계 설정의 제목/입력/버튼은 같은 앱 기준을 따른다.
전시실·감상용 글·문집 표지는 `classAgit.css`의 전시 표현을 유지한다.

생성 ID는 응답을 받기 전 재시도에도 유지한다. 이후 변경은 서버 `expected_revision`으로 충돌을 검출하고
실패한 편집 내용을 화면에 유지한다. 최신 초안을 다시 가져오거나 목록으로 나갈 때 미저장 편집을 확인한다.
저장 요청은 원글 ID·해시·가림 이름만 전달하며 본문·등록 이름·상태는 서버에서 구성한다.

초안의 순서/제목/선정을 고쳐도 현재 공개판은 고정되어 있다. 공개판 갱신 때 최신 원글 자격·해시를 검사한다.
원글 변경은 재확인을 요구하며 회수/삭제/학생 비활성·수록 철회는 다음 읽기에서 숨긴다. 철회 후 재수록은
철회 세대 식별자를 바꾸므로 초안 저장만으로 이전 공개판이 되살아나지 않는다. 새 공개판 갱신이 필요하다.
학급 OFF에서도 초안 편집은 가능하고 열람은 차단한다. 보관/초안 복원 역시 자동 재공개하지 않는다.

학급 전시는 현재 공개판 한 개와 판 번호를 보관한다. 별도 문집 표가 확정 콘텐츠·설정·20개 판을 보관하고, 외부 공유 표가 외부 전용 공개본을 보관한다. C1 수록 원장은
`class`만 기록한다. 원본 삭제 뒤 남은 초안 항목은 nullable sourceId 대신 itemId로 정확히 하나씩 정리한다.

## 검증

`npm run test:class-agit`, `npm run test:architecture`, `npm run test:security`,
`npm run smoke:class-agit`(또는 미적용 상태의 `npm run migrate:check`)로 검사한다.
SQL 스모크는 합성 계정·학급·글만 만들고 전체 ROLLBACK한다. 시작할 때 같은 트랜잭션 안에서 internal/OFF로 초기화하므로 실제 운영 단계와 관계없이 반복할 수 있고 종료 후 실제 시범 설정이 복원된다. 운영 자료로 전시를 발행하지 않는다.

C1에서 확인한 항목: 다른 학급/일반 교사/위조 관리자 접근, 표·도우미 권한, 61편/중복 방지,
원글 해시·본문 위조·명시적 수록 확인, 생성 재시도·revision 충돌, 12편 방 분할, 초안과 공개판 분리,
철회/재확인/재공개·원글 회수/삭제·학생 비활성, 학급 OFF, 공개 중단/보관/복원, 전체 중지.
브라우저 샘플에서 생성·담기·저장·공개·충돌 입력 보존·재확인·철회·조회 실패와 390px 편집을 확인했다.
C2 샘플은 공용 홈 카드와 방문 기록 함수를 사용하며 실제 로그인 인수·실기기 부하를 대체하지 않는다.

학생 홈은 기존 bootstrap에 공개 전시 존재 여부만 합치고 상세 요청을 추가하지 않는다. 본문은 작품을 열 때만
받는다. 방/보기/작품 넘기기는 `onReplace`로 부모 기록을 보존하고, 하위 진입은 `onNavigate`, 닫기는 공용 `onBack`을
사용한다. 요청을 떠나거나 실패한 뒤 예전 전문을 다시 보여 주지 않으며 body 캐시·폴링·Realtime은 없다.
다른 학급/학생으로 바뀌면 앱의 읽기 호스트 키도 바뀐다. 원글·학생 ID와 큰 본문은 history에 넣지 않는다.

학생 공개를 처음 켜는 미설정 학급은 `resolveEnabledModuleIds`가 계산한 기존 메뉴와 현재 legacy flag를 전달한다.
서버는 학급 잠금 안에서 아직 미설정인지·legacy flag가 바뀌지 않았는지 검사한다. 이미 설정된 목록은 서버 값을
유지한다. 새 legacy 필드가 생기면 작업공간과 초기화 계약을 함께 확장하도록 C2 검사가 묶어서 확인한다.

## 주제별 전시실 (61247 · 운영 SQL 반영)

`rooms.js`가 최대 10실·20편/실·120편/전시와 미배정·일괄 이동을 관리한다. 방 삭제는 작품을 미배정으로 옮기며,
미배정이 남으면 학급/외부 발행을 막는다. 방과 작품 순서는 저장 시 정규화한다. 문집 가져오기도 이 순서다.
4종 전시 디자인마다 배경 변형 4개를 제공하며, PC는 최대 5행·모바일은 215px 액자 가로 감상이다.

`61247`은 초안의 rooms/room_id, 발행 목차의 room_definitions, 공개 항목의 room_no를 추가한다.
본문 복사·권한·기간·원본 회수 정책은 유지한다. 회수 시 작은 목차만 갱신하고 다른 방을 당겨 채우지 않는다.
기존 전시의 12편 경계를 백필하며, 원문·링크·만료·시범 학급 설정을 바꾸지 않는다.

호환 읽기는 기존 RPC 이름에 필수 `p_layout_version` 인자를 가진 오버로드를 추가했다. 새 화면은 2를 전달한다.
예전 인자 개수의 학생 방·교사 공개판·외부 읽기는 12편 응답을 반환하는 래퍼로 남긴다. 학생 전문도 새 오버로드에서
`room_title`만 더하며 기존 본문 1편 조회를 재사용한다. 새 방을 편집한 전시를 구형 화면에서 저장/외부 발행하면
PT409로 새로고침을 안내한다. 이 오버로드들은 운영 중인 이전 탭의 호환 경로이므로 임의 삭제하지 않는다.
