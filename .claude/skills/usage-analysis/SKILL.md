# 사용자 분석

## 먼저 돌린다

```
npm run analyze:usage
```

기간을 바꾸려면 `npm run analyze:usage -- --weeks 12 --days 60`.

맥미니에서만 돈다(`agit-db` 컨테이너). 다른 기기면 그렇게 말하고 멈춘다.

## 세는 기준은 한 곳에 있다

`scripts/analyze-usage.mjs`. **질의를 그 자리에서 새로 짜지 않는다** — 기준이 매번 달라지면
지난번 수와 견줄 수가 없다. 새로 보고 싶은 것이 생기면 그 파일에 항목을 더하고,
`tests/usageAnalysis.test.mjs` 가 읽기 전용·개인정보 규칙을 지키는지 본다.

읽기만 한다. 사람을 식별하는 값(이름·메일·학교·글 내용)은 결과에 넣지 않는다.

## 숫자를 읽을 때

- **가입 깔때기가 먼저다.** 가장 크게 떨어지는 칸이 지금의 병목이다. 가입자 수를 늘리는
  이야기는 그다음이다.
- **계정 나이를 가른다.** 새 기능의 효과를 볼 때 전부터 쓰던 교사가 섞이면 뒤집힌 결론이
  나온다(2026-09-14 에 실제로 그랬다 — 동행 모드를 안 한 사람이 글을 더 많이 받은 것처럼 보였다).
- **개학·방학을 본다.** 7월 말~8월 중순은 거의 0이다. 주 단위로 견줄 때 이 구간을 섞지 않는다.
- 표본이 수십 명이면 **표본이 작다고 말한다.** 비율만 크게 보이고 흔들린다.

## 분석에서 끝내지 않는다

숫자를 늘어놓는 것이 목적이 아니다. 마지막에 **고칠 자리 하나**와 그 근거를 댄다.
고친 뒤에는 같은 명령으로 다시 재서, 달라졌는지 확인한다.
